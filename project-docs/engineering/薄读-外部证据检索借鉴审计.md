# 薄读外部证据检索借鉴审计

更新日期：2026-07-30

## 审计边界

本审计关注薄读需要的能力：论文检索、全文获取、页级切片、声明分解、支持与反证检索、句级证据绑定、复核失败降级和可追溯审计。不能验证的 README 宣称不作为实现依据。

## 已采用的组合

1. 候选召回与生成上下文分离：外部候选池最多 32，生成上下文最多 8。
2. 跨 OpenAlex、Crossref、arXiv 去重后执行 RRF 风格融合和 MMR 风格多样性选择。
3. 每次外部扩展形成 `support`、`challenge`、`context` 三路查询；部分路径失败时保留其余可信结果。
4. 同一来源跨查询命中时保留全部 `retrievalIntents` 和 `retrievalQueries`，不能把 challenge 命中直接解释为反驳。
5. 保留明确的开放全文 URL，但在全文尚未解析时将 `evidenceBasis` 固定为 `abstract`，提示词和复核器不得扩张为全文证据。
6. 继续执行句级 evidence ID 白名单、引用关系方向检查、独立复核和自动外部扩展的确定性删除降级。

## 仍需超过参考项目的部分

下一阶段必须把“有全文链接”和“有可引用全文证据”严格分开：

1. 仅下载排名靠前的 2-4 个合法开放获取来源；每次重定向都重新检查 HTTPS、公网地址、大小上限和 PDF 魔数。
2. 按页提取并生成稳定 ID：`external-evidence:<canonical-paper-id>:<content-hash>:<page>:<chunk-index>`。
3. 原文注册表是引用解析的唯一事实源；向量索引只保存 ID，不作为引用文本来源。
4. 对页面/用户请求先拆成 atomic propositions，再为每个 proposition 生成支持和挑战查询。
5. 先做 BM25 + embedding 召回，再用 cross-encoder 或受控模型重排；记录每路 rank 和最终选择原因。
6. 每个 proposition 输出 `supported / partial / contradicted / insufficient`，并区分“没有证据”和“存在反证”。
7. 生成后重新从原文注册表按 ID 取回文本复核，不能复用生成提示词中的可变副本。
8. 记录覆盖率、反证查询覆盖率、无效引用率、全文获取率和 top-N 稳定性，作为发布门禁。

以上设计比单独参考任一项目多保留两项薄读特有约束：论文内闭包优先，以及当前页面内容决定后续入口而非反向生成入口。

## 2026-07-30 运行链路与性能门

本轮复核把失败条件分成四类，避免把可修复的结构问题误报成证据失败：

| 阶段 | 可恢复条件 | 必须停止条件 |
| --- | --- | --- |
| 目标与本地证据 | 证据规划/观察 JSON 无效、规划 ID 越界、工具计划命中为空（使用本轮 allowlist 的有界保底读取） | 没有选中文献、主论文不在当前文库、PDF 没有可引用文本、取消信号已触发 |
| 外部检索 | support/challenge/context 任一路失败但仍有可信完成结果；已验证来源可复用；全文下载或解析失败时保留摘要证据 | 所有检索路由失败且没有已验证来源；来源身份/书目字段不合法；论文外生成没有任何可信来源 |
| 生成与证据 | 规划、观察、句级复核的结构响应各允许一次只修 JSON 的定向重试；自动外部扩展的 unsupported 纯外部句可删除并重新复核 | 真实模型调用失败；结构门连续失败；正文句无本轮 evidence/source；句级复核仍有 unsupported；闭包内引用外部来源 |
| 持久化与恢复 | 本地保存失败保留内存产物；中断下钻仅在快照可完整核验时允许重新提交 | artifact/document/parent/evidence/source 任一边界变化；不能伪装续跑或生成本地假结果 |

性能约束同步落地：最多 12 条已抽样证据直接进入生成 prompt，只有更大的矩阵才启动 bounded planner + observation；薄读已通过句级证据复核后不再重复调用不参与放行的通用远端回答审计。外部检索仍保留 support、challenge、context 三种意图，但 arXiv 只用于 support 主召回，次级意图使用 OpenAlex/Crossref，避免三次 3 秒限速排队。`includeArxiv` 进入 artifact 检索缓存键，禁止不同 provider 策略错误复用。

外部来源选择保留已验证 citation edge 的优先级，同时至少保留不同检索意图的有界候选；topic-search/related 仍只能作为阅读线索，不能在生成层升级为引用关系。
