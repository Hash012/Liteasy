# 薄读“很好地完成了”的判定标准

本文是薄读模态的验收标准与后续开发准绳，优先级高于当前 MVP 的局部实现。它与 `新模态-薄读.md`、`薄读-外部项目架构对比.md` 一起使用。

## 一句话定义

一个“很好地完成了”的薄读，不是把论文压成一段顺滑摘要，而是：

1. 用真实的 Agent 链路生成。
2. 能按论文类型做有重点的总述。
3. 能继续向下深入，并始终保留证据来源。
4. 能区分论文内证据与外部知识。
5. 能在同一标签页内稳定导航、批注、保存、恢复。
6. 不假装已经有社区后端，但要把未来同步接口和状态留好。

## 硬门槛

以下任一条不满足，都不能算完成。

### 1. 必须走真实 Agent 链路

- 薄读生成不能只靠本地模板、固定拼接文本、静态 fixtures。
- 必须经过可追踪的 Agent 工作流，至少包含：上下文装配、检索/证据收集、生成、审计、结构化产物落盘。
- 任何失败都要明确停止，不能回退成“看起来像生成成功”的本地演示文案。

### 2. 必须兼容 OpenAI 和 DeepSeek

- OpenAI 与 DeepSeek 都要能作为真实模型链路成功工作。
- 薄读的 provider 选择应沿用系统既有模型配置，不在 UI 里硬编码成单一路径。
- 任一 provider 配置缺失时，要给出明确错误，不要静默降级成假数据。

### 3. 首次生成时必须使用正确的目标论文

- 优先使用当前 PDF 阅读区正在打开且已选中的那一篇。
- 如果当前没有打开的已选论文，再使用选中列表中的第一篇。
- 这条规则必须固定，不允许靠“看起来差不多”的自动猜测。

### 4. 结果必须按 `artifactId` 组织

- 薄读的结果、批注队列、待同步状态、提示词侧重点，都必须按 `artifactId` 作为边界。
- 不能用 `paperId` 取代 `artifactId` 作为最终产物边界，因为同一篇论文可能对应不同会话侧重点。
- 跨 artifact 关联同一篇文献时，必须使用独立 paper identity，不得把它和薄读产物边界混在一起。

### 4.1 文献身份链必须稳定

- 文献身份解析优先级固定为：`doi -> arxivId -> semanticScholarId -> title+authors+year hash -> local paper id`。
- 公开批注、Intuecho 推荐、外部知识扩展和跨会话复用都必须引用这个 paper identity。
- 当 DOI / arXiv / Semantic Scholar / authors / year 缺失时，可以落到 local paper id，但 UI 和开发文档必须明确这只是本地 fallback。
- `artifactId` 仍然是薄读结果边界；paper identity 只用于识别“同一篇文献”。

### 5. 批注必须是完整闭环，但社区同步先本地化

- 私有批注必须能完整保存、恢复、编辑、删除。
- 公开开关必须存在。
- 自动公开设置必须存在。
- 公共批注先进入本地 `pending_public` 队列。
- UI 必须明确显示“等待 Intuecho 同步”。
- 在社区后端未接好之前，不允许伪装成已经同步到社区。

### 6. 证据与外部知识必须分开

- 总述和下钻内容里，来自论文内的证据与论文外知识必须分开标注。
- 前台总述不应长期呈现为工程化的“关键判断 / 论文内证据 / 外部知识”三块主面板；主体验应是一段可阅读文本，证据以句子级轻量标记进入。
- 呈现出的每个内容性句子都必须有关联证据边界：优先关联论文内 evidence ID；确实越出论文闭包时关联外部知识来源；无证据句必须标记为待复核，不能假装 grounded。
- 论文内证据不能只保存为字符串；必须至少包含 evidence span：paperId、chunkId、page、quote、confidence。
- summary 的关键判断必须形成 claim；claim 必须标记 `grounded`、`weak` 或 `unsupported`，其中 `grounded` 必须引用本轮论文内 evidence ID。
- summary 的句子级证据映射必须保存为结构化数据，用于点击句子后跳转 PDF 原文证据。
- 继续深入时，上一层 claim 与 evidence span 必须进入下一轮 Agent 上下文，用于保持证据边界和判断连续性；下一轮新输出仍必须引用本轮 evidence ID，不能把上一层证据当作新来源伪造。
- evidence span 在 UI 中必须能打开对应 PDF 原文位置，并用 text-layer quote 匹配或 PDF offset 高亮具体证据范围；用户点击总述句子或证据入口后，目标 PDF 中的“证据句”必须高亮指引查看。匹配失败时可以退回页级定位，但必须在接手文档中说明限制。
- 当阅读深度跨过“论文原文闭包”边界时，必须显式提示。
- 跨边界后允许继续深入，但背景色或视觉状态必须变化，让用户一眼看出已经不是纯论文内证据。
- 外部来源与目标论文的关系必须是结构化字段，并严格区分“目标论文引用该来源”“该来源引用目标论文”“相关工作”“仅主题检索命中”。只有 OpenAlex 等上游返回的显式引用/相关图字段才能形成前三种关系；无法解析目标论文或缺少图字段时必须降级为“仅主题检索命中”，不得让模型猜测引用关系。

### 7. 全部呈现内容都要能被批注

- 所有内容性文本块都应支持选中、批注、继续深入。
- 不能只有总述可选，其他层级或推荐内容却变成死文本。

### 8. 语言必须跟随系统设置

- 必须支持中文（默认）/ English / 跟随系统。
- 薄读生成、UI 文案和后处理都要一致遵循目标语言。
- 默认中文时，关键术语保留原文，并用中文括注。

## 质量标准

### 总述质量

- 总述要抓论文读完后真正留下的核心印象，而不是平均覆盖所有章节。
- 对理工类实验/推理-结论型论文，应优先讲：核心结论、关键推导、在学科知识图谱中的位置。
- 对方法型、资源型、综述型论文，重点可以不同，但必须由论文类型驱动，而不是固定模板驱动。
- 总述长度没有硬性上限，但目标是简洁、直指核心，通常 400 字内更理想。

### 下钻质量

- 下钻文本必须和选中的范围、层级深度、补充提示词有关。
- 必须能看出它是在回答“为什么这里值得继续读”，而不是换个说法重写总述。
- 如果用户从同一段落继续深入，系统应尽量保持术语、引用位置和上下文连贯。
- 如果上一层已有结构化 claim/evidence，下钻结果应体现承接、细化、修正或补足关系，不能像无上下文新摘要。

### 结构质量

- 必须有明显的层级导航。
- 必须有返回上一级和进入下一层的路径。
- 如果一个节点下有多个子节点，应能看见可选分支，而不是把所有下一层混成一段长文。
- “遗漏板块”按钮的数量没有硬上限，应由当前总述实际遗漏的内容决定。

### 可视化质量

- 页面不能只有字，必须有清晰的状态可视化。
- 需要有：当前层级、来源类型、是否越过闭包边界、待展开入口、选区弹窗、推荐栏、等待同步状态。
- 视觉状态要稳定，不要让文字和按钮互相遮挡或跳版。

### 性能与手感

- 交互要丝滑，不能生成后长时间空白。
- Agent 正在生成时，必须有明确进度或阶段反馈。
- 结果加载、层级切换、批注弹层、推荐栏开合都要保持可用，不应破坏阅读流。

## 验收场景

以下场景都通过，才算“很好地完成了”。

1. 选中一篇论文，点击薄读。
2. 系统用真实模型生成总述，且总述明显是“按论文类型取舍后的核心结论”。
3. 总述下方出现合理的“深入了解”入口，而不是固定死的几个按钮。
4. 选中总述里的词句继续深入，能在同一标签页内进入下一层。
5. 连续深入后，系统明确提示已经进入论文闭包之外的外部知识层。
6. 右侧推荐栏同步更新，且状态可收起、可恢复。
7. 任意文本可批注，公开批注会进入 `pending_public` 队列并显示等待同步。
8. OpenAI 和 DeepSeek 都能跑通同一条薄读链路。
9. 模型失败时，系统停在错误态，不输出伪造的本地结果。
10. 外部扩展中，来源链接、目标论文身份和 cited/citing/related 关系可追溯；无法确定关系时明确显示为主题检索结果。

## 后续开发者的介入点

薄读后续要由人工继续优化时，优先改这些地方：

- **论文分类器**：可以先粗分，后面再人工细化类型。
- **提示词注册表**：不同类型、不同层级、不同语言的提示词应该可替换。
- **闭包边界策略**：什么时候算论文内证据用尽，应该可调。
- **证据呈现策略**：哪些内容显示为论文内证据，哪些显示为外部知识，应该可配置。
- **推荐策略**：Intuecho 推荐可先简单分组，后续再接真正的社区画像和关系图。
- **语言策略**：系统语言、术语保留、括注规则要能单独调整。
- **同步策略**：`pending_public` 到真实社区的同步器要作为独立模块接入。

## 明确不算完成的情况

- 只做出一个看起来漂亮的本地摘要面板。
- 只支持单一 provider。
- 只支持本地静态文案，不经过 Agent 链路。
- 没有证据和外部知识的边界。
- 没有批注保存与公开队列。
- 没有层级导航，只能单页展开。
- 生成结果和选中文献、选区范围、层级深度没有稳定关系。
