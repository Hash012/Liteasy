# 薄读人工接手文档

本文给后续人工开发者接手薄读模态使用。优先级顺序为：`新模态-薄读.md`、用户在对话中的补充要求、`薄读-完成标准.md`，然后才是当前代码实现。当前实现已经从本地模板原型推进到真实 Agent 链路第一版，但仍不是最终高质量版本。

## 当前状态

已完成：

- 薄读入口在多模态悬浮按钮中可用，标签页标题为“薄读”。
- 初始薄读和继续深入都走 `runAgentAnalysis("thin_reading")`，不再用本地模板伪造正文。
- 薄读模型请求使用 `requireLive: true`；mock endpoint 会报错并停止。
- OpenAI 与 DeepSeek 复用系统模型配置中的 `models.default_provider`、`models.cloud_proxy_endpoint` 和 dev-cloud 上游 key，不在薄读 UI 中硬编码 provider。
- 生成结果以 `artifactId` 为边界保存；批注、待同步队列、branch、prompt 侧重点都挂在 `ThinReadingDocument.artifactId` 下。
- 初始目标论文优先取当前 PDF 阅读区正在打开且已选中的论文，否则取选中文献集第一篇。
- `thinReadingPromptRegistry.ts` 会用标题与 evidence 分项评分，把论文归入 experimental / theoretical / systems / dataset / survey / benchmark / position / humanities / unknown；每类已有 3 个中英文人工“信号 -> 读后留存”少样例。近分类型会输出 winner / runner-up / conflict / confidence 诊断，prompt 要求按主要贡献和读者认知模型裁决，不能按章节名机械选型。
- 已新增薄读模型输出的 Zod schema 校验；模型必须返回合法 JSON，`paperType` 必须为允许值，`paperEvidence` 必须引用本轮 evidence ID。
- live 生成启用严格 trace quality gate：模型必须显式返回覆盖至少 95% 正文的 `summarySentences`；句级 evidence/source 必须属于顶层集合，`grounded` 句必须有论文内 evidence。首次失败会带确定性原因定向修复一次，第二次仍失败则停止；不会在 live 路径中由本地代码猜测句级来源。修复次数和原因保存在 `thinReading.qualityGate`。
- 已新增 `paper-identity/paperIdentity.ts`，按 `doi -> arxivId -> semanticScholarId -> title+authors+year hash -> local paper id` 解析主文献身份。新生成的 `ThinReadingDocument.paperIdentities` 和 Intuecho 推荐 scope 会携带该身份。
- 薄读节点区分论文内证据 `paperEvidence` 和外部知识 `externalKnowledge`；论文内证据已扩展为 `paperEvidenceSpans` 与 `claims`，包含 page、chunk、quote、confidence 和 claim grounded/weak/unsupported 状态。越出论文闭包时 `withinPaperClosure=false`，UI 改变背景状态。当前闭包判定不是只信模型字段：模型返回外部知识、模型主动标记 false、检索覆盖有缺口或 `retrievalConfidence < 0.75` 都会进入闭包外视觉状态。
- 继续深入时，`ThinReadingGenerationContext` 会携带当前 active node 的 `parentClaims` 和 `parentEvidenceSpans`；Agent prompt 会把它们作为上一层连续性上下文，同时仍要求本轮 `paperEvidence` / `claims.evidenceIds` 只引用本轮 evidence ID。
- Intuecho 推荐栏会随当前 active node 更新，支持收起成右侧窄图标栏并恢复；收起状态保留 pending_public 数量提示。
- 私有批注、公开开关、自动公开、编辑、删除、`pending_public` 队列和“等待 Intuecho 同步”提示已本地闭环。
- 设置页新增“薄读生成语言”：中文、English、跟随系统。薄读生成、界面文案、辅助功能标签和下钻提示统一使用解析后的目标语言；默认中文，关键术语要求保留原文并中文括注。
- 已接入薄读专用 OpenAlex 外部检索链：父节点已在论文闭包外，或用户选区提示明确要求外部/后续/相关工作时，模型生成前会先检索真实来源。来源保存 `OpenAlex ID / DOI / URL / authors / year / abstract / retrievalQuery / relevance`；模型只能引用本轮白名单中的 `openalex:W...` source ID。无结果、超时、上游错误或伪造 source ID 都会停止闭包外生成，不回退静态知识或模型常识。

仍需继续打磨：

- 论文类型 registry 已有首轮人工少样例和可解释冲突裁决，但 matcher 仍是轻量启发式；需要用真实 PDF gold set 校准权重、误分类和跨学科混合类型，而不是继续凭直觉叠关键词。
- 证据已有 page/chunk/quote/confidence span 与 claim 结构，UI 可从薄读 evidence span 跳转到 PDF 对应页，并在真实 PDF text layer 中按 quote 归一化匹配后高亮证据范围；但还不是 PDF text offset、跨 claim 关系图或稳定跨版式 quote 定位的完整证据图。
- Intuecho 推荐仍是本地待同步占位结构，没有社区后端。
- 论文身份链已有本地解析和薄读持久化，但 DOI / arXiv / Semantic Scholar / authors / year 仍需要接真实元数据抽取、云端 metadata sync 和社区后端索引。
- 外部知识已接 OpenAlex search 第一阶段，但还没有 Semantic Scholar / CrossRef、多 provider 重排，以及 cited / citing citation graph 关系链。
- 已新增可重复运行的确定性 eval harness 与 8 个手工参考场景，覆盖 experimental / systems / dataset / survey / theoretical / humanities 及 root / branch；会记录核心概念召回、引用精度、句级来源边界、遗漏板块召回、下钻连续性、闭包判定、语言和 unsupported 占比。当前参考场景仍是代码内人工基准，不是逐页标注的真实 PDF gold set。

## 当前 Agent 链路

初始生成：

1. `ReaderPane` / `AppShell` 给 artifact workflow 提供 reader-prioritized selected papers。
2. `useArtifactActions.startArtifactTask("thin_reading")` 创建 `artifactId` 和 `ThinReadingGenerationContext`。
3. `runAgentArtifactAnalysis` 通过 selection attachment 传入 `paperIds` 和 `thinReadingContext`。
4. `useAssistantAgentController` 根据 attachment 收窄 selected papers 与 imported chunks。
5. `generateAssistantAnswer` 对 `artifactType === "thin_reading"` 走真实模型，调用 `buildThinReadingAgentPrompt`，并设置 `requireLive: true`。
6. `parseThinReadingModelSeed` 使用 Zod schema 和严格 trace gate 解析模型 JSON；若句级覆盖或来源集合不合格，模型只获得一次定向修复机会。
7. parser 校验 `paperEvidence` / `claims.evidenceIds` / `summarySentences` 引用本轮可用 ID，再从 `AnalysisEvidence` 构造 evidence spans 与 claims，生成 `ThinReadingNodeSeed`。
8. 本地 audit / HTTP audit 给分析 run 评分；生成 `CompletedMultiPaperAnalysis`。
9. `useArtifactActions` 用 `createThinReadingDocument` 构造节点树并保存 artifact result。

继续深入：

1. `ThinReadingTab` 对遗漏板块或正文选区调用 `onGenerateBranch`。
2. `useArtifactActions.generateThinReadingBranch` 用当前 active node、source、prompt 创建下一层 `ThinReadingGenerationContext`，并带上上一层 `claims` 与 `paperEvidenceSpans`。
3. 上一层 `withinPaperClosure=false` 或选区提示明确要求论文外研究时，`generateAssistantAnswer` 先调用 dev-cloud OpenAlex endpoint；无可追溯来源则停止。
4. 仍走 `runAgentAnalysis("thin_reading")` 和真实模型；prompt 只暴露本轮允许的 external source ID。
5. parser 同时校验论文内 evidence ID 和 external source ID 白名单，返回的 seed 经 `advanceThinReadingDocument` 加为 child node，并保存整个薄读文档。

失败原则：

- 模型 endpoint 是 mock：报错并停止。
- provider/model 不在当前策略允许列表：报错并停止。
- 模型 JSON 不可解析、summary 过短、缺少论文内证据和外部知识标记：报错并停止。
- live 输出缺少显式句级映射、覆盖低于 95%、来源集合不一致或伪装 grounded：定向修复一次；再次失败则报错并停止。
- 闭包外检索无结果、超时、上游错误，或模型引用本轮不存在的 external source ID：报错并停止。
- artifact 保存失败：任务失败或显示本地状态保存失败，不伪装成功。

## 模型输出契约

当前模型必须返回 JSON：

```json
{
  "paperType": "experimental",
  "summary": "string",
  "summarySentences": [{"text": "summary sentence", "evidenceIds": ["evidence-id"], "externalKnowledge": [], "status": "grounded"}],
  "withinPaperClosure": true,
  "paperEvidence": ["evidence-id"],
  "claims": [{"text": "claim text", "evidenceIds": ["evidence-id"], "status": "grounded"}],
  "externalKnowledge": ["openalex:W123456789"],
  "omittedSections": [{"sectionKey": "method", "label": "方法"}],
  "recommendations": [{"relationship": "方法与问题设定", "note": "本地待同步的理解线索", "compatibility": 0.78}]
}
```

注意：

- `paperType` 只能是 `experimental`、`theoretical`、`systems`、`dataset`、`survey`、`benchmark`、`position`、`humanities`、`unknown`。
- `paperEvidence` 只能引用 prompt 中给出的 evidence ID 或含 ID 的短说明。
- `claims` 是 summary 的关键判断。`grounded` claim 必须引用 prompt 中给出的 evidence ID；如果模型不返回 claims，当前 parser 会用 summary 和已验证 evidence 构造一个 synthesis claim。
- `externalKnowledge` 不是自由文本，只能放本轮 OpenAlex 检索白名单中的 source ID；结构化元数据保存在 `evidence.externalSources`。
- `paperEvidence` 与 `externalKnowledge` 不能同时为空。
- `recommendations` 是 Intuecho 本地占位线索，不是社区真实数据。
- `withinPaperClosure=false` 会让 UI 进入外部知识视觉状态。

## 人工完善分类与提示词

当前已经新增 `thinReadingPromptRegistry.ts`，但只是可运行的第一版。它用标题和 evidence 中的关键词先粗分论文类型，再把类型取舍、遗漏板块倾向和生成阶段注入 prompt；模型仍可在 JSON 的 `paperType` 中修正分类。

当前 registry 维度：

- `paperType`: `experimental`, `theoretical`, `systems`, `dataset`, `survey`, `benchmark`, `position`, `humanities`, `unknown`
- `stage`: `root`, `omitted_section`, `selected_text`
- `language`: `zh-CN`, `en-US`

后续每个 registry entry 应继续补齐：

- 类型识别提示。
- 总述关注点。
- omitted section 候选规则。
- evidence 要求。
- 外部知识许可边界。
- 输出 JSON schema 示例。

各类型的初始倾向：

- 实验/推理-结论型：核心结论、关键推导、实验支撑、学科知识图谱位置。
- 方法型：问题设定、方法机制、相对 baseline 的改进点、限制。
- 系统型：架构、数据流、组件职责、性能/可靠性取舍。
- 数据集/资源型：资源定义、构建流程、覆盖范围、评测用途、偏差。
- 综述型：分类框架、争议轴线、知识地图、未解决问题。
- 人文/理论型：核心论题、概念谱系、论证路径、解释力和边界。

## 闭包边界策略

当前实现用模型返回的 `externalKnowledge` / `withinPaperClosure` 与本地检索质量一起判定：

- 模型主动返回 `withinPaperClosure=false`：直接视为闭包外。
- 模型返回非空 `externalKnowledge`：视为闭包外。
- 本轮分析存在 `coverage.missingPaperIds`：视为检索覆盖不足，降为闭包外。
- 本轮 `retrievalConfidence < 0.75`：视为检索置信度不足，降为闭包外。

后续应做成可配置评分：

- 检索到的论文内 evidence 是否足以支撑当前问题。
- 当前 node 是否多次要求解释论文没有定义的前置概念。
- 选区 prompt 是否明确要求外部背景、相关工作或学科知识图谱。
- 模型是否引用了非当前论文来源。
- 引用来源是否外溢：paperEvidence 无法覆盖 summary 中的关键判断。

建议状态从布尔扩展为：

- `inside_paper`: 主要依据目标论文内部证据。
- `near_boundary`: 论文内证据不足，开始需要少量外部背景。
- `outside_paper`: 主要依赖外部论文、教材知识或领域常识。

UI 上 `near_boundary` 和 `outside_paper` 都应有视觉提示，`outside_paper` 必须改变背景色。

## 批注与 Intuecho

当前本地模型：

- `visibility: "private" | "pending_public"`
- `annotationSettings.autoPublic`
- `pendingPublicAnnotationIds`
- `thinReadingIntuechoSyncQueue.ts` 会从已持久化的薄读文档投影出按 `artifactId` 分界的本地 pending 队列。
- `createLocalPendingIntuechoSyncAdapter()` 只返回 `pending_public`，不会伪装成远端已同步；后续真实社区后端只替换 adapter。
- UI 文案：“等待 Intuecho 同步”
- 推荐栏可收起/恢复；收起态只展示 Intuecho 竖向入口和 pending 数量，不把本地占位推荐伪装为真实社区数据。
- `paperIdentities[paperId].primary` 按 DOI / arXiv / Semantic Scholar / title-author-year hash / local id 优先级给同步器提供文献唯一标识。

不要在社区后端完成前把 `pending_public` 展示成“已公开”。后续同步器建议独立模块化：

- 输入：`artifactId`、paper identity、scope、annotation body、target、visibility。
- 输出：Intuecho annotation id、sync status、error。
- 失败重试：按 `artifactId` 分队列，避免一篇论文的失败阻塞另一个薄读 artifact。

推荐策略当前只是本地线索。接社区后应按 scope 请求：

- 全篇：paper identity。
- 板块：paper identity + sectionKey。
- 局部：paper identity + evidence span / quote hash。

## 文献身份链

后续接 Intuecho、外部知识和跨会话复用时，稳定身份链已经有第一版本地实现：

1. DOI。
2. arXiv ID。
3. Semantic Scholar ID。
4. `title + authors + year` hash。
5. local paper id。

当前入口在 `paper-identity/paperIdentity.ts`，不要把这套逻辑散在 UI 或 artifact 里。`artifactId` 仍是薄读产物边界；paper identity 只用于跨 artifact 关联同一文献。

当前限制：

- `Paper` 类型已允许 `doi`、`arxivId`、`semanticScholarId`、`authors`、`year`，但本地示例文献大多还没有这些字段。
- helper 会从 title/sourcePath 中尽量推断 DOI/arXiv/Semantic Scholar ID；推断不到时落到 local paper id。
- `local_paper_id` 只在当前本地文献库内稳定，不能直接用于跨设备、外部知识或 Intuecho 社区关联。薄读 UI 会明确显示“仅本地身份 / Local identity only”；接同步器时必须先补全更高优先级身份，或把该状态作为不可公开同步处理。
- 真正接社区前，需要把 PDF 元数据抽取、文献库 metadata sync 和社区索引统一到同一身份格式。

## 证据模型下一步

当前 `ThinReadingNodeEvidence` 已包含第一版结构化证据：

```ts
type ThinReadingEvidenceSpan = {
  id: string;
  paperId: string;
  chunkId?: string;
  page?: number;
  quote: string;
  normalizedQuote?: string;
  confidence: number;
};

type ThinReadingClaim = {
  id: string;
  text: string;
  evidenceIds: string[];
  status: "grounded" | "weak" | "unsupported";
};
```

当前已经做到：

- 薄读 summary 的关键判断能落到 `claims`。
- `grounded` claim 引用的 evidence ID 会被校验为本轮 evidence。
- `paperEvidenceSpans` 会从真实 `AnalysisEvidence` 构造 page、chunk、quote、confidence。
- branch generation 会把 parent claim/evidence span 带入下一层 prompt，用于保持术语、证据边界和深入方向连续；但下一层输出仍必须引用本轮 evidence ID，不能把 parent span 当作新证据来源。
- UI 的论文内 evidence span 主按钮会触发 `onOpenEvidence`，由 `AppShell.openEvidenceInReader` 打开对应 PDF 并定位到 page；`PdfReader.findQuoteRangeInTextLayer` 会在目标页 text layer 中按 quote 做归一化匹配并绘制 Agent evidence 高亮。批注是独立按钮。
- UI 会显示 claim 状态和 evidence quote，并且 claim/evidence 都可批注。
- `weak` / `unsupported` claim 会在 UI 中显示待复核标记，不再像普通正文一样混入薄读内容。

后续还应做到：

- PDF text offset / quote offset 能从 PDF extractor 写入 evidence span，用 offset 替代当前的运行时 quote text-layer 匹配。
- 对扫描版、断词严重或 quote 被改写的 PDF，应增加 OCR / fuzzy matching / fallback 定位策略。
- unsupported claim 当前已标记 review；下一步应接自动 retry 或人工确认工作流。

## Provider 与 API 配置

OpenAI 与 DeepSeek 都通过 dev-cloud 和 settings 走统一链路：

- `models.default_provider`
- `models.cloud_proxy_endpoint`
- `models.control_plane_endpoint`
- dev-cloud `.env.local` 中的上游 key
- 现阶段 `project-docs/test-api.md` 这条 OpenAI 兼容链路已按 `OPENAI_KEY` + `API_END_POINT` 代理到 `gpt-5.4-mini` 实测通过；`gpt-5.5` 在当前代理组上仍可能返回 520 或模型不可用。
- 当前仓库里的 DeepSeek `.env.local` key 已在 `deepseek-v4-flash` 上实测通过；此前 401 的根因是本地 key 值被多余单引号包住。

薄读不应直接读取 key，也不应在前端写 provider 专用分支。新增 provider 时应扩展 model policy / dev-cloud payload，而不是改薄读 UI。

手动验证 provider 的最小流程：

1. 启动 `LiteasyClaw/services/dev-cloud`。
2. 设置 provider 为 OpenAI，生成一次薄读 root 和一次 branch。
3. 设置 provider 为 DeepSeek，重复同一流程。
4. 断开或改错 key，确认任务失败而不是生成假内容。
