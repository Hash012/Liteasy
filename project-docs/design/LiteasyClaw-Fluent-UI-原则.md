# LiteasyClaw Fluent UI 原则

本项目采用 Fluent 2 的 Windows 工作台取向：清晰的命令层级、克制的表面装饰、可预测的反馈，以及键盘和辅助技术可达性。它是产品自身的设计规范，不复制 Microsoft 产品界面或品牌资源。

## 信息取舍

- 主界面只显示完成当前任务所需的标题、内容、状态和下一步动作。
- 不展示“这是演示环境”“某能力由什么实现”“后续会接入什么”等研发说明。它们属于文档、设置的诊断区，或错误详情的折叠项。
- 空状态只给一个行动方向；状态文本使用简短、可行动的语言，例如“锁定选中文献后开始分析”。
- 长解释放入 `title`、帮助入口或按需展开的详情，不能占据工作区的常驻空间。

## Fluent 2 落地规则

- 使用 `@fluentui/react-components` 的 `FluentProvider` 与标准组件，优先采用其 Button、Input、Dialog、Menu 等组件，而非新造同类控件。
- 色彩使用中性表面、单一蓝色主操作和语义状态色；不要用多色渐变表达普通层级。
- 面板采用 4–8px 圆角、轻边框和低层级阴影。只有浮层、对话框和拖拽目标可以提升阴影或对比度。
- 左侧活动栏以图标表达一级区域，文字通过可访问名称和悬浮提示提供；当前区域使用浅蓝底和蓝色图标。
- 主内容标题优先让位给文档名、会话或任务。产品口号、技术架构和模型链路不应出现在阅读或对话的标题栏。

## 文案与状态

- 文案用动词开头：`导入文献`、`锁定选择`、`开始分析`、`重试同步`。
- 成功、加载和失败反馈应与用户动作或结果关联；失败详情默认收起，并给出可执行的恢复步骤。
- “当前”“状态”“说明”等前缀只有在缺少其他上下文时才使用；已通过选中态、标题或位置表达的信息不重复写出。

## 评审清单

在新增 UI 前确认：是否存在唯一明确的主操作、是否删掉了实现细节、空状态能否在一眼内理解、键盘焦点与 `aria-label` 是否完整、以及文本是否可在不依赖颜色的情况下理解。

参考：[Fluent 2 for React](https://fluent2.microsoft.design/components/web/react/)。
