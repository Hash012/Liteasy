# 薄读运行验收与人工开发接手

更新时间：2026-07-28

本文用于交接薄读模态的运行验收、真实模型链路验证和后续人工开发。需求优先级仍然是：`新模态-薄读.md`、用户对话补充、`薄读-完成标准.md`，最后才是当前代码实现。

## 当前结论

薄读已经达到当前 `薄读-完成标准.md` 所列硬门槛的工程验收状态：

- 生成与继续深入都走真实 Agent 链路，不再用本地模板伪造薄读正文。
- OpenAI 兼容链路和 DeepSeek 链路都已 live smoke 通过。
- 薄读产物、批注、pending_public 队列、prompt 侧重点都按 `artifactId` 作为边界。
- 首次薄读目标论文遵循“当前 PDF 阅读区打开且已选中优先，否则取选中第一篇”的规则。
- 论文身份链按 `doi -> arxivId -> semanticScholarId -> title+authors+year hash -> local paper id` 保存。
- 总述/下钻保留句子级证据映射、论文内 evidence span、claim 状态和外部知识边界；闭包外会改变视觉状态。
- 论文闭包外分支已接 OpenAlex 真实检索；模型只能引用本轮返回的 source ID，外部上角标可打开来源 URL，检索失败不生成假结果。
- 私有批注、公开开关、自动公开、编辑、删除和“等待 Intuecho 同步”本地闭环已存在。
- 中文 / English / 跟随系统的薄读生成语言设置已接入。

这不是薄读质量的终局版本。后续重点应放在真实 PDF gold set、PDF offset 级证据定位、citation graph 与多 provider 外部检索、Intuecho 后端同步和 live-model nightly eval。

## 运行入口

### OpenAI 兼容测试接口

推荐用于浏览器前端验收：

```bash
cd LiteasyClaw/desktop

```

该脚本读取仓库根目录 `project-docs/test-api.md` 中的 `OPENAI_KEY` 和 `API_END_POINT`，映射为 dev-cloud 所需的 `OPENAI_API_KEY` 和 `OPENAI_BASE_URL`。默认模型已改为当前实测可用的 `gpt-5.4-mini`。

注意：

- 不要把 `project-docs/test-api.md` 中的密钥复制到终端输出、截图、issue 或文档。
- 如果代理端点支持模型变化，优先用 `/v1/models` 查询可用模型，再设置 `VITE_LITEASY_OPENAI_MODEL`。

### DeepSeek

DeepSeek 通过 `LiteasyClaw/services/dev-cloud/.env.local` 配置：

```dotenv
DEEPSEEK_API_KEY=<本地密钥>
DEEPSEEK_BASE_URL=https://api.deepseek.com
LITEASY_MODEL_PROVIDER=deepseek
```

当前已确认一个实际问题：`.env.local` 中的 DeepSeek key 不能带额外单引号。此前 401 是由于 key 被 `'...'` 包住；去掉外层引号后，`deepseek-v4-flash` live smoke 通过。

如果要在 Tauri 中验收真实模型，先把 dev-cloud `.env.local` 和 desktop `.env.local` 配好。不要把真实 key 写进已跟踪文件。

## 手工 UI 验收清单

1. 启动真实模型链路：OpenAI 用 `npm run dev:test-api`；DeepSeek 用 `.env.local` 切到 `LITEASY_MODEL_PROVIDER=deepseek` 后启动。
2. 导入或打开至少一篇 PDF，并确保目标论文处于选中状态。
3. 如果阅读区当前打开的 PDF 也在选中集中，点击薄读时应优先使用这篇；否则使用选中文献列表第一篇。
4. 点击多模态悬浮按钮中的“薄读”，观察 Agent 阶段反馈：检索证据、生成、审计、结构化产物保存。
5. 生成完成后检查页面：同一 Tab 内出现总述、层级、论文类型、遗漏板块按钮、Intuecho 推荐栏；`关键判断 / 论文内证据 / 外部知识` 应收敛在轻量“依据”区域中，不应压过总述主视觉。
6. 检查总述质量：不是平均章节摘要，而是按论文类型抓核心结论、关键推导和学科位置；中文默认应保留关键英文术语并中文括注。
7. 检查总述每个内容性句子都有证据标记；点击有论文内证据的句子，应打开对应 PDF 页并高亮“证据句”。展开“依据”后点击 evidence span，也应进入同一套 PDF quote 高亮路径；匹配失败可退回页级定位。
8. 点击遗漏板块，薄读应在同一 Tab 进入下一层；如果已有同 source child，应复用旧 child，不重复生成。
9. 选中总述或下钻正文中的文字，弹出“深入/批注”入口；填写可选提示词后继续深入，应生成与选区和上一层 claim/evidence 连贯的内容。
10. 当父层已在闭包外，或选区提示明确要求外部/后续/相关工作时，应先看到外部检索阶段；生成后页面进入闭包外视觉状态，“外1”上角标应能打开真实来源 URL。OpenAlex 无结果或失败时必须停止，不能生成假外部内容。
11. 对总述、claim、evidence、external knowledge、recommendation 添加批注；私有批注应保存、恢复、编辑、删除。
12. 勾选公开或开启自动公开后，批注应进入 `pending_public`，UI 显示“等待 Intuecho 同步”，不能显示成已公开。
13. 收起 Intuecho 推荐栏，应变为窄栏入口并保留 pending 数；再次点击可恢复。
14. 切换薄读生成语言为 English / 跟随系统，重新生成，检查 prompt 和 UI 后处理遵循目标语言。
15. 故意切到 mock endpoint 或错误 provider/key，薄读应停在错误态，不能输出本地假内容。

## 当前数据契约

`ThinReadingDocument` 是薄读保存边界，必须按 `artifactId` 管理。`paperIdentity` 只用于跨 artifact 识别同一篇论文，不得替代 `artifactId`。

核心节点字段：

- `summary`: 当前层薄读文本。
- `paperType`: 论文类型。
- `withinPaperClosure`: 是否仍在论文闭包内。
- `evidence.paperEvidenceSpans`: 论文内 evidence span，含 `paperId`、`chunkId`、`page`、`quote`、`confidence`。
- `evidence.claims`: summary 关键判断，状态为 `grounded` / `weak` / `unsupported`。
- `evidence.summarySentences`: summary 每个内容性句子的证据边界，含 `text`、`evidenceIds`、`externalKnowledge`、`status`。
- `evidence.externalKnowledge`: 本轮已验证的 external source ID 列表，不是自由概念文本。
- `evidence.externalSources`: OpenAlex 结构化来源，保留 provider、source ID、DOI、URL、作者、年份、摘要、查询和相关度。
- `omittedSections`: 当前总述未覆盖但可深入的小标题按钮。
- `recommendationScope`: Intuecho 推荐和 pending 队列请求范围。
- `annotations`: 私有和 `pending_public` 批注。

模型输出必须是可解析 JSON；错误 JSON、空 evidence、伪造 evidence ID 都应失败。

## 后续人工开发优先级

### P0：质量评测闭环

建立 5-20 篇论文 gold set，至少覆盖实验型、方法型、系统型、数据集型、综述型和理论/人文型。每篇保存 gold summary、关键遗漏板块、选区下钻答案、证据位置和外部边界判定。

完成标准：

- 有可重复运行的 eval harness。当前可用命令为 `cd LiteasyClaw/desktop && npm run test:thin-reading-eval`，内置 8 个手工参考场景；真实 PDF gold set 仍需继续补齐。
- 记录 root summary 核心命中率、evidence precision、branch relevance、external boundary、language consistency、unsupported claim 占比。

### P0：人工完善 prompt registry

扩展 `thinReadingPromptRegistry.ts`，加入人工样例、类型冲突裁决、少样例提示词和语言风格约束。重点不是增加模板，而是让不同论文类型的“读完后真正留下的东西”被正确取舍。

完成标准：

- 每类论文至少 3 个人工案例。当前 9 类均已有 3 个中英文“信号 -> 留存”抽象案例，并且只注入当前候选类型。
- root / omitted_section / selected_text 三个 stage 都有差异化指导。当前已分别约束核心取舍、遗漏板块对父结论的作用、选区为何值得深入。
- 中英文输出有独立风格检查。当前 prompt 与 deterministic eval 已分语言处理；仍需真实模型样本做风格人工评分。
- 类型冲突不能静默靠数组顺序决定。当前分类结果会记录 title/evidence 分项、runner-up、conflict 和 confidence，并在 prompt 中要求按主要贡献裁决。

### P1：证据定位升级

把 PDF text offset / quote offset 写入 evidence span，减少运行时 text-layer quote 匹配的不稳定。扫描版或断词严重 PDF 增加 OCR / fuzzy matching / page fallback 分级。

完成标准：

- evidence span 能定位到页内字符范围。
- 失败时显示页级 fallback 原因。
- claim 到 evidence 的跳转和高亮稳定可复现。

### P1：结构化输出能力

把 Zod schema 与 provider 的结构化输出能力对接，减少自由 JSON 解析漂移。OpenAI 兼容代理和 DeepSeek 要分别确认支持能力；不支持时保留当前 parser 作为严格 fallback。

完成标准：

- provider 返回 schema 违规时失败并显示可读错误。
- 不得自动补出看似成功的假 seed。
- DeepSeek 常见 shape drift 有测试覆盖。

### P1：外部知识检索扩展（OpenAlex search 第一阶段已完成）

当前已接 OpenAlex search，并实现 source ID 白名单、超时/空结果/上游失败分类、生成前停止和 UI 来源跳转。下一步接 Semantic Scholar / CrossRef、多 provider 去重重排，以及 citation graph 的 cited / citing / related 关系。

完成标准：

- 外部知识引用不混入论文内 evidence。
- UI 能解释为什么越过闭包。当前有闭包外状态和来源上角标；还需增加关系类型与边界原因详情。
- cited / citing / related works 至少有一条可追踪链路。

### P1：Intuecho 后端同步

保留当前 `pending_public` 本地语义，新增真实 sync adapter。不要把本地 pending 显示成已公开；只有远端返回 Intuecho annotation id 后才能标记 synced。

完成标准：

- 队列按 `artifactId` 隔离。
- 同步失败可重试且不阻塞其他 artifact。
- 同步 payload 使用 paper identity，而不是只用 local paper id。

### P2：元数据抽取与身份链增强

把 PDF metadata、DOI/arXiv/Semantic Scholar 查询、云端 metadata sync 统一进 `paperIdentity.ts` 的输入链。

完成标准：

- DOI / arXiv / Semantic Scholar / authors / year 能从真实文献库补齐。
- fallback 到 local paper id 时 UI 和日志明确说明。
- 跨 artifact 同论文关联稳定。

### P2：UI 与性能打磨

继续优化薄读页面的加载态、分支导航、Intuecho 折叠、选区弹层和长文本布局。大文献下要避免空白等待和 UI 跳版。

完成标准：

- 生成阶段始终有可见进度。
- 分支切换、批注编辑、推荐栏开合不阻塞阅读。
- 移动和桌面视口无文字遮挡。

## 接手注意事项

- 不要提交 `.env.local`、`project-docs/test-api.md` 密钥内容、上游响应全文或任何 API key。
- 不要把 `pending_public` 改名成 `public`，直到 Intuecho 后端真的接通。
- 不要把同一篇论文的 paper identity 当作薄读产物边界；薄读边界始终是 `artifactId`。
- 不要把上一层 evidence span 当作下一层新证据；下一层输出仍必须引用本轮 evidence ID。
- 不要用 mock endpoint 验收薄读质量；mock endpoint 对薄读应失败。
- 当前 docs 里的“已通过”以 2026-07-28 的本地验证为准；换机器或换 key 后需要重跑 live smoke。
