# 薄读运行验收与人工开发接手

更新时间：2026-07-28

本文用于交接薄读模态的运行验收、真实模型链路验证和后续人工开发。需求优先级仍然是：`新模态-薄读.md`、用户对话补充、`薄读-完成标准.md`，最后才是当前代码实现。

薄读已实现并自动验证了当前 `薄读-完成标准.md` 中的大部分核心链路，但尚不能宣称整体“很好地完成”。以下是已有工程能力，不等同于真实 PDF gold set、完整人工 UI/性能验收或 Intuecho 后端已经完成：

- 生成与继续深入都走真实 Agent 链路，不再用本地模板伪造薄读正文；薄读页面会直接显示当前 artifact task 的检索、生成、审计或保存阶段与进度，避免分支生成期间只显示空白或静态等待文案。
- 薄读始终是单篇阅读任务：当前阅读区已打开且被选中的论文会优先进入首位，root context、导入、Agent evidence scope 与保存的 artifact papers 都只保留这篇 `primaryPaperId`；其他已选论文不应混入全篇总述。继续深入时也会重新收敛旧缓存或异常文档中的 `paperIds` / artifact paper refs 到该主论文，不能让历史多篇数据扩大 branch evidence scope。多论文集合仍服务于其他分析模态。
- OpenAI 兼容链路和 DeepSeek 链路都已 live smoke 通过。
- 薄读产物、批注、pending_public 队列、prompt 侧重点都按 `artifactId` 作为边界。
- OpenAlex 自 2026-02-13 不接受匿名 API 请求。用户必须在设置的“OpenAlex 外部文献检索”中配置自己的 API key；桌面端仅以 `X-OpenAlex-Api-Key` 私有请求头交给本地 dev-cloud，服务端只在 OpenAlex URL 的 `api_key` 查询参数中使用它。密钥不得进入 artifact、检索缓存、Agent prompt、日志或测试记录。缺失、格式无效或被 OpenAlex 以 401/403 拒绝时，外部检索在缓存前明确停止并返回 `openalex_api_key_required`（HTTP 503）；桌面端展示可操作的设置提示，且绝不能退化为无图关系的 Crossref 结果。非 UI 的 live 验收使用 `LiteasyClaw/.env.openalex.example` 规定的 `api_key=` 字段，实际值放在同目录 `.env.openalex.local`（已被忽略）。
- 首次薄读目标论文遵循“当前 PDF 阅读区打开且已选中优先，否则取选中第一篇”的规则。
- 论文身份链按 `doi -> arxivId -> semanticScholarId -> title+authors+year hash -> local paper id` 保存。
- 总述/下钻保留句子级证据映射、论文内 evidence span、claim 状态和外部知识边界；闭包外会改变视觉状态。
- 论文闭包外分支已并行接 OpenAlex 与 Crossref 真实检索，并按 DOI 去重重排；模型只能引用本轮返回的 source ID，外部上角标可打开论文来源 URL，来源区另提供不可替代的 provider record URL 用于核验上游记录。Crossref 来源以规范 DOI 和 `https://api.crossref.org/works/<encoded-doi>` 保存，且永远只能标为“主题检索命中”；目标论文引用、引用目标论文、相关工作三类关系仍只由 OpenAlex 图字段确定。
- live 模型输出经过严格句级 trace gate；不完整输出只允许一次有边界的结构修复，连续失败不保存产物。
- 薄读产物和 PDF 原文的私有批注、公开开关、自动公开、编辑、删除和“等待 Intuecho 同步”本地闭环已存在。PDF 原文批注会保存 paper identity、页码和文本层矩形范围，公开项使用独立的 `pdf_passage` scope，不会伪装成薄读 artifact。
- 中文 / English / 跟随系统的薄读生成语言设置已接入。

### 当前图表证据边界

- 本地 PDF 先使用 PDF.js `getTextContent()` 取得页面文字层，再按普通文本切块。文字层中的图注、表头、单元格、坐标标签和数字可能进入模型证据，但其二维坐标、表格行列、跨页表头、图例颜色和曲线对应关系不会保存。
- 只有一页完全没有可选文字时，导入链路才会把整页渲染后交给 Tesseract OCR。OCR 结果仍被当作无结构页面文本；含正文文字层但图表本身是位图的页面不会额外 OCR 图表。
- 论文外 PDF 的全文补强当前以 `ocrEnabled: false` 提取，只能使用内嵌文字；扫描页或纯图片图表不能形成外部全文 evidence。
- 模型网关当前只接收 `prompt: string`，不传 PDF 页面图片、图表截图或结构化单元格。因此生成文本可能使用论文正文对图表结论的复述，也可能使用被正确抽取的局部表格文字，但不能将其描述为视觉或结构化图表理解。
- 当前数字保真质量门会要求下钻句保留其所概括量化断言中的原文数字；它不验证数字属于哪一行、哪一列、哪条曲线或哪个实验条件。若纯文本顺序不足以直接支持这些关系，证据复核应收缩或拒绝该断言。

仍未完成的核心验收包括：扩展真实 PDF gold set、扫描版 PDF 的 OCR / 模糊匹配 / 稳定坐标定位、结构化表格解析与视觉图表理解、更多 provider（例如 Semantic Scholar）与真实联网多 provider 验收、Intuecho 真实后端联调、live-model nightly eval，以及跨视口 UI/性能人工验收。薄读与 PDF 原文都具备显式 HTTPS Intuecho 端点设置和手动同步入口：远端确认的 `intuechoAnnotationId` / `syncedAt` 才会保存为已同步；失败项保留错误与重试资格，编辑待同步项会重新进入队列。薄读同步只把回执合并到请求后仍为同一 `updatedAt` 版本、且尚未被其他回执确认的公开批注；请求进行中会禁用已有批注的编辑、删除和公开切换，避免旧回执覆盖本地新状态或把撤回误示为已生效。PDF 原文批注按 `paper.id + sourcePath` 保存在本地 WebView storage，可随同一文献重开恢复；旧版本地批注会迁移为私有记录。PDF 公开项的 payload 携带稳定 paper identity、页码和矩形范围，并在 `local_paper_id` 身份时拒绝联网。当前没有实际社区端点，不能将此称为后端同步已经验收。扫描 PDF 的 OCR 语言可在设置中选择 English、简体中文或中英混合，并会传入下一次导入的 Tesseract worker；OCR 证据仍保守地只支持页级定位。当前已实现的是 artifact 隔离的单轮 OpenAlex/Crossref 检索失败恢复与结果复用，不是无界 citation traversal。

## 自动化验收

当前已在 2026-07-28 跑通：

```bash
cd LiteasyClaw/desktop
npm test
npm run build

cd ../services/dev-cloud
npm test
```

真实模型薄读（消耗模型调用，不纳入默认 `npm test`）使用：

```bash
cd LiteasyClaw/desktop
npm run test:thin-reading-live-model
```

该命令只从 `project-docs/test-api.md` 读取现有测试 API 配置，在可用 loopback 端口临时启动 `dev-cloud`，再执行桌面 `generateAssistantAnswer` 的真实薄读路径。它会验证 `execution.mode=live`、strict structured output、句级 trace gate、论文内 evidence span 和 summary sentence 映射；并以运行时实际生成的 evidence ID 对 ColBERT 的 late interaction / MaxSim / 效率取舍 root case 运行 gold 评分。ColBERT 的人工标注允许 `experimental` 或 `systems`，因为其主要贡献同时具有检索架构与实证方法特征；其他 gold case 默认仍要求单一明确类型。不会打印密钥或完整模型响应。运行完成会关闭临时服务。它仍是单一 root case，不替代跨论文的质量评测或人工阅读验收。

默认 provider 是 OpenAI。要让同一 quality gate 使用本地 `dev-cloud/.env.local` 中的 DeepSeek 配置，显式执行：

```bash
cd LiteasyClaw/desktop
LITEASY_THIN_READING_LIVE_PROVIDER=deepseek npm run test:thin-reading-live-model
```

该分支不会读取 `project-docs/test-api.md`；若 `DEEPSEEK_API_KEY` 未配置，会清晰失败，不会退回 mock。

当前 live gold case 默认是 `colbert`。可用 `LITEASY_THIN_READING_LIVE_EVAL_CASE=bert` 切换为 BERT 的双向预训练 root case，例如：

```bash
LITEASY_THIN_READING_LIVE_EVAL_CASE=bert npm run test:thin-reading-live-model
```

`LITEASY_THIN_READING_LIVE_EVAL_CASE=bert-external` 是单独的联网闭包外 case：它以 BERT DOI 请求 OpenAlex，并要求生成结果保留本轮实际返回的 relation、外部 source ID、HTTPS 论文链接、规范 `sourceRecordUrl` 和“论文外证据”边界。它不会把开放检索结果强行要求为特定论文或 `cites_target`，以免把合法的 `related` / `topic_search` 误判为失败；关系保真按每个 `summarySentences.externalKnowledge` 所绑定的 source 判定，不能因本轮另有 citation graph source 就把该 `topic_search` / `related` 来源写成 citation。违规输出会被 generation gate 拒绝并仅允许一次定向修复。AlphaFold `cites_target` 的具体图边由 `npm run test:thin-reading-openalex-live` 单独核对。该 case 要求 `LITEASY_OPENALEX_API_KEY`，或工作区根目录、`LiteasyClaw/`、`LiteasyClaw/services/dev-cloud/` 下 `.env.openalex.local` 的 `api_key=`；live harness 只在子进程内把它注入临时用户设置，绝不输出或持久化。它消耗一次外部检索和一次模型调用，不纳入默认测试。

live harness 以 `verbose` reporter 运行，并为每条 live test 设置 120 秒上限；它会依次输出本地服务健康检查、Vitest 启动、外部检索与模型生成、质量门评估等阶段。只以最终退出码和断言结果判定通过，阶段日志不构成通过证据。

`LITEASY_THIN_READING_LIVE_EVAL_CASE=bert-zh-branch` 会运行中文论文内下钻：它以 BERT 的 `masked language modeling（掩码语言建模）` 为当前页 evidence，并向模型传入上一层“双向预训练” claim/span。评测要求保留紧邻术语对、父层连续性、句级 evidence 映射和论文内闭包；它消耗一次模型调用，不纳入默认测试。

`LITEASY_THIN_READING_LIVE_EVAL_CASE=glue-benchmark` 会运行 GLUE 的基准评测型 root case：它使用仓库内 GLUE PDF 的九项 NLU 任务、资源比较与 linguistic diagnostic suite evidence，要求总述保留任务结构、句子/句对边界、跨设置可比较性与诊断层的作用，不能退化成泛化的数据集目录。它消耗一次模型调用，不纳入默认测试。

`LITEASY_THIN_READING_LIVE_EVAL_CASE=squad-dataset` 会运行 SQuAD 的数据集/资源型 root case：它使用仓库内 SQuAD PDF 的 crowdworker、Wikipedia passage 与 extractive answer evidence，要求总述保留资源构建、答案边界和评测用途，不能退化成模型结果摘要。它消耗一次模型调用，不纳入默认测试。

1. 启动真实模型链路：OpenAI 用 `npm run dev:test-api`；DeepSeek 用 `.env.local` 切到 `LITEASY_MODEL_PROVIDER=deepseek` 后启动。
2. 导入或打开至少一篇 PDF，并确保目标论文处于选中状态。

6. 检查总述质量：不是平均章节摘要，而是按论文类型抓核心结论、关键推导和学科位置；中文默认应保留关键英文术语并中文括注。

   自动化质量门还应证明 `summarySentences` 完整覆盖 100% 的正文、句级来源属于顶层白名单、`grounded` 只用于论文内 evidence；不能以 parser 猜测映射冒充模型输出完整。

9. 选中总述或下钻正文中的文字，弹出“深入/批注”入口；填写可选提示词后继续深入，应生成与选区和上一层 claim/evidence 连贯的内容。

11. 对总述、claim、evidence、external knowledge、recommendation 添加批注；私有批注应保存、恢复、编辑、删除。
12. 勾选公开或开启自动公开后，批注应进入 `pending_public`，UI 显示“等待 Intuecho 同步”，不能显示成已公开。
13. 收起 Intuecho 推荐栏，应变为窄栏入口并保留 pending 数；再次点击可恢复。
14. 切换薄读生成语言为 English / 跟随系统，重新生成，检查 prompt 和 UI 后处理遵循目标语言。
15. 故意切到 mock endpoint 或错误 provider/key，薄读应停在错误态，不能输出本地假内容。

## 当前数据契约

`ThinReadingDocument` 是薄读保存边界，必须按 `artifactId` 管理。`paperIdentity` 只用于跨 artifact 识别同一篇论文，不得替代 `artifactId`。

核心节点字段：

- `summary`: 当前层薄读文本。
- `paperType`: 论文类型。
- `withinPaperClosure`: 是否仍在论文闭包内。
- `evidence.paperEvidenceSpans`: 论文内 evidence span，含 `paperId`、`chunkId`、`page`、`quote`、`confidence`；可选 `pageTextStart` / `pageTextEnd` 是页内的规范化文本搜索坐标，用于 PDF text-layer 的重复 quote 消歧，不是原始 PDF 字节偏移。规范化规则固定为 NFKC、Unicode dash 统一为 `-`、删除 soft hyphen、折叠空白并转小写；提取器和阅读器共享同一规则，不能各自演化。
- 当前 `paperEvidenceSpans` 没有图表区域、表格行列、图例或坐标轴字段；其中的表格/图形文字仍只是 `quote` 的纯文本内容。未来若增加结构化图表 evidence，必须使用可区分的新契约并保留原始区域与提取来源，不能把模型推断回填成 PDF 原文 span。
- `evidence.claims`: summary 关键判断，状态为 `grounded` / `weak` / `unsupported`。
- `evidence.summarySentences`: summary 每个内容性句子的证据边界，含 `text`、`evidenceIds`、`externalKnowledge`、`status`。
- `evidence.externalKnowledge`: 本轮已验证的 external source ID 列表，不是自由概念文本。
- `evidence.externalSources`: OpenAlex 结构化来源，保留 provider、source ID、DOI、论文落地 URL、不可变的 `sourceRecordUrl`、作者、年份、摘要、查询、相关度和 `relation`。desktop client、Agent attachment 和 artifact cache 都要求 `sourceId` 是 `W...`、`id` 严格等于 `openalex:<sourceId>`、`sourceRecordUrl` 严格等于 `https://openalex.org/<sourceId>`，落地 `url` 必须是 HTTPS；不能因落地页优先而丢失或伪造上游记录。`relation` 只允许 `cited_by_target`、`cites_target`、`related`、`topic_search`。DOI 或 arXiv 身份可触发一次精确目标解析；其他无法锁定目标 work 的情况保守使用 `topic_search`。
- `omittedSections`: 当前总述未覆盖但可深入的小标题按钮。
- `recommendationScope`: Intuecho 推荐和 pending 队列请求范围。
- `annotations`: 私有和 `pending_public` 批注。

本地 artifact cache 在恢复薄读前会校验 document 版本、`artifactId` 一致性、根/活动节点、批注队列、语言字段和外部来源载荷；不完整或错配缓存会被丢弃，不能覆盖可用产物。批注必须属于当前 artifact 和存在的节点，target 必须与该节点匹配，`pending_public` ID 只能指向对应可公开批注。节点 source 与 recommendationScope 也必须匹配：root 只能对应 whole-paper，遗漏板块必须保留同一 sectionKey，正文选区必须保留同一 excerpt 和 evidenceIds。旧版 OpenAlex 来源若仅缺少可由 `sourceId` 确定的 `sourceRecordUrl`，恢复时会安全补成 `https://openalex.org/<sourceId>`；其他不可信来源记录不迁移、不渲染。

旧产物若缺少 `summarySentences` 句级映射，界面会将每个摘要句显示为“待核”，不会从 node-level claim、`paperEvidence` 或外部来源猜测句级 grounded/weak 标记，也不会提供伪造的证据跳转；只有保存了明确句级映射的内容才能显示可点击上角标。同一句同时关联论文 evidence 和 external source 时，两类上角标必须并列显示为“证 n”和“外 n”，不得用其中一类遮蔽另一类来源。

页面选区保存批注时会保留内容 target：总述为 `node_summary`，外部来源为 `external_knowledge` 并带 source ID，Intuecho 推荐为 `recommendation` 并带 recommendation ID。不要在后续同步或恢复中把这些局部关联降级成无类型文本。选区批注在用户未显式勾选公开时也必须遵守 document 的 `autoPublic` 设置；开启自动公开后，所有批注入口都应进入本地 `pending_public` 队列。

浏览器验收已覆盖总述、外部来源正文和 Intuecho 推荐文本的选区、批注与深入入口；390px 窄视口还会核对选区弹层完整可见、保存后批注实际写回页面且无横向溢出。PDF 原文选区只用于定位、批注和普通问答上下文，不直接新建薄读分支；分支必须从薄读节点内已有的可审计文本发起。

应用重启时，在途 Agent 调用已中断，不能声称服务端续跑。薄读下钻任务仅在本地保存受限长度的重提交快照：`artifactId`、薄读文档版本、主论文 ID、父节点 ID 和 branch source。恢复时必须重新验证当前 artifact/document、父节点、遗漏板块或选区文本，以及选区引用的论文 evidence ID / 外部 source ID；任一项不匹配就只保留中断失败态。验证通过才显示“重新提交同一输入”，且它会创建新的模型请求，不复用旧 `runId`。根薄读和其他 artifact 任务不提供这种伪续跑入口。

从总述选区继续深入时，`selected_text` source 还会保存该选区相交的 `summarySentences.evidenceIds`。下一轮 prompt 将这些 ID 作为优先解释的父层证据，用于说明选区为什么值得继续读；它们不替代下一轮检索，下一层输出仍必须引用本轮 evidence ID。选中外部来源标题，或带“外 n”标记的总述句时，分支还会保存 `externalSourceIds`：只能指向父节点已验证的 canonical source，并会连同该来源元数据进入下一轮外部上下文；请求边界会拒绝“携带来源”与这些 source ID 不完全一致的附件。补充检索仍会尝试执行，但空结果不会丢弃用户明确选中的既有可追溯来源。`topic_search` 仍只能作为主题检索线索，不能被改写成引文关系。该分支的 `recommendationScope.kind="selected_passage"` 也会持久化同一组 `evidenceIds`、`externalSourceIds` 和 excerpt，并原样进入 `pending_public` 队列；未来 Intuecho 同步器必须用它们关联具体句段，不能把范围退化成整篇论文。恢复缓存时这些 ID 必须唯一，论文 evidence ID 必须属于父节点论文内 evidence 边界，外部 source ID 必须属于父节点外部来源；不满足时整个薄读缓存会被拒绝，避免把伪造 ID 送入下一轮 Agent。

选区原文在进入 Agent prompt 时最多保留 1,600 字符，补充提示最多 600 字符；超出部分以省略号截断，防止长选区挤占本轮 evidence、JSON contract 与审计约束。页面补充输入使用同一 600 字符上限。

模型输出必须是可解析 JSON；错误 JSON、空 evidence、伪造 evidence ID 都应失败。`summary` 在 JSON 原始字段中必须是一段连续自然文本，换行、小标题或列表式总述会在空白归一化前失败，不能被格式清洗后伪装成合格总述。论文原文、证据矩阵、父层文本、用户选区/补充资料和外部来源标题/摘要全部是不可信参考数据，不能覆盖薄读任务、结构化 schema 或 evidence/source 白名单；其中任何要求忽略规则、改变角色或泄露内容的文字都必须视为资料而非指令。
live 输出还必须通过 explicit trace gate。首次失败会进入 `repairing_structured_output`，修复 prompt 只能使用原 evidence/source 白名单；`thinReading.qualityGate` 保存 attempts、repaired 和 repairReasons。

## 后续人工开发优先级

### P0：质量评测闭环

建立 5-20 篇论文 gold set，至少覆盖实验型、方法型、系统型、数据集型、综述型和理论/人文型。每篇保存 gold summary、关键遗漏板块、选区下钻答案、证据位置和外部边界判定。

完成标准：

- 有可重复运行的 eval harness。当前可用命令为 `cd LiteasyClaw/desktop && npm run test:thin-reading-eval`。除 9 个手工参考场景外，已加入 8 篇仓库内公开 PDF（ColBERT、ACORN、Vector DBMS survey、Transformer、BERT、GLUE、SQuAD、古代语言语料分析）的 PDF-backed gold case；每条保存 SHA-256、相对路径、页码和 quote，并在测试中重新提取原始 PDF 核对。`npm run test:thin-reading-openalex-live` 是单独的 OpenAlex 联网图关系验收；`npm run test:thin-reading-external-live` 会同时核对 Crossref 的 AlphaFold DOI 规范记录、OpenAlex 图边，以及服务端聚合器是否返回 OpenAlex 和只能标为 `topic_search` 的 Crossref 来源。三条 OpenAlex live 命令统一要求 `LITEASY_OPENALEX_API_KEY` 或约定位置 `.env.openalex.local` 的 `api_key=`，读取器不输出密钥；两者均不纳入默认测试。
- 评测记录 root summary 核心命中率、citation precision、citation recall、evidence grounding、branch relevance、external boundary、external source traceability、external source gold match、external relation fidelity、language consistency、unsupported claim 占比。citation precision 防止无关 evidence 混入，citation recall 要求每条 gold 必要 evidence 都实际被 candidate 的 summary/claim/paperEvidence 引用，不能因只引用部分正确证据而通过。`evidence grounding` 要求候选 span 的 evidence ID、页码和 quote 同时回溯到 gold PDF；闭包外的每个 externalKnowledge ID 必须能映射到本轮 provider 来源的上游 ID、HTTPS 论文链接、规范 `sourceRecordUrl`、关系标签与检索 query，不能用自由文本冒充来源。涉及已验证图关系的 gold case 还必须锁定 canonical external source ID 与 relation，格式正确但指向另一篇论文的来源同样失败。关系保真以句子映射到的具体 source 为准：Crossref 必须是 `topic_search`，`topic_search` / `related` 不得因同轮其他来源存在图边而被写成已验证 citation；明确的否定性边界说明不算误述。
- 真实 PDF-backed case 已达到 12 条，覆盖 ColBERT、ACORN、Vector DBMS Survey、Transformer、BERT、GLUE、SQuAD 和古代语言语料分析；其中有中文 ColBERT root case，以同一真实 PDF span 验证 `late interaction（后期交互）` 的紧邻术语对。新增中文 BERT 下钻 case 以第 2 页 MLM 原文验证 `masked language modeling（掩码语言建模）` 必须承接父层“双向预训练”，不能退化为中文改写或独立摘要。另含一条 BERT 英文下钻 case，验证选区机制与上一层主轴的承接，以及一条 GLUE diagnostic-suite 下钻 case，验证 benchmark 总述向语言学诊断目的的承接；还包括一条 GLUE benchmark case、一条 SQuAD 资源型 case，以及一条人文型 case。人文 case 锚定了 patristic literature 中 biblical reuse 的语文学研究对象，避免把计算方法压过研究问题。手工 gold suite 另有一个真实外部边界 case：2026-07-28 查询 OpenAlex 得到 AlphaFold (`W3177828909`) 引用 BERT (`W2963341956`)，因此只能作为 `cites_target` 的论文外图关系呈现，不能倒灌为 BERT 论文内证据。`npm run test:thin-reading-openalex-live` 会从 AlphaFold 的 `referenced_works` 重新核对这条边，且会在 work ID 或标题漂移时失败。后续仍需扩到 5-20 篇的完整跨类型集；新增 PDF 必须沿用同一 provenance 契约，不能用摘要文本替代原文证据。

### P0：人工完善 prompt registry

扩展 `thinReadingPromptRegistry.ts`，加入人工样例、类型冲突裁决、少样例提示词和语言风格约束。重点不是增加模板，而是让不同论文类型的“读完后真正留下的东西”被正确取舍。

完成标准：

- 每类论文至少 3 个人工案例。当前 9 类均已有 3 个中英文“信号 -> 留存”抽象案例，并且只注入当前候选类型；每类另有不输出给用户的 coverage audit，用于检查高价值阅读维度，避免把 Literature-Review-Assistant 式固定栏目直接变成薄读大纲。
- root / omitted_section / selected_text 三个 stage 都有差异化指导。当前已分别约束核心取舍、遗漏板块对父结论的作用、选区为何值得深入。
- 中英文输出有独立风格检查。当前 prompt 与 deterministic eval 已分语言处理；中文关键术语除了 gold eval 同时核对原词与释义外，live parser 还会用本轮 evidence terms 拒绝“中文（原文术语）”的反向括注。中文选区或补充提示明确给出“原文（中文释义）”时，生成入口会把该术语对作为本轮硬约束，遗漏后只允许一次有边界的修复。`bert-zh-branch` 已在 OpenAI 兼容和 DeepSeek 真实路径通过；仍需更多真实模型样本做风格人工评分。
- 类型冲突不能静默靠数组顺序决定。当前分类结果会记录 title/evidence 分项、runner-up、conflict 和 confidence，并在 prompt 中要求按主要贡献裁决。

### P1：证据定位升级

PDF text offset 已写入 retrieval chunk、analysis evidence 和 thin-reading evidence span，并在薄读 marker、ArtifactTabs evidence-open request、AppShell reader target 和 PDF 跳转中以 `pageTextStart` / `pageTextEnd` 保留。提取器与 PDF text layer 使用同一套 NFKC / dash / soft-hyphen / 空白规范化坐标；重复 quote 按离持久化 offset 最近的候选消歧，已覆盖“第二次出现的引文含 soft hyphen 和全角字符”的回归。精确匹配失败后还会做一次仅移除空白/连字符的紧凑匹配，以处理常见的跨行断词和 Unicode dash 漂移，命中后仍从真实 text-layer 建立高亮范围。`ReaderPane.test.tsx` 还模拟同一 quote 在 100%/200% PDF 布局下的 Range 几何，要求生成的百分比覆盖层完全一致，防止缩放重渲染改变证据位置；Playwright 进一步加载真实 BERT PDF，在 100% 到 110% 缩放时等待 PDF.js canvas 重渲染，并要求 quote overlay 保持存在、四个比例坐标的差异均小于 `0.1%`。无法匹配时，主阅读区会明确显示“页级定位”原因。扫描版或缺失文字层的 PDF 现在会在桌面端按页渲染后使用 Tesseract.js OCR；`eng`、`chi_sim`、`eng+chi_sim` 语言包均作为静态应用资源离线提供。`npm run test:thin-reading-ocr-offline` 会真实渲染 `liteasy-ocr-scanned-fixture.pdf`、用本地语言包调用 Node Tesseract worker，并要求完整保留英文扫描证据句；同一命令还会读取仓库内固定的双语 PNG fixture，验证简体中文 evidence 主体和中英混合文本，因此不依赖执行机的中文字体。Playwright 的浏览器用例会通过 Vite 静态资源、PDF.js canvas 与浏览器 Tesseract worker 再次提取该扫描 PDF，防止语言包只在 Node 运行时可用。OCR 得到的 chunk、analysis evidence 和 thin-reading span 坐标为 `textExtraction="ocr"`，阅读器会明确提示“该证据来自 OCR 识别，当前只能页级定位”，不会伪造原生 text-layer 高亮。跨类型真实 PDF 的人工视觉验收与可稳定持久化的 glyph/DOM 坐标仍待完成。

完成标准：

- evidence span 已携带页内字符范围，并用于重复 quote 消歧。
- 精确匹配失败时已显示页级 fallback 原因。
- 扫描 PDF 会尝试实际 OCR，且 OCR 证据在 UI 中保守降级为页级定位；不能把 OCR 文本误报为可精确 text-layer 高亮。
- claim 到 evidence 的跳转和高亮仍需在真实 PDF、扫描 PDF 和跨缩放条件下完成稳定性验收。

### P1：结构化输出能力

薄读现在会把与客户端 Zod parser 对应的 JSON Schema 一并传到 provider：OpenAI Responses 使用 `text.format=json_schema` 且 `strict=true`，DeepSeek Chat Completions 使用 `response_format=json_object`。客户端仍以 Zod parser、evidence/source 白名单与 live trace gate 作最终裁判。兼容代理若以 `400` / `422` 拒绝结构化参数，provider 只会重试一次不带结构化参数的同一 JSON prompt；该兼容路径同样必须通过严格 parser 和 trace gate，绝不降级成假 seed。

完成标准：

- OpenAI / DeepSeek 的 provider 请求形状已有自动化覆盖。2026-07-28 已通过本地真实 dev-cloud 做最小 strict-schema smoke：OpenAI 兼容链路与 DeepSeek 都返回 `{"marker":"LIVE_SCHEMA_OK"}`，且 `execution.mode=live`。每次切换兼容代理、模型或 provider 配置后仍需重跑。
- provider 返回 schema 违规时由 Zod 和 trace gate 失败并显示可读错误；不得自动补出看似成功的假 seed。
- DeepSeek JSON-object 模式与后续 shape drift 的严格 parser 测试已覆盖；仍需累积真实模型失败样本。

### P1：外部知识检索扩展（OpenAlex + Crossref 第一阶段已完成）

当前已接 OpenAlex search 与 Crossref DOI 检索，按 DOI 去重重排，并实现 source ID 白名单、超时/空结果/上游失败分类、生成前停止和 UI 来源跳转。Crossref 只产生 `topic_search`，不能伪造成 citation graph；其规范 DOI provenance 会原样保留到下一轮 Agent context。OpenAlex 是当前唯一能产生 cited / citing / related 的 provider。2026-07-28 对 Semantic Scholar 公开 Graph API 的最小 DOI 请求可建立连接但返回 HTTP 429；在没有受控 API key、配额和重试预算前不得把它接成生产 provider。后续接入后仍需进行真实联网多 provider 验收。

当同一次检索同时存在明确 `cited_by_target` / `cites_target` 图边与未被用户主动选中的 `topic_search` / `related` 结果时，生成上下文只传入明确图边；显式选中的来源仍会保留。这样不会把低强度检索线索混进 citation 句，也不会隐藏用户主动要求阅读的外部来源。每个传入来源还携带 source-ID 级的 relation 叙述许可。2026-07-29 的闭包外 live case 曾揭露模型混写 `topic_search` 与 citation 的问题，随后完成上述输入收敛；首次复测遇到上游 OpenAI 兼容代理 HTTP 503，故这条真实闭包外 case 仍需在服务恢复后重跑，不能记录为通过。

完成标准：

- 外部知识引用不混入论文内 evidence。
- UI 能解释为什么越过闭包。当前闭包外节点会显示“已越出论文原文闭包”的原因，并列出本轮外部来源及 `cited_by_target` / `cites_target` / `related` / `topic_search` 的可读关系；上角标仍可直达原始记录。
- cited / citing / related works 至少有一条可追踪链路。
