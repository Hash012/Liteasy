### 进行中

1. "导出文档"功能, HTML 导出的就是 md 普通文本, 需要进一步渲染; 导出 PDF 采样需进一步准确化, 当前生成PDF内容对应不上并且极度模糊. 可以参考[一个与我们技术栈相同的 Markdown 组件](https://github.com/Stravica/markdoc)
2. "薄读"中, 提供的"节点图"渲染中, 节点的边改成只有两段垂直直线的模式, 而不是现在三段直线在中间弯折. 并且, 边的链接位置要发生适应性改变, 比如, 如果一个节点 A 在节点 B 的右边, 则 B 从右边发出一条边连接 A; 如果将 A 拖动到 B 上方, 那么改成从 B 上方发出一条边. 采用一个粗略的改动决定算法就可以, 尽可能减少边的重叠.
3. 薄读字数限制与内容实质需要更多字数才能讲明白的问题冲突: 解决方案: 要求只要不是就特定知识点提出问题, 就尽可能泛化地从全局角度回答, 到了特定知识点才提供较为独立的讲解, 并指出参见哪些知识来理解这个知识, 仅在提示词里面对 AI 做软性要求, 不强制 Hook 拦截过多字数. 在"薄读"里插入图片需要设置为一个开关.
4. Markdown 渲染**未能覆盖全部** Markdown 出现场景, 尤其是数学公式与 code block 出现场景; 在生成内容时, 哪些内容面向用户省略还需打磨, 以及生成时可能有 `evidence-xxxxx` 字样出现, 这个建议用一些小标签/符号来代替, 而不是影响观感
5. Mindmap 功能, 当前模式是采用了一堆 subagents 狠狠干, 精确到每一个术语是什么意思, 但是可能过于消耗, 而且定位跟薄读有冲突, 还不能交互. 感觉可以改成薄读里面的一个 autogeneration 模式, 或者先不生成过深并提供交互进展.
6. *交互性*. 用户点击生成后, 应当反映进度, 而不是一个不会跳动的进度条. 需要将AI当前动作/流式输出文字等等以美观的形式呈现给用户. 如果连不上 API, 也需要给出合理的提示.
7. 丰富文献搜索的机制, 并给出用户搜索选项
