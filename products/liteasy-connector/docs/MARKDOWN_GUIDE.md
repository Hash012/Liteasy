# 批注 Markdown 示例

把下面围栏里的文本复制到插件批注编辑器，即可查看实际效果。

````markdown
# 这节我真正理解了什么

**核心结论**不应只抄原句，要补一个 *自己的例子*。

## 接下来的验证

- [x] 能不用原文解释一遍
- [ ] 写一个边界情况
  - 输入为空时会怎样？
  - 并发修改时会怎样？

> 这是从阅读中产生的疑问，不一定是作者的结论。

| 设计 | 优点 | 代价 |
| :--- | :--- | ---: |
| 按需加载 | 减少无用渲染 | 多一次恢复操作 |

```rust
fn main() {
    let learned = true;
    println!("understood: {}", learned);
}
```

时间复杂度可以写作 $O(n \log n)$。

$$
\sum_{i=1}^{n} i = \frac{n(n+1)}{2}
$$

~~之前的误解~~ → ==现在需要特别留意的边界==。

一个补充观点[^why]。

[^why]: 这里写下论证或后续材料。
    缩进四个空格可以续写同一个脚注。

: 重复执行同一操作，不产生额外效果。

先尝试自己回答，再展开检查。

</details>
````

双美元、括号式公式只在正文中解析；代码块保留原文。公式使用 KaTeX 支持的 TeX 子集，不是完整 TeX 排版系统。Mermaid / PlantUML 等围栏保留代码，不执行。危险 HTML 不保留；HTML 能排版不代表能执行脚本、嵌入网页或任意样式。

建议一篇批注围绕一个要点，正文尽量保持可独立理解：我的解释 → 自己的例子 → 不确定之处 → 待验证问题。保存的是原始 Markdown，预览方式不会改变正文。
