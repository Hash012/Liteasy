# Mobile accounts

Android uses an external system browser and authorization code + PKCE S256 ([RFC 8252](https://www.rfc-editor.org/rfc/rfc8252.html)). The callback is exactly `com.liteasy.mobile://oauth/callback`; state and the verifier expire after five minutes and survive process recreation in installation-bound Android Keystore encryption. Matching callbacks are consumed once. The app never accepts a password or exposes access/refresh tokens to JavaScript.

Configure a distinct public identity client named `liteasy-mobile-public`, with the exact callback above, PKCE S256 required, no password grant/client secret, and the `liteasy-mobile` access-token audience. The local/staging realm templates contain this client. Existing local realms can add it using the existing `configure-keycloak.sh` reconciliation entry point. Set `LITEASY_IDP_MOBILE_CLIENT_ID` on the Liteasy API after registering the client. Without that variable the existing API remains operational and mobile identity endpoints report unavailable.

The native account service accepts HTTPS API and issuer endpoints, requires token/revocation/authorization endpoints on the configured issuer origin, and refuses HTTP redirects while exchanging credentials. `/v1/mobile/session` verifies the access token through the existing JWT/JWKS and live introspection boundary, checks its audience and public client ID, and returns only the verified subject/issuer. The Android app does not derive identity from unverified ID-token claims. Refresh keeps the same subject; rotated refresh credentials are encrypted before being reused. Logout clears local credentials and stops that library's background sync before attempting server revocation.

Account scope includes API endpoint, issuer and subject. The guest library remains separate and accessible while signed in. Copying guest materials requires an explicit choice, keeps original files, skips existing attachments and copies metadata/annotations transactionally. Publication receipts and account/sync credentials are not copied. Downloaded account material stays available offline and is hidden from the guest library after logout.

Deployment changes here are templates and code, not a claim that a live identity provider/API has been upgraded. Deploy the identity-management audience update with the API so disabling/deleting an account confirms revocation for mobile as well. Live-provider login requires the operator's HTTPS endpoint and an actual user account. A debug APK has the same HTTPS requirement.
