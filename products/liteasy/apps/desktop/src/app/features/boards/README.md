# Canvas whiteboards

Whiteboard files use [JSON Canvas 1.0](https://jsoncanvas.org/spec/1.0/) (`.canvas`), the format used by Obsidian. The object repository retains immutable content revisions, provenance, placements and knowledge relations as the working index. Opening an existing unbound board or creating a board automatically materializes its Canvas file; historical objects are not deleted or rewritten.

On desktop, managed files live in `boards/<account hash>/<object hash>.canvas` below the configured Liteasy data directory. File grants, account isolation, bounded UTF-8 reads and compare-and-swap writes use `noteFileService`. The browser preview uses origin-private filesystem storage when supported. **另存为白板文件** writes a user-chosen `.canvas`, including into a connected Obsidian Vault. Subsequent edits autosave after a short debounce. A failed save retains the local board and reports the error. Conflicting external edits require reopening or saving a separate copy; they are never overwritten automatically. Opening the board, returning focus to Liteasy, or receiving a local file-change event refreshes the file when safe. This is not a filesystem watcher.

The adapter preserves node order, coordinates (including negative origins), sizes, colors, groups, links, edge directions/labels and unknown extension fields. Text cards render Markdown. Markdown file cards without subpaths load through the existing folder grant; editing a card creates independent text rather than overwriting the linked note. Media and heading/block references appear as file-reference cards and preserve their `file`/`subpath` fields. Group background image paths are preserved, but background images and binary media are not yet rendered inline or copied by export. Keep referenced assets with their Vault-relative paths when transferring a Canvas to another folder or application.

Groups use a translucent boundary and an external label; moving a group moves fully contained cards in one version-checked board patch. Cards have a compact selection toolbar, subtle resize handles, neutral connectors and theme-aware surfaces. Existing pan, zoom, marquee selection, keyboard movement, context transfer and history remain available.

Common gestures follow [Obsidian Canvas](https://obsidian.md/help/plugins/canvas): click to select, double-click to edit, double-click empty space to create a note, and drag a card directly to move it. Shift-click adds/removes a selection; dragging selected cards moves them in one undoable operation. Hold Shift to constrain movement or preserve a corner resize's aspect ratio. Space-drag or middle-drag pans; Ctrl/Command-wheel zooms at the pointer, Shift-wheel scrolls horizontally. Shift+1 fits all cards and Shift+2 fits the selection. Escape or leaving an edited note saves changes; source excerpts still require explicit conversion into a note. The selection toolbar's transfer handle sends existing content references to chat or another board.

Selection and temporary foreground ordering never write board revisions. Pointer movement below four screen pixels is ignored. Layout edits run sequentially, refresh only the active board, and reuse unaffected content and typography. Rapid local geometry edits can advance through their own revision chain; concurrent external changes still fail version checks. Autosave retries snapshots invalidated by ongoing edits without treating them as external file conflicts.

Regression coverage: `boardFiles.test.ts`, `boardFileController.test.tsx`, native `note_files::store::tests`, and `canvasNotesHierarchy.browser.spec.ts` cover round trips, managed storage, preservation of external changes, group movement and both color schemes.
