> 这是本机资产 MCP，不是单论文评论 Review。代码跨平台复用，但当前开发记录不能代替你的 Windows 安装包与真实客户端验收。

## 第一次连接
1. 打开 **设置 → AI 与助手 → 本机 MCP · Codex**，启用本机 MCP，先保持只读。
2. 点击 **复制配置**，将生成的段落合并到当前操作系统用户的 `.codex/config.toml`。已有同名 `[mcp_servers.liteasy]` 时替换该段，不覆盖其他设置。
3. 使用设置页给出的程序路径和 `connection.json` 路径，不要照抄别人的盘符或猜测自己的 AppData 位置。
4. 重启客户端的 MCP 连接或客户端本身，同时保持 Liteasy 打开。
5. 先要求客户端查找一个非敏感笔记并读取标题与少量内容，确认连接的是正确账号和资料库。

客户端版本可能调整菜单名；本机 STDIO 和配置字段以客户端官方说明为准。WSL 或远程主机不会自动共享 Windows 本机进程及目录。搬动安装目录后，重新复制配置。

## 按需写入
确认读取成功后，才开启 **允许创建和修改资产**。可让客户端先读当前版本，再追加一小段测试文字；检查 Liteasy 中的实际笔记，确保保留旧内容。

示例：“在 Liteasy 查找‘测试研究笔记’，读取当前完整正文和版本。把下面一句追加到末尾，保留已有内容；版本冲突时停止并说明，不要强行覆盖。”

## 真实能力边界
PDF 原文件、电子书来源和固定快照通常只读；笔记可按能力追加或替换；白板写入需要合法结构和版本核对。具体资产以 `liteasy_stat` 返回的 capabilities 为准，不按文件名字猜写权限。

长文读取可能分页。替换全文前必须读完；使用 `nextOffset` 继续，提交 `expectedRevision`。超时没有回执时，先查实际内容与版本，不能认定“肯定没有写入”。

## 关闭与撤销
本机 MCP 默认关闭，每次启动需重新启用；切换账号会撤销，切回也不自动恢复。关闭、改权限或切换账号后，旧连接失效，需要客户端重新连接。已经提交的修改不会因撤销而自动回滚。

桥接本身不调用模型；客户端是否把读取内容发送到外部模型，由该客户端的配置决定。“本机连接”不等于“资料绝不离开本机”。
