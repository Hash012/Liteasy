保存自己的编辑和必要副本，再用非敏感的小文件验证能否复现。能公开的最小样本比整个私人资料库更适合排错。

## 提交前删除这些信息
API key、Authorization 请求头、访问令牌、同步口令、WebDAV 密码、私有连接文件、Cookie、真实个人信息，以及不应公开的论文或笔记内容。URL 查询参数也可能包含敏感信息，路径可隐去用户名但保留结构。

模型问题保留服务商、协议和模型类型通常有帮助，但不要上传密钥；文件问题保留格式、页数和大小；同步问题保留类别、状态和是否等待重启。日志路径依具体版本而定，不凭空猜测并要求你扫描整个磁盘。

## 通过哪里提交
使用项目维护者指定的反馈渠道，或在允许公开时使用仓库的问题入口。本离线手册的“复制问题模板”只在本机生成文本，不上传反馈、不自动创建 issue，也不收集阅读内容。

## 自愿导出本地诊断
帮助页顶部的“本地诊断”默认关闭。需要排查原位置 PDF／EPUB 打开问题时，可以启用“记录本次窗口的诊断”，离开帮助页重现问题，再返回点击“预览诊断包”。目前只记录选择文件、读取文件、准备阅读器这三个阶段的状态、格式和耗时；错误只保留固定分类码，不收集错误原文、正文、路径、搜索词、聊天、密钥或账号。

预览是固定快照，可逐条删除记录，也可取消“包含应用版本与环境信息”；随后“导出已预览的诊断包”只下载当前预览的 JSON，不上传到任何地址。环境来自当前窗口，无法识别的架构或 WebView 版本显示为 `unknown`。如果下载不可用，可以复制预览文本保存。

记录只在内存中保留最近 100 条；关闭窗口会丢失，切换账号会关闭并清空。关闭后重新启用会开始新会话。“关闭并清空记录”可随时清除。准备阅读器完成不代表首屏已绘制，也不包含全文提取、标注、模型、同步等其他流程；原生事件分发前的错误仍需按复现步骤说明。

## 维护者需要区分的结果
源代码阅读、单元测试、浏览器测试、Windows 安装启动、真实服务联调与生产验收是不同证据。报告清楚自己的环境，能避免把某一层成功误解为全链路成功。
