成熟版 Intent-Native Generative UI 构建地图

最现实的路线是受控声明式 GenUI：模型输出 IntentPlan 和 UI DSL，系统用能力图、Schema、Policy、UX Validator 和事务执行器控制边界。下面按构建顺序展示从 0 到生产级的路径。

1. Registries First

Component Registry 先定义能画什么：Panel、Button、Table、Chart、Form。
Capability Graph 再定义能做什么：布局、数据、文件、任务、集成。
DataSource Registry 动态 UI 只能引用数据源名，不能直连数据库。
Risk Rules 删除、上传、重启、付费、权限变更默认高风险。

2. Intent Runtime

IntentInput 自然语言、GUI、API 都标准化为同一种输入。
Context Builder 给模型脱敏上下文，给策略引擎完整上下文。
Semantic Planner 规则或 LLM 生成 IntentPlan，但不执行。
Plan Validator 校验 capability、参数、依赖和禁止组合。

3. Generative UI Runtime

UI DSL 模型写配置，不写 HTML/CSS/JS。
Virtual UI Tree DSL 被解释成虚拟组件树。
Layout Solver 求解尺寸、区域、响应式和可访问性约束。
Dynamic Canvas 渲染动态界面，但 reset 始终可见。

4. Safety And Quality

Action Router 动态按钮只触发 ActionRef，不能运行任意代码。
Policy Engine 最终裁决 allow、clarify、confirm、deny。
UX Validator 检查遮挡、弹窗、关闭入口、可达性、内容一致性。
Execution Journal 记录输入、计划、DSL、策略、事件和状态差异。
Step 0

列清单：组件、能力、数据源、风险。不要先接模型。

Step 1

定义 DSL 和 Schema：IntentPlan、UIDsl、ActionRef、DataSourceRef。

Step 2

实现 Dynamic Canvas：手写 DSL 能渲染，错误 DSL 会拒绝。

Step 3

实现 Action Router + Policy：所有动作先裁决再执行。

Step 4

接入规则 Planner：不用 LLM 也能跑完整链路。

Step 5

接入 LLM Gateway：结构化输出，失败回退到规则 planner。

Step 6

加入 UX Validator：防遮挡、防坏弹窗、防误导。

Step 7

加入 Streaming UI：先预览计划，再显示骨架，最后逐步挂载组件。

Step 8

建立测试矩阵：golden intent、schema、policy、visual、red team。

Step 9

插件化：插件可注册组件和能力，但永远不能绕过 policy。

生产级原则： Intent is flexible, Plan is structured, UI is declarative, Action is capability-bound, Policy is authoritative, UX is validated, Fallback is permanent.
