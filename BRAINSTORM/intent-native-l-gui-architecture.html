Intent-Native L-GUI Architecture

双内核范式：Intent Runtime 负责理解、计划、权限、执行和审计；Generative UI Runtime 负责 UI DSL、虚拟视图树、组件工厂、布局求解和动态画布。模型提供候选结构，系统拥有最终裁决权。

1. Interaction

Natural Language 用户用目标表达需求，而不是寻找固定按钮路径。
Default UI 稳定兜底界面，模型失败时仍然可用。
Dynamic Canvas 接收受控 UI DSL，渲染动态组件树。
Confirmation UI 高风险计划必须解释后由用户确认。
Audit UI 展示系统理解、计划、风险、动作和状态差异。

2. Intent Runtime

Context Manager 读取当前状态、权限、选择对象和可用能力。
LLM Gateway 兼容 OpenAI、DeepSeek 和本地模型，只负责规划。
Semantic Planner 把自然语言转成 IntentPlan，而不是直接执行。
Plan Validator 校验 schema、能力、参数和步骤依赖。
Capability Graph 系统能做什么、风险如何、需要哪些权限。

3. Generative UI Runtime

UI DSL 模型输出配置，不输出任意 HTML、CSS 或 JS。
Component Cards 告诉模型可用组件、props、children 和限制。
Design Tokens 视觉由语义 token 控制，保持审美一致。
Layout Solver 解决区域、尺寸、响应式和可访问性约束。
Component Factory 把 DSL 节点映射为真实组件实例。

4. Security And State

Action Router 动态按钮只触发 ActionRef，不运行任意代码。
Policy Engine 独立裁决 allow、clarify、confirm 或 deny。
Data Engine 动态 UI 通过数据源名访问数据，不能直连数据库。
Transactional Executor 唯一能改变状态的层，支持失败恢复和审计。
Execution Journal 记录输入、上下文摘要、计划、策略、事件和状态差异。

范式约束： Intent is free, Plan is structured, UI is DSL, Component is registered, Token controls taste, Policy is authoritative, Execution is sandboxed, Audit is mandatory.
