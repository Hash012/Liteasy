# Liteasy 开发进展报告

**日期：2026-05-13 | 当前阶段：Phase 0-1（桌面端核心原型）**

---

## 1. 项目概览

Liteasy 是一款桌面优先的 AI 驱动论文阅读与学习平台。当前处于 Phase 0-1 阶段，已搭建起完整的桌面三栏交互骨架，具备真实的 PDF 渲染、SQLite 持久化存储、批注系统，但 AI 问答和产物生成仍为 mock 数据。

**技术栈：**
- 桌面壳：Tauri 2（Rust 后端 + React 前端）
- 前端：React 18 + TypeScript + Vite
- PDF 渲染：pdfjs-dist 4.x（Canvas + TextLayer）
- 本地数据库：SQLite（rusqlite，bundled 模式，WAL 日志）
- 测试：Vitest + @testing-library/react + jsdom

### 6.3 数据库表（6 张）

```
papers (id, title, file_path, content, page_count, imported_at)
  ├── note_groups (id, paper_id FK→papers CASCADE, name, sort_order, created_at)
  │     └── notes (id, group_id FK→note_groups CASCADE, paper_id FK→papers CASCADE, ...)
  ├── conversations (id, paper_id FK→papers SET NULL, mode, title, created_at)
  │     └── messages (id, conversation_id FK→conversations CASCADE, role, content, ...)
  └── settings (key, value, updated_at)
```

## 9. 已知问题与待改进项

### 9.1 功能缺口

- AI 问答/解释全为 mock，无真实 LLM 集成
- 会话未自动持久化（`persistConversation` 存在但未调用）
- 高亮、阅读进度、产物标签页刷新后丢失
- 页面计数算法简单（扫描 `/Type /Page` 字节），非完整 PDF 解析
- `db_load_conversations` / `db_load_messages` 未被前端使用（无会话历史浏览 UI）

### 9.2 工程缺口

- 无 CI/CD 配置
- 无 React Error Boundary
- 无 loading skeleton，仅有文字加载状态
- 缩放无防抖，每次点击立即重渲染 PDF
- CSS 为单文件 679 行，后续可能需要拆分
- 无端到端测试

### 9.3 架构注意点

- 所有 store 为手写工厂函数 + 可变状态，非 Redux/Zustand
- AppShell 为 537 行的"上帝组件"，承担了过多的状态和事件处理
- 前端对所有 `invoke()` 做了 try/catch 静默降级，方便浏览器开发但可能隐藏错误

## 12. 下一步建议

1. **接通真实 LLM API** — 替换 `mockAnswer()` 和 `mockRetrieve()`，这是当前最大的功能缺口
2. **补全持久化** — 高亮、阅读进度、产物标签页、会话自动保存
3. **会话历史 UI** — 利用已实现的 `db_load_conversations` / `db_load_messages`
4. **拆分 AppShell** — 将状态逻辑按领域拆到各自 store 或自定义 hook 中
5. **添加 E2E 测试** — 使用 Playwright 或 Tauri 测试框架覆盖主链路
6. **CI/CD** — 配置 GitHub Actions 自动构建和测试
