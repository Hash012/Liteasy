## 证据优先级

同一问题优先采用对应的当前 UI／实现代码，配合近期实现记录；较早文档作为历史线索。设计规格表示目标，不能覆盖现状。`archive/` 明确不是当前运行方式依据。[S22–S23]

## 接口兼容审计

`HelpArticle` 只支持 Markdown 正文与摘要，没有平台徽章、资产 URL 解析器和文章间帮助路由。平台条件由 provider 在正文前输出引用块，不向接口强塞额外必填字段。复杂元数据留在新内容模块，旧 UI 不必理解它。

正文不使用 YAML frontmatter、HTML details、脚本、iframe、自定义帮助协议或假定存在的 UI Action 链接。原本 HelpPanel 会输出 h1，因此正文使用 h2 起始。应用命令只在业务调用方通过已有入口执行，内容 provider 不访问文件、网络或执行命令。

AppShell 和助手上下文目录都引用 `builtinHelpProviders`；只在 AppShell 注入第二个 provider 会让助手继续看旧内容，甚至产生重复 `liteasy` ID。故本包替换同一导出内容，而不重复注册。

## 覆盖与有意不覆盖

主体覆盖 Liteasy Desktop 的常见用户任务与已核实集成。Intuecho 管理、SaaS 计费、服务器运维、营销站点和浏览器连接器的完整产品手册不纳入本次桌面包；不能用仓库总 README 的多产品结构冒充这些产品都被测试过。

扩展／工作流篇提供实际能力发现与权限判断，不编造尚未逐项核对的工作流发布界面。备份篇提供已知入口、范围检查与恢复原则，不声称已确认一个覆盖所有外部目录和凭据的万能备份按钮。发布前待拍截图和真实账号／服务验收，均在验证清单中保留。

## 接入范围

替换一个内置 provider 入口；新增内容模块、静态导入表和 48 篇 Markdown；新增 focused tests；精确更新一条过时测试断言。默认不改 HelpPanel、Controller、AppShell、工作流、锁文件、数据格式、账号或网络权限。

可选 CSS 和上下文帮助按钮是独立示例，不会被接入脚本偷偷应用。用户数据迁移、安装器分发、翻译服务和在线反馈后端都不属于本包。
