# 薄读四档支持架构与生成成功边界

状态：权威设计基线

日期：2026-08-11

适用范围：薄读根级总述、遗漏板块下钻、正文选区下钻、外部知识扩展和 AI 独立理解

## 1. 文档定位

本文统一薄读文本生成中的来源支持模式、论文闭包、句级主张、运行状态、修复、模式转换、失败和性能预算。

四档来源支持架构是本文的前提：

1. 仅论文内可追溯证据。
2. 论文内与论文外可追溯证据并用。
3. 仅论文外可追溯证据。
4. 无文献依据的 AI 独立理解。

本文解决的核心问题不是“怎样更容易失败”，而是怎样在不伪造证据、不降低内容质量、不显著增加延迟的前提下，让每个具备基本运行条件的薄读请求尽可能产生有用结果。

当本文与以下文档中的概括性失败规则冲突时，四档支持、生成修复、模式转换和失败边界以本文为准：

- [薄读“很好地完成了”的判定标准](薄读-完成标准.md)
- [薄读外部项目架构对比与技术演进建议](薄读-外部项目架构对比.md)

本文不覆盖上述文档中的论文选择、artifact 边界、文献身份、批注、证据定位、语言和交互要求。

## 2. 目标与非目标

### 2.1 目标

- 在输入、模型和本地文献可用的合格请求中，使技术完成率持续逼近 100%。
- 同时提高句级可追溯性、证据直接支持率、根级方向质量和下钻回答相关性。
- 通过并发、按需规划、有界修复和结果复用控制延迟，不用无限 Agent 循环换取质量。
- 把缺少文献支持转化为明确的来源模式，而不是伪装成有证据内容或粗暴终止整个阅读流。
- 只让不可恢复、会破坏当前任务契约的错误成为真正失败。

### 2.2 非目标

- 不以降低质量门、放宽 evidence ID、跳过句级复核来提高成功率。
- 不以本地模板、fixture、静态摘要或缓存中的其他论文结果冒充本轮成功。
- 不要求每次生成都调用更多模型或更多外部服务。
- 不把 `ai_interpretation` 伪装成论文结论、外部研究结论或 `grounded` 内容。
- 不把推荐候选、社区批注、检索元数据或标题相似度直接当作薄读证据。

## 3. 总原则

薄读采用以下顺序处理问题：

```text
准备可靠输入
  -> 使用当前可获得的最高匹配来源模式生成
  -> 确定性校验与无损修复
  -> 针对失败句定向再生成
  -> 隔离未通过的可选字段或局部句子
  -> 定向换源或复用仍可信的来源
  -> 在任务语义允许时切换到另一正式支持模式
  -> 只有任务契约仍无法满足时才失败
```

失败边界的正式表述为：

> 任何无法满足当前任务语义、四档支持模式契约、结构契约或最低内容完整性的错误必须停止；不影响这些契约的辅助步骤、可选增强和局部内容失败，应在完整审计后修复、隔离或继续。

“成功”只表示本轮生成形成了一个契约完整、通过相应质量门并成功持久化的节点。成功不等于“有论文证据”；来源基础由 `supportMode` 单独表达。

## 4. 六个独立状态轴

以下状态必须分离，禁止互相替代或反向推断。

| 状态轴 | 取值 | 回答的问题 | 不得替代 |
|---|---|---|---|
| 正文节点运行状态 | `queued / running / completed / failed / cancelled` | 薄读正文节点是否完成并持久化 | 来源可信度、附属产物状态 |
| 来源支持模式 | `paper / paper_and_external / external_only / ai_interpretation` | 正文基于哪类来源 | 运行状态、句级强弱 |
| 句级论文支持状态 | `grounded / weak / unsupported` | 单句相对目标论文的支持边界 | 外部来源是否直接支持该句、节点整体来源模式 |
| 论文闭包 | `inside_paper / near_boundary / outside_paper` | 当前讲解是否越出目标论文范围 | 是否生成成功 |
| 外部关系 | `cited_by_target / cites_target / related / topic_search` | 外部文献与目标论文是什么关系 | 外部内容是否直接支持某句话 |
| 附属产物状态 | `not_requested / optional_pending / required_pending / completed / failed / omitted` | 图、anchor、figure 等独立产物是否完成 | 正文节点是否成功 |

关键约束：

- `completed + ai_interpretation` 是合法组合。
- `failed + paper` 不是合法产物；任务失败时不得创建新节点。
- `outside_paper` 不自动等于 `external_only`，也可以是 `paper_and_external` 或 `ai_interpretation`。
- `topic_search` 只描述关系来源，不能单独证明正文命题。
- 自动可视化失败不能自动转化为正文失败。

`grounded` 专指目标论文 evidence 对该句的直接支持；可追溯外部来源直接支持的句子按既有契约可记为 `weak`，但必须另行通过外部命题级 review。这一命名表示“不是由目标论文 grounded”，不表示外部句天然低质量。`unsupported` 只允许出现在明确的 AI 独立理解模式中。

## 5. 四档来源支持模式

### 5.1 `paper`：仅论文内可追溯证据

适用场景：

- 根级总述主要由目标论文建立。
- 论文内部的机制、实验、方法、局限或概念下钻。
- 外部检索不可用，但论文内证据仍足以回答当前问题。

契约：

- 每个内容性句子至少绑定一个本轮允许的论文 evidence ID。
- `externalKnowledge` 为空。
- `grounded` 句必须绑定论文 evidence；不得仅因文本看似正确而标记 grounded。
- 论文 evidence span 至少保存 paper、chunk、page、quote 和 confidence。

这里的“仅论文内证据”不表示穷尽整篇论文的全部证据，只表示当前正文没有使用论文外来源。

### 5.2 `paper_and_external`：论文内与论文外可追溯证据并用

适用场景：

- 根级总述需要用可追溯外部来源说明有证据的领域位置。
- 下钻既解释目标论文内容，又补充后续工作、相关背景或外部对照。
- 同一节点中不同句子分别依赖论文内和论文外来源。

契约：

- 节点至少包含一个论文 evidence ID 和一个外部 source ID。
- 每个句子分别绑定直接支持它的来源，不允许用节点中“存在某来源”替代句级映射。
- 论文内外来源必须在结构中分离。
- 外部句不得仅因外部来源可靠而标记 grounded；只有目标论文 evidence 直接支持的句子才可 grounded。外部句虽按论文支持状态记为 weak，仍必须由绑定的外部来源直接支持并通过同等严格的命题级 review。

### 5.3 `external_only`：仅论文外可追溯证据

适用场景：

- 用户已经越出论文闭包，询问后续研究、相关工作、引用网络或外部背景。
- 目标论文只能提供问题入口，当前正文的实质内容全部来自可追溯外部来源。

契约：

- `paperEvidence` 为空。
- 每个内容性句子至少绑定一个本轮允许的外部 source ID。
- 每个句子的论文支持状态为 weak，但绑定外部 evidence 必须直接支持该句；weak 不能作为放宽外部证据门的理由。
- `withinPaperClosure=false`，闭包状态为 `outside_paper`。
- 外部来源必须保存 provider、canonical/source ID、URL、检索查询、证据基础和关系。
- 只有来源正文、摘要或结构化全文 evidence 直接表达的命题才能进入正文；标题和主题命中不足以支持具体事实。

### 5.4 `ai_interpretation`：无文献依据的 AI 独立理解

`ai_interpretation` 不提供用户直达入口。它只作为外部来源获取或验证耗尽后的恢复模式：当前任务确实需要越出论文闭包，论文内证据不足，并且系统已经执行适用的外部检索与来源验证，最终出现以下任一结果：

- `all_routes_failed`：计划中的外部路线全部调用失败、不可调度或在截止时间内没有返回可用结果。
- `no_trusted_sources`：至少一条外部路线完成，但合并、去重、可信度和可追溯性筛选后没有可信来源。
- `verification_exhausted`：候选来源进入正文生成后不能直接支持对应命题，且一次定向换源仍没有得到可验证来源。

只有用户没有要求仅接受可追溯来源、没有指定不可替代的外部来源，并且没有禁止 AI 独立理解时，系统才可在上述结果后重新生成第四档正文。用户提出“给出你自己的理解”也不能绕过外部检索和来源验证。

这是一种正式支持模式，不是运行失败，也不是本地模板兜底。

契约：

- `paperEvidence=[]`、`externalKnowledge=[]`、`externalSources=[]`。
- 所有句子为 `status=unsupported`、`supportMode=ai_interpretation`。
- 不得携带 source anchors、recommended source figures 或声称来自文献的视觉证据。
- 可以生成明确标注为“AI 概念示意”的 Mermaid、HTML demo 或其他解释性视觉，但只能表达当前 AI 推理中的概念关系、假设或可检验机制，不得伪装成原文图、实验结果、精确经验规律或文献共识。
- 不得出现来源归因、论文归因、命名研究发现、引用标记、来源 URL 或精确经验数据。
- 用可能性、概念推理、假设和可检验方向表达，不冒充事实结论。
- 必须保存 AI 模式进入原因：`all_routes_failed / no_trusted_sources / verification_exhausted`，以及已尝试路线、来源筛选结果和换源结果。
- 必须通过专门的 AI 独立理解审阅；审阅检查来源伪装、事实化表达、精确数据、任务相关性和风险措辞，不用“缺少文献证据”否决本档本身。
- UI 必须持续显示“无文献依据：AI 独立理解”，不能只在首次进入时提示。

### 5.5 节点模式判定

节点模式根据最终保留下来的句级映射判定：

| 论文 evidence | 外部 source | 无来源 AI 正文 | 最终模式 |
|---|---|---|---|
| 有 | 无 | 无 | `paper` |
| 有 | 有 | 无 | `paper_and_external` |
| 无 | 有 | 无 | `external_only` |
| 无 | 无 | 有 | `ai_interpretation` |
| 有 | 任意 | 有 | 非法混合；必须拆分或按单一模式重新生成 |
| 任意 | 有 | 有 | 非法混合；必须拆分或按单一模式重新生成 |
| 无 | 无 | 无 | 不得生成正文；进入失败或输入修复 |

不得先宣称一种模式，再强迫正文迁就该模式。最终模式必须与实际句级来源一致。

## 6. 模式路由、转换与任务语义

四档是来源基础分类，不是从高到低的质量等级。初始路由决定本轮优先获取什么来源，最终模式则由通过审阅后实际保留的句级来源决定。不得把模式转换称为质量“降级”，也不得仅为提高完成率把任务对象换掉。

### 6.1 初始路由

- 与任务语义兼容的显式来源约束优先级最高：“只依据论文”进入 `paper`；“使用选中的外部来源”进入 `external_only` 或 `paper_and_external`。要求“给出你自己的理解”只影响表达意图，不构成第四档的初始路由，也不能覆盖根级论文总述或指定来源解读的对象契约。
- 根级论文总述默认进入 `paper`。只有“领域位置”等确实需要外部材料且用户策略允许时，才并发准备外部来源并形成 `paper_and_external`。
- 论文内选区下钻默认从 `paper` 开始；问题越出论文闭包时才进入混合或外部路线。
- 通用的后续研究、相关工作或外部背景请求优先进入 `external_only` 或 `paper_and_external`；可信外部来源耗尽后，可在任务允许时重新生成 `ai_interpretation`。
- 路由只是检索和生成策略，不预先锁死最终模式。未进入最终正文的候选来源不参与模式判定。

### 6.2 合法的重新判定

- `paper -> paper_and_external`：外部来源增加了任务所需且通过句级审阅的内容。
- `paper_and_external -> paper`：自动补充的外部句未通过或被删除，但论文内正文仍完整回答问题。
- `paper_and_external -> external_only`：当前问题完全越出论文闭包，最终保留正文没有论文内命题。
- `external_only -> paper_and_external`：最终保留正文确实使用了目标论文内容，且每句来源映射成立。
- 外部候选路线（`external_only / paper_and_external`）`-> ai_interpretation`：通用论文外问题出现 `all_routes_failed`、`no_trusted_sources` 或 `verification_exhausted`，且系统清除旧来源、来源化正文和旧模式诊断后，以 AI 契约重新生成并明确披露。

第四档只在外部检索与验证已经形成耗尽决议后启动。同一请求开始生成 AI 正文后，不再反向改判为 `external_only` 或 `paper_and_external`；截止时间后到达的来源只可进入缓存，供新的用户请求使用，不能静默改写本轮节点。

### 6.3 禁止的转换

- 任意薄读请求在目标论文没有可用本地文本索引时转为外部模式或 AI 理解。
- 用户显式选中某个外部来源后，该来源复核失败却转为 AI 理解。
- 用户明确要求“只依据论文”“只依据已验证文献”时转为 AI 理解。
- 把推荐候选、社区批注或标题命中转成 `external_only` 证据。
- 把上一层 evidence ID 当成下一层新 evidence ID。
- 为了提高成功率把 unsupported 句改标 weak 或 grounded。

### 6.4 显式来源与通用问题

“继续了解后续研究”是通用外部问题，可以在检索耗尽后进入 AI 理解。

“继续解读用户选中的论文 B”以论文 B 为任务对象。论文 B 的来源不可用或不能支持当前命题时必须停止该分支，不能用另一来源或 AI 猜测替代，除非用户重新选择任务。

“请给出你自己的理解”在薄读中只表达用户希望获得独立分析，不构成第四档直达条件。若问题属于论文内事实，仍按论文证据路线处理；若问题越出论文闭包，仍须先执行外部检索与来源验证，只有形成合法耗尽原因后才可进入 AI 理解。

## 7. 统一生成流水线

### 7.1 `prepare_context`

- 固定目标论文、artifact、父节点、选区、深度、语言和显式输出请求。
- 根级优先使用当前阅读区中已打开且被选中的论文；否则使用选中列表第一篇。
- 所有薄读请求，无论最终进入 `paper`、`paper_and_external`、`external_only` 还是 `ai_interpretation`，都必须校验目标论文已导入并存在可用本地文本索引。
- 本地文本索引是恢复目标论文、父节点、选区、论文闭包和检索问题的任务作用域前提；缺失时不得通过切换来源模式继续。
- 在 `external_only` 和 `ai_interpretation` 中，本地索引只能用于精确恢复任务作用域和构造检索或解释问题，不能写入 `paperEvidence`、绑定为正文 evidence、支持论文归因或据此把句子标记为 grounded。
- 下钻继承父节点 summary、claims、evidence spans、闭包状态和祖先路径。
- 上下文压缩只能裁剪次要历史，不得删除当前选区、用户提示、显式来源和必要父层证据。

### 7.2 `plan_interpretation`

- 根级固定为 `orientation`：核心思想、论文全景和有证据的领域位置。
- 下钻固定为 `exploration`：回答用户选区，并承接、细化、修正或补足父层认识。
- 判断 what、why、how、mixed 和请求深度。
- 规划结果决定讲解顺序和外部知识需求，但不能绕过证据门。

### 7.3 `prepare_evidence`

`prepare_evidence` 为可能进入前三档的候选路线准备论文 evidence。外部检索或验证耗尽并获准进入第四档后，AI 正文重生成阶段不再运行论文 evidence planner/observer，只保留由本地索引精确恢复的任务作用域和 AI 模式禁用项，并从正文 evidence 输入与输出中清除论文 evidence。

小证据集直接进入正文生成，避免为简单任务增加两次串行模型调用。

大证据集使用有界循环：

1. planner 只读取轻量证据目录并提出 read/search/view 请求。
2. 确定性工具只在本轮 evidence 白名单内执行。
3. observer 检查首轮证据是否足够。
4. observer 只能停止或请求一轮补充。
5. 两轮合计证据数量受固定上限约束。

planner 是证据选择优化器，不是最终事实裁判。最终正文仍必须通过句级 evidence 白名单、结构门和语义复核。

### 7.4 `retrieve_external`

- 第四档没有跳过本阶段的用户入口；任何可能在外部来源耗尽后进入 `ai_interpretation` 的通用论文外问题，都必须先形成可审计的外部检索与来源验证结果。
- support、challenge、context 路线并发执行。
- 使用 `Promise.allSettled` 语义：单路失败不阻止其他可信来源。
- 外部请求应与本地规划并行启动，只在构造最终 prompt 前汇合。
- 汇合受固定截止时间和最小证据充分条件控制：已有来源覆盖任务所需命题时可以提前进入生成；其余路线取消或仅进入缓存，不得在落盘后静默改写节点。
- 截止时间内没有可信来源时，按实际结果记录 `all_routes_failed` 或 `no_trusted_sources`，并立即执行合法的 AI 模式转换或失败判定，不等待无界 provider 尾延迟。
- 对需要方法、实验、局限或深度解释的来源优先获取受控全文；没有全文时只允许摘要直接支持的有限表述。
- 合并来源时保留 provider record、canonical ID、关系和检索意图，不用模型猜测关系。

### 7.5 `generate_node`

- 正文模型只接收实际选中的本轮 evidence 和允许的外部来源。
- 输出严格结构化 JSON，不从自由 Markdown 猜结构。
- summary、summarySentences、claims、anchors、omittedSections 和可选视觉意图分别建模。
- 首次生成可流式展示，但流式草稿不得在质量门前保存为正式节点。

### 7.6 `validate_and_review`

按以下顺序执行：

1. JSON Schema 与 Zod 结构校验。
2. summary 单段、目标语言和关键术语校验。
3. evidence/source 完整 ID 白名单校验。
4. summary 句级 100% 覆盖校验。
5. claim、句子和来源模式一致性校验。
6. 数字、范围、单位和限定词保真校验；具体证明模型、等价规则、局部修复和失败边界以 [薄读数值与定量命题保真门](薄读-数值与定量命题保真门.md) 为准。
7. 外部 citation relation 保真校验。
8. 图表和视觉 evidence 边界校验。
9. 前三档执行命题级 evidence review；第四档执行 AI 独立理解 review，二者互斥。
10. 根级方向或下钻回答完整性校验。

薄读已经有专用句级复核时，不再串行调用不参与放行的通用远端答案审计。

### 7.7 `persist_node`

- 只有正文、模式和审计全部通过后才构造节点。
- 节点和 artifact 更新必须原子持久化。
- branch 失败保留父节点和既有文档，不创建半成品 child。
- 保存失败属于本轮失败，不能在 UI 中宣称已完成。

## 8. 修复与成功优先策略

### 8.1 修复顺序

按成本和风险从低到高执行：

1. 无损确定性规范化。
2. 删除或修复非正文可选字段。
3. 只改失败句的模型定向修复。
4. 删除复核仍失败的句子，保留逐字不变的通过句。
5. 外部来源定向换源。
6. 合法切换四档支持模式。
7. 任务契约仍无法满足时失败。

不得每次失败都重写整篇正文。已经通过的句子、ID 和来源映射应被冻结，以降低回归和延迟。

### 8.2 正文修复预算

- 结构规范化、可选字段删除、planner/observer fallback、外部换源和视觉修复分别计数，不得共用一个“总重试次数”。
- 不调用模型的确定性修复不消耗正文模型修复预算。
- planner 或 observer 失败不消耗正文修复预算；正文尚未生成时尤其不能把规划失败记成一次正文失败。
- 外部换源只消耗来源恢复预算；只有重新生成失败句时才消耗对应正文定向修复预算。
- 附属视觉使用独立预算，不得耗尽正文预算，也不得触发整篇正文重写。
- 普通根级：首次生成后允许一次一般修复。
- 根级第二轮若只剩明确的句级证据问题，可额外执行一次严格定向修复。
- 根级第三次不得改变已通过句、任务方向或来源白名单。
- 普通下钻：首次生成后允许一次正文修复。
- AI 理解：首次生成后允许一次安全表达修复，并重新审阅。
- 每个修复后的正文都必须重新通过对应 reviewer。

这不是无界重试。额外预算只用于已经定位且可修复的问题，不用于期待模型随机变好。

### 8.3 句子隔离

正文在修复预算耗尽后，可以确定性删除 reviewer 判定为 partial、contradicted 或 insufficient 的句子，条件是：

- 保留句在原 reviewer 中均为 supported。
- 保留句文本和映射不被改写。
- 至少剩余一个有信息量的内容句。
- 剩余正文仍直接回答选区或补充提示。
- 删除记录、sentence ID 和原因进入 audit。

根级使用同一机制，但删除后仍必须覆盖核心思想、论文全景和有证据的领域位置中的适用部分；不能通过删除关键方向换取形式成功。AI 理解可隔离违反本档安全表达契约的句子，但剩余内容仍须形成实质性的独立理解。

若删除后只剩背景、过渡或无关内容，则本轮失败，不能用空洞正文提高成功率。

### 8.4 外部来源恢复

- 自动加入的无支持外部句可以删除；删除后重新核验剩余正文。
- 必需外部来源失败时，允许一次针对失败命题的定向换源。
- 有部分可信来源存活时保留它们，不因另一条路线失败而丢弃全部来源。
- 候选来源已经进入正文但命题级复核失败，且一次定向换源仍不能取得直接支持时，记录 `verification_exhausted`；通用外部问题可以据此重新生成 AI 理解。
- 显式选择的外部来源不得被静默替换。

### 8.5 可选增强隔离

以下内容默认不应拖垮已经合格的正文：

- anchor 搜索和外部锚点补充。
- 自动推荐的 source figure。
- 自动 visualization intent。
- 关系梳理和视觉编辑 Subagent 私有 brief。
- 自动生成但无法修复的非必需视觉产物。

处理方式：先局部修复；仍失败则删除对应可选字段并记录 audit。用户通过快捷命令明确要求 Mermaid、HTML demo 或指定可视化时，可视化子任务必须单独给出成功或失败，不能把纯正文冒充可视化成功；但可视化失败也不能反向删除或否决已经通过质量门的薄读正文节点。

## 9. 可恢复降级，不应失败

### 9.1 Planner 不可用

允许继续的情况：

- 429、超时或 500/502/503/504 等瞬时服务错误。
- provider 支持正文结构化生成，但暂不支持 planner 的小型结构化调用。
- planner 输出格式修复仍失败，但本地 evidence 矩阵完整、排序稳定且最终正文 reviewer 可用。
- planner 返回的 `focus`、`pageRequests`、`searchQueries` 或 `selectedEvidenceIds` 仅超过数量预算，但数组元素仍可校验；这属于可恢复的结构偏差，不是任务契约失败。

降级方式：

- 对可恢复数组先执行无模型的确定性规范化：字符串去除首尾空白、按规范化值去重、保留原顺序，再截断到 schema 上限；页码按原值去重并保序截断。该处理不得新增内容、重排优先级或绕过 evidence ID 白名单。
- 数组规范化后已经满足 schema 时直接采用，不再增加一次模型调用。`selectedEvidenceIds` 中仍有非本轮 ID、核心字段类型错误、缺少必需选择或存在其他不可无损修复的问题时，才允许一次 planner 格式修复。
- 一次格式修复后仍不可校验时，放弃模型规划并进入确定性 evidence fallback；不得继续重试 planner，也不得将该错误提升为 `artifact_generation_failed`。
- 使用确定性、数量有界的已排序 evidence 范围。
- 不把整份大 evidence 矩阵塞入 prompt。
- audit 写入 `planningMode=deterministic_fallback`、错误类别、采用 ID 和截断数量。

不得继续的情况：

- 用户取消。
- 本地 evidence 数据违反结构不变量。
- 未分类的编程错误。

planner 专用路由的认证、账号会话、provider 或 endpoint 配置错误不得伪装成瞬时错误；如果主正文路由已独立验证可用，且有界确定性规划足以维持证据契约，可以记录明确配置错误后继续正文。若错误影响共享认证、主正文路由或所有已授权兼容路由，则必须停止。

### 9.2 Observer 不可用

首轮 planner 和工具观察已经成功时，observer 瞬时不可用可以使用第一轮实际 evidence 继续，audit 必须记录：

```text
stopReason=observer_unavailable
rounds=[first_round]
fallback=deterministic_first_round
```

不能把 observer 缺失伪装成 `observation_sufficient`。如果第一轮没有任何实际 evidence，必须使用有界确定性 evidence 或停止，不得生成无来源的前三档正文。

### 9.3 可选 Subagent 不可用

关系、视觉等责任 Subagent 只提供不可信候选 brief。其失败不影响主 Agent 使用原 evidence 工作，应记录未完成但继续。Subagent 错误文本不得作为学术内容或用户正文进入最终 prompt。

### 9.4 部分外部路线失败

只要至少存在一个通过来源门且能直接支持正文的来源，就使用可信结果继续。失败路线、完成路线和复用状态进入审计；不得因为 route 数量减少而降低来源校验标准。

## 10. 正文节点真正失败条件

只有以下情况应使本轮薄读正文节点生成失败。附属视觉、anchor 和 figure 按独立产物状态判定，除非请求本身只包含该子任务，否则不反向改变正文节点状态。

### 10.1 输入与作用域不可成立

- 没有目标论文。
- 目标论文未导入或任意薄读请求没有可用本地文本索引。
- artifact、父节点、选区、文档版本或恢复快照无法按原语义精确重建；仅缓存过期或可无歧义重新定位时应先恢复，不应失败。
- 显式选择的外部来源无法按 canonical identity 重新验证、不可访问或与当前任务不一致；仅 URL 更新但身份和内容可验证时应恢复。

### 10.2 用户或运行环境终止

- 用户取消。
- 应用退出或重启后，可信检查点和原请求作用域都无法恢复；可恢复时应从最后可信阶段重新发起真实模型请求。
- 所有用户已授权、能力兼容且满足隐私与费用策略的模型路由均不可用。单一路由失败时可切换到已配置兼容路由，但不得静默启用未授权 provider。
- 主正文模型在有界传输重试和合法路由切换后仍不可用。

### 10.3 正文契约无法恢复

- 结构化输出在修复预算耗尽后仍不可解析。
- summary 与 summarySentences 无法形成 100% 映射。
- evidence/source ID 越出白名单且修复失败。
- 数字、来源关系、图表断言或术语在修复、保守改写或句子隔离后仍不合格，并且删除它们会使正文无法回答任务。
- 句子隔离后没有有信息量且回答当前任务的正文。
- 根级总述无法覆盖最低方向要求。
- 下钻结果无法回答选区、层级和补充提示。

### 10.4 模式契约无法成立

- 前三档存在无来源内容句。
- AI 理解的 evidence/source 字段非空、正文声称由论文或外部来源支持，或伪装成事实归因。
- AI 理解在一次定向修复和一次确定性禁用项清理后仍违反模式契约，或清理后不再形成实质答案。
- 用户要求仅使用可追溯来源，但没有任何来源能够支持当前命题。
- 显式来源失败后没有得到用户授权，却试图切换来源或 AI 模式。

### 10.5 持久化与独立子任务失败

- 正式节点无法原子保存。
- 保存后的文档版本、parent/child 或 active node 不一致。
- 用户明确请求的视觉产物在修复预算后仍缺失或无效，只使该视觉子任务失败；已经合格并成功保存的薄读正文节点仍是成功节点。若请求本身只有视觉命令，则本次命令失败，但不得破坏既有节点。

失败时保留旧文档和旧节点，显示稳定错误类别、失败阶段和可执行恢复建议。不得保存失败正文或回退为模板。

## 11. 性能与调用预算

### 11.1 关键路径

| 工作负载 | 正常关键路径 | 条件性调用 |
|---|---|---|
| 小型论文内任务 | 正文生成 -> 证据复核 | 一次正文修复 |
| 大型论文内任务 | planner -> 首轮工具 -> observer -> 正文生成 -> 证据复核 | 一轮补充工具、有限责任 Subagent、定向修复 |
| 外部扩展任务 | 本地规划与多条外部路线并发 -> 正文生成 -> 证据复核 | 全文补证、一次换源、AI 模式重生成 |
| AI 恢复路径 | 外部检索或验证耗尽 -> AI 正文 -> AI 独立理解审阅 | 一次安全表达修复、一次确定性禁用项清理 |

### 11.2 性能规则

- 少于规划阈值的 evidence 不调用 planner/observer。
- AI 正文重生成阶段不重复调用 evidence planner、observer 或外部检索；这些阶段已经形成可审计的耗尽决议。
- 外部检索、本地规划和可选 Subagent 尽可能并发。
- 外部多路线并发，单路失败不串行等待重跑所有路线。
- 外部汇合使用有界截止时间和证据充分提前结束，不等待最慢 route 才开始正文生成。
- 只有定向修复才能增加正文调用；不得使用无界 `loop until good`。
- 已通过句冻结，修复 prompt 只携带失败句和直接相关 evidence。
- 已验证的外部检索结果和完成节点可以按 artifact、查询策略和来源 revision 安全复用。
- 专用薄读 reviewer 已参与放行时，不重复调用通用远端审计。
- 进度事件应在本地立即出现，首轮正文允许流式展示，但不提前落盘。

### 11.3 延迟门禁

对同一 provider、论文集合和工作负载：

- 新设计不得仅为增加 Agent 数量而增加正常路径串行调用。
- P50 不应高于现有基线。
- P95 增幅超过 10% 时，必须有可重复的 `paperGroundedness`、`externalDirectSupportRate`、citation precision、root orientation 或 branch relevance 改进证据。
- 修复路径延迟单独统计，不能混入正常路径掩盖回归。
- 外部 provider 延迟、正文模型延迟和本地持久化延迟分别记录。

## 12. 成功率与质量指标

“无限接近 100%”指合格请求的技术完成目标，不代表可以隐藏输入错误、取消、服务中断或质量失败。

必须同时报告：

| 指标 | 含义 |
|---|---|
| `rawCompletionRate` | 全部请求中成功持久化节点的比例 |
| `eligibleCompletionRate` | 排除用户取消、无目标论文或无可用本地文本索引等不可执行输入后的完成率 |
| `traceableCompletionRate` | 前三档可追溯节点的完成率 |
| `aiInterpretationRate` | 第四档节点比例，防止靠大量转入 AI 模式虚增成功率 |
| `modeCompletionRate` | 按最终 `supportMode` 统计各档成功节点占合格请求的比例；第四档只能来自外部恢复路径 |
| `modeReclassificationRate` | 初始路由与最终模式不同的比例及原因 |
| `firstPassRate` | 无正文修复即可通过的比例 |
| `repairSuccessRate` | 定向修复后成功的比例 |
| `sentenceQuarantineRate` | 依靠删句完成的比例及删除句数 |
| `plannerFallbackRate` | planner/observer 降级比例 |
| `paperGroundedness` | 论文内句是否由绑定目标论文 evidence 直接支持 |
| `externalDirectSupportRate` | 外部句是否由绑定外部 evidence 直接支持；不得由 weak 标签代替 |
| `citationPrecision/Recall` | 句级来源准确性和覆盖 |
| `rootOrientationCoverage` | 核心思想、论文全景和领域位置质量 |
| `branchRelevance` | 下钻是否回答选区和提示 |
| `P50/P95 latency` | 正常、修复、外部和 AI 路径分别统计 |

不得只报告总完成率。若总完成率上升但 traceableCompletionRate、paperGroundedness、externalDirectSupportRate 或 branch relevance 下降，则优化失败。

## 13. 审计契约

每个成功节点至少记录：

- 最终 `supportMode` 及判定依据。
- interpretation plan 和阅读模式。
- planner 是否启用、失败或降级。
- evidence tool rounds、实际返回 ID 和停止原因。
- 外部 attempted/completed routes、可信来源数和 fallback reason。
- 进入 `ai_interpretation` 时记录 `all_routes_failed / no_trusted_sources / verification_exhausted` 之一及其判定输入。
- 模型/provider、workload、上下文压缩摘要和调用耗时。
- 每次正文修复的类型、失败句和是否隔离。
- 被删除的句子、anchor、figure 或视觉字段及原因。
- evidence review 或 AI interpretation review 结果。
- 最终质量门尝试次数。

审计不得保存 API key、完整 prompt、未脱敏外部全文、用户隐私画像或模型原始长输出。

## 14. UI 表达

四档使用稳定标签：

- `paper`：论文内支持。
- `paper_and_external`：论文 + 外部支持。
- `external_only`：仅外部支持。
- `ai_interpretation`：AI 独立理解。

UI 规则：

- 标签表示来源类型，不写成“高/中/低质量”。
- AI 理解显示持久警示和无来源说明。
- 外部模式显示论文闭包外状态，但不在正文中暴露 provider、source ID 或检索过程。
- 修复、删句和 planner fallback 属于审计信息，不作为常驻正文文案。
- 失败时保留当前已读节点，明确本轮 branch 未创建。
- 用户可从失败态重新提交；应用重启后的重新提交必须产生新模型请求。

## 15. 验收矩阵

### 15.1 四档模式

- 论文内根级总述生成 `paper`，每句有论文 evidence。
- 根级或下钻混合来源生成 `paper_and_external`，句级来源各自正确。
- 闭包外且只有可信外部来源时生成 `external_only`。
- 外部检索耗尽且任务允许时生成 `ai_interpretation`，证据字段为空并显示警示。
- 用户要求“给出你自己的理解”时仍先执行外部检索；有可信来源时进入相应外部档，只有检索或验证耗尽后才进入 `ai_interpretation`。
- 四种节点都可以是 `completed`，但数据和 UI 不能混淆。

### 15.2 高成功率恢复

- planner 返回 502 时使用有界确定性 evidence，记录 fallback audit，正文仍需通过 reviewer。
- observer 超时时保留第一轮 evidence，记录 `observer_unavailable`。
- 一个外部 route 失败、另一个成功时使用成功来源。
- 一个自动外部句失败时删除该句并重新复核。
- 必需外部句失败时完成一次定向换源。
- 下钻部分句子失败时隔离失败句，并验证剩余正文仍回答选区。
- anchor 或自动视觉失败时正文仍可成功。

### 15.3 必须失败

- 无目标论文，或无可用本地文本索引的任意薄读请求。
- 所有已授权兼容模型路由的认证或调用均失败。
- 用户取消。
- 结构和证据映射在预算耗尽后仍无效。
- 显式选择来源无法支持内容，却试图切换 AI。
- AI 理解经过定向修复和禁用项清理后仍违反模式契约或没有实质答案。
- 删句后没有实质答案。
- 节点保存失败。

显式请求的视觉产物缺失只判定对应视觉子任务失败，不得把已经合格的正文节点改成失败。

### 15.4 性能

- 小任务不出现 planner/observer 调用。
- 多条外部检索并发。
- AI 恢复路径复用已经形成的外部耗尽决议，不重复运行 evidence planner、observer 或外部检索。
- 正常路径不执行通用远端重复审计。
- 修复只发送失败范围，不重写已通过句。
- CI 记录调用数和确定性结构门；真实模型 benchmark 记录质量、成功率、P50/P95 和成本。

## 16. 禁止的反模式

- 为避免幻觉，把任何辅助错误都变成整轮失败。
- 为提高成功率，跳过 evidence review 或把 unsupported 改标 weak。
- 外部来源为空时生成 `external_only`。
- AI 理解携带伪造 citation 或论文归因。
- 因用户要求“自己的理解”而跳过外部检索，直接生成 `ai_interpretation`。
- 在目标论文没有可用本地文本索引时继续外部或 AI 下钻。
- planner 失败后把全部 evidence 无界塞入 prompt。
- observer 失败却审计为“证据充分”。
- 一条外部 route 失败就丢弃其他可信 route。
- 一个 anchor、figure 或自动视觉失败就丢弃合格正文。
- 显式视觉子任务失败后回滚或删除已经合格的正文节点。
- 每轮修复重写全部内容，导致已通过句回归。
- 用第三次自由生成替代句级定向修复。
- 把任务成功率与 traceableCompletionRate 混为一个数字。
- 把 AI 模式比例上升解释为证据质量上升。

## 17. 最终判定

一次薄读生成可以成功，当且仅当：

1. 目标论文及其本地文本索引可用，其他输入作用域有效。
2. 形成四档之一的合法来源支持模式。
3. 正文结构、句级映射和该模式的质量门通过。
4. 本轮任务语义仍被回答。
5. 节点与审计原子持久化成功。

系统应主动修复局部问题、保留可靠内容、并行获取来源并合法切换支持模式。只有无法形成任何合法模式、无法回答当前任务或无法保存结果时才失败。这样才能同时获得接近 100% 的合格请求完成率、更高的内容质量和受控的生成速度。
