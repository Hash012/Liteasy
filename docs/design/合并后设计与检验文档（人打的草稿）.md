## 文件系统
1. UI 效果：
类似VScode的打开文件的效果，根据本地和云端对应的文件夹的目录结构来折叠、展开、插入、移除。清除mock的部分，只做真实的储存系统。

2. 组成结构：
本项目涉及到的文件整体分为4类：一类是部署在服务器上的程序文件以及供软件完成各种功能的用户信息等数据、一类是打包成exe文件分发给用户的软件端、一类是exe运行后在用户本地创建的用于储存本地文献库的本地文件夹、一类是服务器上分给用户来缓存（包括收藏（永久）、检索缓存、推荐缓存）以及组织来储存的文件夹。
为理解这些点，需要明白本项目的投入使用时的状态：项目主体是Liteasy软件，是一款Saas软件，用户需登录自己的账号，文件存在本地系统，其他服务由服务器来根据账号身份完成、派发；用户可以访问Intuecho论坛，是一款web应用，论坛账号和软件账号一致，且可以互通；管理员有进行测试软件的专用账号，该账号登录后可以看到调试与报错信息，普通用户账号登录后不暴露不必要的过程信息，另外有web网页供管理员管理账号、分配用户限额、组织限额、配置需要管理员配置的api和可供agent检索的网站、数据库、管理论坛中的帖子（即软件和论坛一起管理）。

3. 身份和文件系统：
服务器端的数据文件和用户账号关联，用户本地的软件端的数据文件不和用户关联，每个用户登录都会拥有自己的本地文件。个性化推荐相关的数据和用户身份以及他所拥的文献有关联。

4. 开发人员视角下的文件夹要求：
结构清晰，易于阅读和部署
