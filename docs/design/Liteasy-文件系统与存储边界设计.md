# Liteasy 文件系统与存储边界设计

状态：已确认，作为文件系统、云端存储、身份边界和相关 UI 改造的目标设计  
确认日期：2026-08-06  
适用范围：LiteasyClaw 桌面端、Liteasy 云服务、Intuecho 身份互通、管理后台

## 1. 文档目的

本文定义 Liteasy 投入使用后的文件与数据边界，解决以下问题：

- 桌面端只展示和操作真实的本地或云端文献资源，不再依赖示例目录、演示账号或 mock provider。
- 本地文献库与 SaaS 账号解耦，同一操作系统用户切换 Liteasy 账号时仍看到同一个本地库。
- 收藏、推荐、组织库分别展示，跨区域拖拽表示复制，不隐式删除来源。
- 云端目录是数据库中的逻辑树，PDF 正文进入对象存储，不为每个用户创建物理服务器目录。
- 本地和云端删除统一进入可恢复的回收站。
- 个性化推荐可以使用账号及其当前可见本地文献的元数据，但用户可以关闭并彻底清除相关云端数据。
- Liteasy、Intuecho 和管理后台共享身份源，同时保持会话受众、权限和业务数据隔离。
- 开发测试保留测试替身，但生产及日常开发运行路径不再提供虚假业务结果。

本文是目标态设计，不表示当前代码已经满足这些要求。实施必须按第 16 节迁移，不得通过覆盖现有用户工作区改动来达成。

## 2. 已确认的核心决策

1. 同一操作系统用户下，本地文献库不随 Liteasy 登录账号变化。A 账号退出并登录 B 账号后，看到同一个本地库。
2. 第一版只支持一个当前启用的本地库根目录。用户可以更换根目录，但同一时刻不组合多个根目录。
3. 左侧资源区域由本地文献库、收藏、关联推荐、组织文献库四个独立区域组成。
4. 区域内部支持移动；不同区域之间的拖拽一律是复制。
5. 收藏和组织库能获得 PDF 时保存正文，否则保存可检索、可引用的元数据条目。
6. Liteasy 中的删除操作进入回收站，本地和云端默认保留 30 天。
7. 第一阶段只展示和导入 PDF 文献资源。Zotero 的后续元数据格式兼容写入路线图，但不属于第一阶段交付。
8. 个性化可以使用本地文献的必要元数据；关闭后停止采集和使用，清除后删除相关云端数据。
9. 云端使用 `scope_type + scope_id + folder_id` 表达归属和目录层级，PDF 使用内容寻址对象存储。
10. 平台管理员、开发诊断权限和组织管理员是三套不同权限，不能通过硬编码特殊账号实现。
11. 生产及日常开发运行路径移除 mock provider、演示账号、fixture 文献和假数据回退；自动化测试中的受控替身继续保留。

## 3. 四类文件与数据边界

| 类别 | 位置 | 归属 | 真源 | 备份责任 |
| --- | --- | --- | --- | --- |
| 服务部署文件 | 服务器只读发布目录或容器镜像 | 平台 | 构建产物与版本仓库 | 重新构建和重新部署 |
| Liteasy 桌面端 | 用户电脑的安装目录 | 安装实例 | 签名安装包 | 重新下载安装 |
| 本地文献库 | 当前操作系统用户选择的本地目录 | 设备上的操作系统用户，不属于 SaaS 账号 | 本地文件系统及库内伴生数据 | 用户负责；产品应提供导出和备份提示 |
| 云端业务数据 | 事务数据库、对象存储、缓存服务 | 用户、组织或平台 | 数据库中的逻辑记录及对象存储 | 平台负责分层备份和恢复演练 |

必须遵守以下物理隔离：

- 服务部署文件不得与数据库文件、上传 PDF、日志、密钥或备份位于同一个可变发布目录。
- 服务进程只获得完成职责所需的目录、数据库和对象存储权限。
- `.env.local`、生产密钥和对象存储凭据不得进入安装包、仓库或前端响应。
- 开发环境可以使用 SQLite 和本地对象目录模拟生产基础设施，但必须遵守相同的逻辑归属和权限校验。
- 生产环境使用事务数据库和独立对象存储。文档不把具体云厂商写死，目标能力应兼容 PostgreSQL 与 S3 API。

### 3.1 云端对象与用户归属的关系

PDF 字节可以按 SHA-256 去重，因此对象本身不直接声明“属于某个用户”。用户和组织拥有的是指向对象的受权逻辑条目：

```text
用户或组织作用域
  -> 目录节点
    -> 文献条目
      -> 可选的内容对象引用
        -> 对象存储中的 PDF 字节
```

即使两个作用域引用相同内容哈希，服务端也必须先校验调用者对文献条目的权限，不能凭内容哈希直接下载对象。

## 4. 总体架构

```text
                    统一身份服务
                 /       |        \
          Liteasy 桌面端  Intuecho  管理后台
                 |        |        |
                 +--------+--------+
                          |
                  业务 API 与授权层
                    /            \
             事务数据库          对象存储
        用户、组织、目录、权限     PDF、可再生大对象
                    
Liteasy 桌面端
  |
  +-- 本地库适配器 -> 本地真实目录、文件监听、库内回收站
  |
  +-- 云端客户端 -> 收藏、推荐、组织库、个性化和账号服务
```

依赖方向继续遵循仓库约束：

```text
layout -> controllers -> features -> shared types / clients
```

- `AppShell` 只组合各区域，不承载跨区域复制、权限判定或文件事务。
- 本地文件操作由 library feature 调用 Tauri 命令完成。
- 跨区域拖拽由 controller 编排源读取、目标授权、复制提交和 UI 刷新。
- 云端权限由服务端最终判定，前端禁用按钮只能改善体验，不能替代授权。

## 5. 本地文献库

### 5.1 身份与根目录

本地库根目录属于当前操作系统用户，不接受 `accountKey` 作为目录选择、占用或读取条件。

根目录指针存放于 Tauri 的操作系统用户级应用数据目录，例如：

```text
app_data/local-library/library-root.json
```

根目录内使用不含账号信息的库标记：

```json
{
  "libraryId": "lib_01...",
  "schemaVersion": 1
}
```

该标记文件命名为 `.liteasy-library.json`。它用于识别库和迁移版本，不用于阻止另一个 Liteasy SaaS 账号打开目录。

旧的按账号根目录设置和 `.liteasy-library-profile` 必须迁移，不能继续作为运行时授权依据。

### 5.2 推荐目录结构

```text
<library-root>/
  .liteasy-library.json
  .liteasy/
    index/
    metadata-entries/
    paper-artifacts/
    trash/
  研究方向 A/
    paper-a.pdf
  课程资料/
    paper-b.pdf
  paper-c.pdf
```

- 用户目录和 PDF 位于根目录的正常可见层级，UI 按真实相对路径展示。
- `.liteasy/` 是 Liteasy 管理的隐藏目录，不显示在资源树中，也不能被当作文献目录拖拽。
- `index/` 是可重建索引，不能成为判断 PDF 是否存在的唯一真源。
- `metadata-entries/` 保存没有 PDF 正文的本地条目；UI 将它们显示在只读虚拟组“仅元数据”中。
- `paper-artifacts/` 保存批注、锚点、全文解析、阅读状态等与文献身份关联的数据。
- `trash/` 保存由 Liteasy 删除且仍可恢复的本地资源。

现有 `papers/` 和 `paper-artifacts/` 结构通过迁移兼容，不要求用户手工移动。最终 UI 不把系统管理目录暴露为普通文献目录。

### 5.3 文献身份

以下标识必须分离：

| 标识 | 含义 | 稳定性 |
| --- | --- | --- |
| `libraryId` | 一个本地库 | 更换路径后不变 |
| `documentId` | 一个逻辑文献副本 | 重命名、移动、进出回收站后不变 |
| `contentHash` | PDF 字节的 SHA-256 | 字节变化时变化 |

两个字节完全相同的本地 PDF 可以是两个独立逻辑副本，拥有不同 `documentId` 和独立批注。上传云端时，两者可以复用同一个内容对象。

绝对本地路径不得上传到个性化服务、审计日志或普通错误响应。

### 5.4 支持的资源与第一阶段限制

第一阶段：

- 展示 `.pdf` 文件，扩展名匹配不区分大小写。
- 导入前同时校验 PDF 文件头、大小和可读性，不能只信任扩展名。
- 沿用当前单文件 256 MB 上限，后续允许通过平台配置调整。
- 支持没有正文的元数据条目，但不伪装成可打开的 PDF。
- 不展示任意办公文件、压缩包、图片或源码文件。

符号链接、Windows junction 和其他可能跳出根目录或形成循环的重解析点默认不跟随。若未来开放，必须先增加明确的信任和循环检测策略。

### 5.5 文件监听

桌面宿主负责监听根目录，React 不直接轮询磁盘。

监听要求：

- 监听创建、修改、重命名、移动和删除事件。
- 对短时间批量事件去抖并合并，避免一个复制动作触发大量 UI 重绘。
- 优先增量重扫受影响路径；监听溢出、恢复运行或索引版本不一致时执行全量校验。
- Liteasy 自己完成操作后，通过操作 ID 去重监听回声，但仍以最终磁盘状态校验结果为准。
- Windows 大小写不敏感的同名冲突按目标文件系统规则处理。
- 外部程序直接删除文件时，UI 应移除条目并提示“文件已在系统外删除”；这种删除不承诺进入 Liteasy 回收站。
- 监听错误不显示内部堆栈，向普通用户提供可重试状态和 `traceId`。

### 5.6 本地操作语义

| 操作 | 结果 |
| --- | --- |
| 新建目录 | 在当前目录创建真实文件夹 |
| 导入 PDF | 写入目标目录，校验完成后建立或更新索引 |
| 重命名 | 原子重命名文件或目录，保留 `documentId` |
| 移动 | 在库内移动真实资源，保留 `documentId` 和伴生数据 |
| 删除 | 移入 `.liteasy/trash/` 并写入恢复清单 |
| 恢复 | 回到原路径；冲突时追加可见序号，不覆盖现有资源 |
| 永久删除 | 从回收站清除正文和仅由该逻辑副本拥有的伴生数据 |
| 刷新 | 校验磁盘、索引和 UI 快照，不能注入示例资源 |

跨卷更换整个库根目录时使用“复制、校验、切换指针、再清理旧位置”的可恢复流程，不能把部分文件留在两个活跃库中。

## 6. 本地回收站

### 6.1 清单

每次删除生成一个 `trashId` 和清单，至少包括：

```text
trashId
libraryId
nodeType: document | folder | metadata_entry
documentId（适用时）
originalRelativePath
trashedAt
purgeAfter
payloadRelativePath
artifactReferences
```

目录删除必须把完整子树作为一个可恢复事务处理。操作中途失败时，要么回滚到原位置，要么保留带有修复状态的清单，不能静默丢失部分文件。

### 6.2 保留与恢复

- 默认保留 30 天。
- 应用启动和计划维护任务可以清理过期项。
- 用户可以手动永久删除单项或清空回收站。
- 恢复路径存在同名资源时，生成 `名称 (2)` 等新名称，不覆盖。
- 回收站容量计入本地磁盘占用，UI 应展示大小和过期时间。
- 本地库更换根目录时，回收站和伴生数据随库一起迁移。

## 7. 云端文献与目录模型

### 7.1 作用域

目标作用域保持简单：

```text
scope_type = user | organization
scope_id   = 用户 ID | 组织 ID
```

- `user` 作用域在产品 UI 中称为“收藏”，不是“云端本地库”。
- `organization` 作用域在 UI 中称为“组织文献库”。
- 推荐不是永久文献作用域，而是带过期策略的虚拟结果集。

### 7.2 逻辑实体

目标数据模型至少包含：

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| `library_folders` | `folder_id, scope_type, scope_id, parent_folder_id, name, status` | 多级目录和目录回收站状态 |
| `library_entries` | `document_id, scope_type, scope_id, folder_id, entry_kind, content_hash?, metadata, status` | PDF 或仅元数据条目 |
| `storage_objects` | `content_hash, byte_length, storage_key, media_type` | 内容寻址对象 |
| `storage_object_references` | `document_id, content_hash` | 对象引用与垃圾回收依据 |
| `storage_quotas` | `scope_type, scope_id, limit_bytes` | 用户或组织配额 |
| `organization_storage_policies` | `organization_id, upload_policy, export_policy` | 组织导入和复制出库策略 |
| `team_annotations` | `organization_id, document_id, uploaded_by, body` | 组织文献协作数据 |

`entry_kind` 至少支持：

- `pdf`：存在对象引用，可以下载和打开。
- `metadata_only`：没有对象引用，只能检索、引用或以后补充正文。

当前 `library_documents.content_hash NOT NULL` 无法表达仅元数据条目，实施时必须迁移为可选对象引用或等价的拆表模型。

### 7.3 目录约束

- 同一作用域和父目录下，活动节点名称按目标平台归一化后唯一。
- 服务端拒绝把目录移动到自身或后代目录。
- 父目录必须与子节点处于同一 `scope_type + scope_id`。
- 文件夹进入回收站时，整棵子树对普通列表不可见。
- 恢复冲突时由服务端生成非覆盖名称，并返回最终名称。
- 所有树修改在数据库事务中完成，并增加作用域修订号用于并发检测。

### 7.4 对象存储事务

推荐上传流程：

1. 服务端校验身份、目标作用域权限、文件大小和配额。
2. 字节流写入临时对象并计算 SHA-256，不信任客户端声明的哈希。
3. 校验 PDF 类型和安全策略。
4. 在数据库事务中创建或复用 `storage_objects`，再创建文献条目和对象引用。
5. 事务成功后提交对象；失败则清理临时对象。
6. 定期清理没有数据库引用的孤立临时对象。

复制相同 PDF 到收藏或组织库时，只创建新的逻辑文献条目和引用，不重复保存字节。配额按逻辑文献正文大小计算，不能因为全局去重而让用户绕过配额。

### 7.5 收藏不是缓存

收藏是用户主动保存的长期数据：

- 不设置自动 TTL。
- 纳入事务、配额、备份、导出和账号删除流程。
- 支持多级目录、PDF 正文和仅元数据条目。
- 只有用户本人或明确授权的后台流程可以修改。

`collections.json` 不能继续作为目标态主存储。

## 8. 推荐、检索缓存与个性化数据

### 8.1 数据分类

| 数据 | 是否长期 | 默认清理策略 | 是否属于用户 |
| --- | --- | --- | --- |
| 收藏 | 是 | 用户删除或账号生命周期处理 | 是 |
| 推荐缓存 | 否 | TTL、画像版本变化或用户清除 | 是 |
| 推荐候选 | 否 | 数量上限和 TTL | 是 |
| 推荐反馈 | 是，直到用户清除 | 用户清除或账号生命周期处理 | 是 |
| 检索缓存 | 否 | TTL 和容量淘汰 | 视内容可按用户或内容指纹划分 |
| 解析缓存 | 否 | 版本与容量淘汰 | 仅在不含私密用户信息时可跨用户复用 |
| 个性化画像与信号 | 是，直到用户清除 | 用户清除或账号生命周期处理 | 是 |

推荐区是虚拟分组视图，可以按任务、主题、时间或关联度分组，但不能伪装成用户创建的物理目录。

### 8.2 本地文献清单上传

个性化开启时，桌面端可以向当前登录账号同步必要的本地文献清单：

- `documentId` 的不可跨账号跟踪形式或一次性同步 ID；
- `contentHash`；
- 标题、作者、DOI、年份等可用元数据；
- 用户明确产生的收藏、打开、保存等信号。

禁止上传：

- 本地绝对路径；
- Windows 用户名或主目录；
- 与推荐无关的目录名称；
- 未经需要上传的批注正文、私密笔记或任意本地文件内容。

同一本地库会在 A 和 B 分别登录且分别开启个性化时，与两个账号各自形成云端画像关联；这种关联只存在云端，不写回本地库的账号标记。

### 8.3 关闭与清除

关闭个性化：

- 立即停止上传新的本地文献清单和行为信号。
- 不再使用历史画像生成推荐。
- 暂时保留已有画像，便于用户重新开启。
- 仍允许基于当前手动选择文献或检索词执行非个性化推荐。

清除个性化数据：

- 删除学术画像；
- 删除画像词项和权重；
- 删除行为信号；
- 删除推荐反馈和抑制记录；
- 删除推荐候选与推荐缓存；
- 删除服务器保存的本地文献元数据快照；
- 递增或重置相关版本，使旧缓存无法再次命中。

清除操作不删除本地文件、收藏、收藏中的 PDF、组织文件或用户有权访问的组织数据。

清除接口必须幂等，并在服务端事务或可恢复工作流中完成。UI 只有在服务端确认完成后才显示成功，不能仅清空 `localStorage`。

## 9. 四区域资源管理器 UI

### 9.1 信息结构

左侧文献资源面板按以下顺序显示四个可折叠区域：

1. 本地文献库
2. 收藏
3. 关联推荐
4. 组织文献库

每个区域独立维护加载、错误、空状态和展开状态。登录要求只影响云端区域，不得让本地文献库消失或切换到另一个账号目录。

本地库、收藏和组织库使用 VS Code 风格的紧凑树：

- Chevron 控制展开和折叠。
- 文件夹在文献前显示，同级按稳定规则排序。
- 使用 Fluent 2 文件夹、PDF、云端、组织、回收站和状态图标。
- 图标按钮提供可访问名称和 Tooltip。
- 右键菜单提供与当前节点和权限匹配的操作。
- 刷新、创建目录、导入和回收站使用图标命令，不使用常驻说明文字。

推荐区使用虚拟分组，条目仍可展开查看元数据和来源，但不提供“新建推荐目录”。

### 9.2 真实状态要求

- 空状态就是空状态，不能补入 `My Library / Courses / Vector Search` 等硬编码节点。
- 服务不可用时显示明确错误和重试入口，不能回退到演示推荐或假回答。
- 无 PDF 的条目必须显示“仅元数据”状态，打开命令不可用，但允许补充正文或复制元数据。
- 云端操作先显示待处理状态，服务端失败后恢复到之前快照并说明可执行的下一步。
- 文件监听产生的外部变化应增量更新，不折叠用户当前正在浏览的无关目录。

### 9.3 展开状态归属

- 本地库展开状态按 `libraryId` 存在本机。
- 收藏展开状态按用户账号存在本机，必要时可以上云同步设置。
- 组织库展开状态按 `userId + organizationId` 存在本机。
- 推荐分组展开状态是短期 UI 状态，不进入长期业务数据库。

## 10. 拖拽与复制矩阵

不同区域之间始终是复制，来源不被删除。目标区域创建新的逻辑条目；有正文时复制或上传正文，没有正文时创建仅元数据条目。

| 来源 \ 目标 | 本地库 | 收藏 | 推荐 | 组织库 |
| --- | --- | --- | --- | --- |
| 本地库 | 同区域移动 | 上传 PDF 或元数据 | 不支持 | 有上传权限时上传 |
| 收藏 | 下载 PDF 或保存元数据 | 同区域移动 | 不支持 | 有上传权限时复制 |
| 推荐 | 下载 PDF 或保存元数据 | 保存 PDF 或元数据 | 不支持 | 有上传权限时保存 |
| 组织库 | 受导出策略控制 | 受导出策略控制 | 不支持 | 同组织内移动；跨组织复制需同时满足源导出和目标上传权限 |

拖拽流程必须在开始前和提交时分别校验权限，防止长时间拖拽过程中角色或策略已变化。

### 10.1 组织上传策略

组织负责人可以配置谁能向组织库新增内容。目标枚举：

- `owner_admins`：仅组织负责人和组织管理员。
- `all_members`：所有活动成员。

无论 UI 状态如何，服务端每次写入都重新校验成员身份和策略。

### 10.2 组织导出策略

组织负责人配置文献能否从组织库复制到本地、收藏或其他组织：

- `disabled`：普通成员和组织管理员均不可复制出库。
- `admins_only`：组织负责人和组织管理员可以复制出库。
- `all_members`：所有活动成员可以复制出库。

组织负责人始终可以操作。该策略限制复制和下载持久正文，不限制用户在产品内按其阅读权限在线查看。

若产品将“在线查看”实现为完整 PDF 下载到可导出的普通文件路径，则无法真正执行禁导策略。此时必须使用受控应用缓存、短期授权和禁止“另存为”的能力边界，并在产品文档中诚实说明客户端内容保护不能等同于 DRM。

## 11. 云端回收站

### 11.1 用户收藏

- 用户可以删除、恢复和永久删除自己的收藏节点。
- 文件夹删除将子树统一标记为已删除。
- 默认保留 30 天。
- 回收站内容继续占用用户逻辑配额，永久清除后才释放逻辑引用。

### 11.2 组织库

- 组织负责人和组织管理员可以删除、恢复和永久删除组织节点。
- 普通成员不能管理组织回收站。
- 默认保留 30 天。
- 所有操作写入不可由普通成员修改的审计日志。
- 恢复时重新校验父目录和名称冲突。

### 11.3 对象垃圾回收

文献条目永久删除后，移除对应对象引用。只有不存在任何用户、组织或其他合法实体引用时，后台垃圾回收任务才删除对象存储中的字节。

不能仅依赖应用内存中的引用计数。引用变更和文献永久删除必须由数据库事务保证一致性，并由周期性校验任务修复计数或引用差异。

## 12. 身份、权限和管理后台

### 12.1 统一身份，不共享业务会话

Liteasy、Intuecho 和管理后台共享同一个用户身份源和用户 ID，但使用不同客户端和 token audience：

| 客户端 | Audience | 主要能力 |
| --- | --- | --- |
| Liteasy 桌面端 | `liteasy-desktop` | 文献、推荐、Agent、个人与组织功能 |
| Intuecho | `intuecho-web` | 论坛浏览、发帖和互动 |
| 管理后台 | `liteasy-admin` | 平台治理和审计 |

- 不能把一个站点的会话 Cookie 直接作为另一个站点的业务会话。
- 服务端按 audience、scope、角色和资源归属共同授权。
- 用户被禁用或删除时，统一身份服务吊销所有客户端的活动会话。

### 12.2 角色分离

| 角色或权限 | 范围 | 能力 |
| --- | --- | --- |
| 普通用户 | 自己 | 收藏、画像、个人配额和可访问组织功能 |
| 组织成员 | 指定组织 | 按组织策略阅读、上传或复制 |
| 组织管理员 | 指定组织 | 成员和组织库日常管理 |
| 组织负责人 | 指定组织 | 策略、管理员、配额申请和最终控制 |
| `platform_admin` | 平台 | 账号、配额、组织治理、API 配置、检索源和论坛治理 |
| `developer_diagnostics` | 非生产环境 | 请求追踪、内部诊断和开发错误详情 |

`platform_admin` 不应默认获得读取所有用户或组织 PDF 正文的能力。确需支持排障时，使用独立、限时、说明原因且全量审计的支持访问权限。

### 12.3 Intuecho 批注社区模型

Intuecho 不区分“问题”“帖子”和“批注”，社区唯一内容实体为 `annotation`。独立批注必须至少关联一篇文献或一处原文字句；对薄读生成内容的批注必须同时保存生成内容目标和对应原文 evidence，不能只引用无法追溯的生成结果。一个批注可以混合关联多篇文献、多个原文字句和多个带证据的薄读目标。

回复也是批注，通过 `parent_annotation_id` 关联原批注。回复在评论区呈现并继承原批注的可见范围，也可以增加回复者自己的文献或原文字句目标；只有公开且具有自己文献目标的回复才可同时进入广场。原批注不存在、已撤回或当前用户无权查看时，不得创建回复，也不能通过错误差异泄露私有批注是否存在。

可见范围固定为：

- `private`：仅作者本人；
- `organization`：仅指定组织的当前有效成员；
- `mutual_followers`：仅当前互相关注用户；
- `public`：公开，可按发布者选择进入广场。

组织可见性和组织邀请不能由 Intuecho 自行信任客户端字段。Intuecho 使用专用 client-credentials 机器身份调用 Liteasy 内部组织授权 API；token audience 为 `liteasy-internal`，client 为部署配置的 `intuecho-organization-service`，scope 为 `organization:authorize`。Liteasy 再从组织事务库实时判断组织状态、成员状态、邀请者角色和目标成员冲突。该机器身份不是用户 audience，不得交给浏览器或桌面端。

用户标签和平台语义标签均持久保存。平台标签优先采用本地可部署的语义特征/向量算法，不以外部 LLM API 作为正确性或可用性前提；必须记录分类器版本和置信度。作者可以申诉平台标签，管理员的接受/驳回决定、原因、操作者和 `traceId` 写入不可修改的审核审计。检索输入 `/A` 只把 `A` 作为本次请求的动态二分类标准并用于推荐排序，不保存成标签、画像或长期分类。

研究机构、机构类型和学段来自用户资料。发布和每次编辑保存当时的资料快照，展示最后编辑时的信息；用户属于多个机构时，筛选按任一机构存在即匹配。广场支持推荐与最新排序，以及指定机构、机构类型、学段、文献类型和稳定文献身份筛选。

只有当前互相关注的用户可以新建私聊会话或发送新消息。解除互关后保留历史消息，但所有续发失败关闭。组织邀请必须使用结构化邀请卡片；卡片只有在 Liteasy 组织权限系统真实创建邀请后才能写入会话，不能把普通文本当成有效邀请。

旧 `topic/work/post/comment` 接口仅用于迁移兼容，不得继续作为新社区功能的主数据模型或要求桌面导入文献生成论坛 topic/work 映射。

### 12.4 管理员创建

- 不在源代码、迁移、默认 JSON 或前端常量中写死管理员账号和密码。
- 本地开发通过脚本读取 `.env.local` 创建或更新开发管理员。
- 开发管理员可以同时具有 `platform_admin` 和 `developer_diagnostics`。
- staging 演示使用隔离环境中的真实账号、真实权限链路和可重置测试数据。
- 生产首个管理员通过一次性引导命令创建，首次登录必须修改密码并启用 MFA。
- 后续管理员由已有授权管理员邀请或授予，并生成审计事件。

### 12.5 错误与诊断

普通用户响应只包含：

```json
{
  "code": "stable_error_code",
  "message": "可执行的用户提示",
  "traceId": "trace_..."
}
```

原始异常、堆栈、SQL、文件路径、服务密钥和上游响应正文只能进入受控服务端日志。生产管理员界面显示错误编号、影响范围和审计信息，不自动显示原始堆栈。

`developer_diagnostics` 只在非生产环境启用。部署配置必须在服务端强制关闭生产诊断能力，不能只隐藏前端入口。

## 13. Mock、演示数据与测试替身策略

### 13.1 必须从运行路径移除

- 模型 `mockProvider` 和由它生成的假回答。
- 静态推荐列表以及 `sourceKind: "mock"` 运行时分支。
- `demo-session-*`、演示账号和请求缺少会话时自动补演示会话的行为。
- 管理后台的 Demo 重置、重新播种以及依赖 Demo 状态的业务面板。
- 硬编码组织、成员、收藏和会话 JSON 主数据。
- `fixtures/*.pdf` 作为真实文献缺失时的运行时回退。
- 资源树中的硬编码目录以及按标题关键字伪造目录分类。
- 外部模型或检索服务未配置时自动返回的虚假成功结果。

服务未配置或不可用时必须返回明确的不可用状态，不能伪造完成。

### 13.2 可以保留

- `*.test.ts(x)` 和 `*.test.mjs` 中的 mock transport、临时目录、内存数据库和固定响应。
- 测试专用 fixture 文件，但不得打包进生产路径或由生产代码自动引用。
- 处理真实输入的确定性降级算法，例如远程解析不可用时使用本地解析器。
- UI 对未知错误的安全提示、解析器兼容逻辑和不泄露内部信息的显示降级。

“fallback”这个词本身不是删除标准。判断标准是它是否在没有真实数据或真实服务的情况下伪造业务成功。

### 13.3 测试环境入口

测试替身必须通过测试依赖注入、测试 runner 配置或独立测试进程启用。不得使用可被普通用户设置的生产环境开关开启 mock provider。

## 14. Zotero 兼容路线图

### 第一阶段：PDF

- 接收 Zotero 导出的目录中的 PDF。
- 递归发现 PDF 并保留导出目录中的相对层级。
- 使用与普通本地导入相同的去重提示、大小校验、文献身份和回收站流程。
- 不读取 Zotero 数据库，不承诺导入标签、笔记、引用键或集合元数据。

### 第二阶段：结构化 JSON

- 支持 Better BibTeX JSON。
- 支持 CSL JSON。
- 解析标题、作者、DOI、年份、标签、引用键和附件相对路径。
- 附件存在时关联 PDF；附件缺失时建立仅元数据条目。
- 提供字段预览和冲突确认，不静默覆盖已有用户元数据。

### 第三阶段：通用交换格式

- 支持 BibTeX `.bib`。
- 支持 RIS `.ris`。
- 评估 Zotero 官方 Web API 或受控连接器，但不直接修改 Zotero 的 SQLite 数据库。
- 增加增量导入、重复合并和来源追踪策略。

第二、三阶段不属于第一阶段验收范围。

## 15. 接口与命令边界

### 15.1 Tauri 本地命令

目标能力至少包括：

| 能力 | 说明 |
| --- | --- |
| 获取本地库快照 | 返回真实目录、PDF、元数据条目、回收站计数和修订号 |
| 设置本地库根目录 | 与 SaaS 账号无关，执行安全迁移 |
| 创建目录 | 校验路径、保留名称和根目录边界 |
| 导入 PDF | 流式或受控写入，避免前端长期持有超大字节数组 |
| 移动或重命名 | 文件系统与伴生数据一致更新 |
| 移入回收站 | 生成清单并原子移动 |
| 列出和恢复回收站 | 支持冲突改名 |
| 永久删除 | 清理正文和伴生数据 |
| 订阅变化 | 发出带修订号的本地库变化事件 |

所有本地命令必须在 Rust 层 canonicalize 并验证路径位于根目录内，拒绝路径穿越、符号链接逃逸和操作 `.liteasy/` 内部管理节点。

### 15.2 云端 API

现有文献上传、列表、下载、更新、回收和目录接口可以演进，但还需补齐：

- 一次获取作用域目录树和修订号；
- 文件夹移入回收站、恢复和永久删除；
- 回收站列表和清空；
- 用户收藏与组织库之间的服务端复制；
- 组织上传和导出策略读取、修改；
- 元数据条目创建和后续补充 PDF；
- 本地文献元数据清单的增量同步和删除；
- 个性化启用状态读取、修改和完整清除；
- 平台管理员引导、RBAC、MFA 状态和审计查询。

写接口要求：

- 使用幂等键避免重试产生重复文献。
- 使用作用域修订号或等价乐观并发控制。
- 返回服务端最终节点名称和修订号。
- 返回稳定错误码和 `traceId`。
- 权限校验基于认证会话，不接受客户端自行声明 `owner_key` 作为授权事实。

## 16. 迁移实施计划

### 阶段 0：基线与保护

- 冻结新增运行时 mock 和演示账号依赖。
- 为现有真实本地扫描、导入、云端文献 API、画像清除建立回归测试。
- 记录所有生产代码中的 Demo、fixture、JSON 主数据和 mock provider 引用。
- 定义数据库与对象存储备份、恢复和迁移回滚方式。

### 阶段 1：本地库账号解耦

- 将根目录设置从按 `accountKey` 存储迁移为操作系统用户级单一设置。
- 将 `.liteasy-library-profile` 替换为 `.liteasy-library.json`。
- 删除所有本地库 Tauri 命令的 `accountKey` 授权语义。
- 保留稳定 `documentId` 和已有批注、锚点、全文及阅读状态。
- 增加本地目录创建、回收站、恢复、永久删除和文件监听。

若发现多个旧账号指向不同根目录：

1. 一次性迁移界面列出所有现有根目录。
2. 用户选择一个作为当前库。
3. 未选目录保持原状，不自动合并、不删除。
4. 用户可在之后显式导入其他目录的 PDF。
5. 选择成功并校验后才移除所选根目录的账号占用标记。

### 阶段 2：云端长期数据事务化

- 把组织、成员和组织策略从 JSON 迁入事务数据库。
- 把收藏从 `collections.json` 迁入用户作用域目录与文献表。
- 扩展云端文献模型以支持仅元数据条目和文件夹回收站。
- 将对象字节迁出服务发布目录，接入独立对象存储根或 S3 兼容服务。
- 对迁移前后数量、归属、哈希、配额和权限进行核对。

### 阶段 3：四区域真实资源树

- 移除硬编码 `libraryCollections` 和标题关键字分类。
- 接入本地监听快照、收藏目录树、推荐虚拟分组和组织目录树。
- 实现区域内移动及跨区域复制 controller。
- 实现组织上传和导出策略。
- 补齐加载、空、错误、离线、冲突和回收站状态。

### 阶段 4：个性化隐私闭环

- 增加服务端个性化启用状态。
- 本地监听变化只在开启且已登录时同步必要元数据。
- 完整实现关闭和清除语义。
- 对现有按钮执行端到端验证，确保不是只修改本地 UI 状态。
- 提供可审计但不泄露内容的删除结果。

### 阶段 5：身份与管理面收敛

- 将 Liteasy、Intuecho 和管理后台接入统一身份源及独立 audience。
- 把平台角色、组织角色和开发诊断权限分离。
- 提供开发管理员创建脚本和生产一次性管理员引导。
- 增加 MFA、会话吊销、审计日志和受控支持访问。

### 阶段 6：清除运行时 mock

- 按第 13.1 节逐项移除 mock provider、Demo API、演示账号、fixture 文献和静态业务结果。
- 外部依赖缺失时改为明确不可用状态。
- 测试替身迁入测试边界并确认不会进入生产构建。
- 对仓库执行静态扫描，并逐项人工判断合法容错与虚假业务回退。

### 阶段 7：Zotero 第一阶段

- 支持递归导入 Zotero 导出目录中的 PDF。
- 保留相对目录层级。
- 复用普通 PDF 导入、去重、回收站和文件监听能力。
- 第二、三阶段仅保留接口扩展点和设计计划，不提前引入半成品解析入口。

## 17. 安全、可靠性与运维要求

### 17.1 本地安全

- 所有路径操作限制在已确认根目录内。
- 拒绝 `..` 穿越、符号链接逃逸、设备文件和内部管理目录操作。
- 写入索引和清单使用临时文件、落盘和原子替换。
- 大文件导入避免把多份 PDF 同时展开成前端数字数组。
- PDF 解析任务与文件管理事务分离，解析失败不删除原始 PDF。

### 17.2 云端安全

- 对象存储默认私有，禁止公开 bucket。
- 下载使用经过业务授权的服务端流或短期签名 URL。
- 数据库和对象存储静态加密，传输使用 TLS。
- PDF MIME、文件头、大小和恶意内容策略由服务端重新检查。
- 高风险管理操作要求 MFA、新鲜认证和审计。
- API 密钥使用密钥管理服务或部署密钥，不写入数据库普通配置字段的明文响应。

### 17.3 一致性

- 数据库记录和对象写入使用临时对象加事务提交模式。
- 复制、删除和恢复接口幂等。
- 所有树修改检测环和跨作用域父节点。
- 后台任务处理过期回收站、缓存淘汰、孤立对象和引用一致性检查。
- 缓存故障不得损坏收藏、组织库或身份主数据。

### 17.4 备份

| 数据 | 备份策略 |
| --- | --- |
| 事务数据库 | 时间点恢复能力、加密备份、定期恢复演练 |
| PDF 对象存储 | 版本或不可变备份策略、生命周期策略、跨故障域复制按部署等级确定 |
| 审计日志 | 独立保留，普通管理员不可修改 |
| 推荐和检索缓存 | 原则上不备份，可重建 |
| 本地文献库 | 平台不自动承诺云备份；提供用户可理解的备份提示和完整导出 |

正式上线前必须补充经业务确认的 RPO、RTO、审计保留期和账号删除保留期，本文不虚构具体 SLA。

### 18.2 桌面端

- 生产构建扫描不得包含 mock provider 入口、演示凭据或 fixture 文献引用。

## 19. 验收标准

### 19.1 本地库

- A、B 两个 Liteasy 账号在同一 Windows 用户下看到同一个本地库。
- 退出登录后本地库仍可查看和管理，云端区域进入登录提示状态。
- 在 Windows 文件管理器中新建、移动、重命名或删除 PDF 后，Liteasy 自动更新。
- Liteasy 删除的文件和目录可从本地回收站恢复，默认过期时间为 30 天。
- UI 不显示 `.liteasy/` 内部目录，不显示不支持的任意文件。

### 19.2 云端

- 收藏和组织库来自真实数据库目录树，不读取长期 JSON 主数据。
- PDF 正文进入独立对象存储，服务发布目录不包含用户上传数据。
- 仅元数据条目可以列出和引用，但不能伪装成已有全文。
- 文件夹和文献均可回收、恢复和永久删除。
- 任何用户都无法通过猜测 ID、哈希或路径读取其他作用域内容。

### 19.3 UI 与拖拽

- 四个区域独立展示并可折叠。
- 同区域拖拽是移动，跨区域拖拽是复制。
- 组织出库操作严格遵守 `disabled / admins_only / all_members`。
- 复制失败不删除来源，也不留下可见的半成品目标条目。
- 空库不会出现硬编码示例目录或文献。

### 19.4 个性化与隐私

- 关闭后不再产生新的本地文献清单或行为信号上传。
- 清除后服务端所有约定个性化数据均被删除，旧缓存无法命中。
- 清除个性化不删除收藏、组织文件或本地文件。
- 服务端不保存本地绝对路径。

### 19.5 身份与 mock 清理

- Liteasy、Intuecho 和管理后台使用统一身份 ID 和各自 audience。
- 平台管理员、开发诊断和组织角色独立授权。
- 管理员通过安全引导或非生产脚本创建，没有硬编码账号或密码。
- 生产及日常开发运行路径不存在 mock provider、演示会话、假推荐、fixture PDF 回退或 Demo 重置业务入口。
- 自动化测试仍能通过测试边界使用受控替身。

## 20. 第一阶段明确不做

- 本地库与云端收藏的自动双向同步或镜像。
- 同时打开多个本地库根目录。
- 通用文件管理器能力。
- Zotero JSON、BibTeX、RIS 的正式导入。
- 直接读写 Zotero SQLite 数据库。
- 依靠客户端实现不可绕过的 DRM。
- 在生产环境向管理员显示原始堆栈、密钥或用户私密正文。

## 21. 当前实现差距摘要

以下是当前开发阶段仍必须承认的差距，不应将仓库实现或本机测试等同于部署完成：

- 本地库账号解耦、真实目录操作、回收站、监听恢复和四区域 controller 已实现并有自动化覆盖，但完整 Windows Tauri 实机验收尚未执行。
- Liteasy 正式 PostgreSQL/S3 边界和独立 Intuecho PostgreSQL 的 schema、仓库、迁移与 readiness 已实现；目标 Linux 环境尚未部署，正式数据库、私有 S3、跨故障域复制、PITR 和一致性恢复没有环境证据。
- 统一 OIDC 的三个用户 audience、Intuecho 专用组织服务身份、MFA、新鲜认证、会话吊销与账号删除续跑已有代码契约；真实 IdP、Windows Credential Manager 和 staging 浏览器 SSO 尚未联调。
- Intuecho 已以 `annotation` 作为新社区唯一内容实体并完成桌面交接、本机浏览器发布/读回、标签申诉、互关私聊和组织授权协议；新的五迁移 PostgreSQL 集成脚本尚未在当前机器的真实 PostgreSQL 上执行。
- 模型、扫描、Crossref/OpenAlex/Semantic Scholar 连接器与失败关闭策略已有实现和受控 transport 测试；真实上游、病毒库更新、部署出口、限流和密钥轮换尚无 staging 证据。
- 生产维护命令和发布证据门禁已有仓库入口，但正式调度、监控告警、隔离备份恢复、RPO/RTO 与保留期签署尚未完成。
- Zotero 仅完成第一阶段 PDF 目录导入；结构化 JSON、BibTeX 和 RIS 按路线图保留，Zotero SQLite 直读写仍明确不做。

以上差距以第 19 节和实施审计中的发布门禁判断，不以页面是否显示按钮或单元测试是否通过判断完成。
