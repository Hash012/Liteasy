下面是目标架构。它不是现状，而是按我们刚确认的要求完成后应达到的结构。

**总体架构**

虚线的“未确认 → 使用”必须被硬性拒绝，而不是只在 UI 提示。

**分级确认决策**

```mermaid
flowchart TD
  START["PDF 身份线索"] --> HAS_ID{"存在稳定外部 ID？"}

  HAS_ID -->|是| TIER1{"属于一级来源？"}
  TIER1 -->|是| EXACT["按来源内 ID 精确回查"]
  EXACT --> VALID1{"唯一命中且题录无冲突？"}
  VALID1 -->|是| CONFIRMED["confirmed<br/>创建正式 literatureId"]
  VALID1 -->|否| CONFLICT["conflict / ambiguous"]

  TIER1 -->|否，聚合来源| REFETCH2["重新抓取聚合来源记录"]
  REFETCH2 --> CORROBORATE{"两个独立来源一致？"}
  CORROBORATE -->|是| CONFIRMED
  CORROBORATE -->|否| USER{"用户明确选择候选？"}
  USER -->|是| VALID2{"重新抓取后<br/>无来源冲突？"}
  VALID2 -->|是| CONFIRMED
  VALID2 -->|否| CONFLICT
  USER -->|否| AMBIG["ambiguous"]

  HAS_ID -->|否| SEARCH["题名 + 完整作者 + 年份<br/>仅用于检索候选"]
  SEARCH --> FOUND{"找到来源候选？"}
  FOUND -->|是| USER
  FOUND -->|否| UNRESOLVED["unresolved<br/>只保留本地文件"]

  MANUAL["用户人工输入题录"] --> SEARCH

  CONFIRMED --> CITABLE["允许引用、发布、同步"]
  CONFLICT --> BLOCK["禁止正式使用"]
  AMBIG --> BLOCK
  UNRESOLVED --> BLOCK

  classDef pass fill:#e8f5e9,stroke:#2e7d32,color:#172019;
  classDef wait fill:#fff4ce,stroke:#a15c00,color:#302000;
  classDef stop fill:#fdecec,stroke:#b42318,color:#3b1111;

  class CONFIRMED,CITABLE pass;
  class START,HAS_ID,TIER1,EXACT,REFETCH2,CORROBORATE,USER,VALID1,VALID2,SEARCH,FOUND,MANUAL wait;
  class CONFLICT,AMBIG,UNRESOLVED,BLOCK stop;
```

这里最关键的规则是：人工输入只能重新发起检索，不能直接创建正式论文。

**目标数据模型**

```mermaid
erDiagram
  LITERATURE_RECORDS ||--o{ LITERATURE_IDENTIFIERS : "拥有规范标识"
  LITERATURE_IDENTIFIERS ||--o{ IDENTITY_CLAIMS : "拥有来源证据"
  LITERATURE_RECORDS ||--o{ LITERATURE_RELATIONS : "作为关系起点"
  LITERATURE_RECORDS ||--o{ LITERATURE_RELATIONS : "作为关系终点"
  LITERATURE_RECORDS ||--o{ ANNOTATION_TARGETS : "被正式引用"

  LITERATURE_RECORDS {
    text id PK
    text title
    json authors
    int publication_year
    text version_kind
    text confirmation_status
    int revision
  }

  LITERATURE_IDENTIFIERS {
    text id PK
    text literature_id FK
    text identifier_kind
    text normalized_value
    unique kind_and_value
  }

  IDENTITY_CLAIMS {
    text id PK
    text identifier_id FK
    text provider
    text provider_record_id
    text verification_status
    json evidence
    timestamp observed_at
  }

  LITERATURE_RELATIONS {
    text from_literature_id FK
    text to_literature_id FK
    text relation_type
    text verification_status
    json evidence
    timestamp created_at
  }

  ANNOTATION_TARGETS {
    text annotation_id FK
    text literature_id FK
  }
```

这里对文字版设计做了一个重要收敛：标识和来源证据分开保存。

例如 DOI `10.x/abc` 只能属于一个 `literatureId`，但 Crossref、OpenAlex、Semantic Scholar 都可以分别为它提供验证证据：

```mermaid
flowchart LR
  DOI["唯一标识<br/>doi:10.x/abc"]
  C["Crossref claim"]
  O["OpenAlex claim"]
  S["Semantic Scholar claim"]
  L["literatureId"]

  L --> DOI
  DOI --> C
  DOI --> O
  DOI --> S
```

这样不会因为 provider 不同，让相同 DOI 被错误挂到多个论文实体。

**预印本与正式版**

```mermaid
flowchart LR
  subgraph Preprint["预印本实体"]
    LP["literatureId: L-preprint"]
    AID["arxiv_id: 2401.01234v2"]
    PA["预印本页码与批注"]
    LP --> AID
    LP --> PA
  end

  subgraph Published["正式发表实体"]
    LF["literatureId: L-published"]
    DOI["doi: 10.x/example"]
    FA["正式版页码与批注"]
    LF --> DOI
    LF --> FA
  end

  LP -->|"is_preprint_of<br/>有来源证据"| LF

  PA -.不自动迁移.- FA
```

两者可以在搜索结果中组成一个版本组，但：

- 不共享 `literatureId`；
- 不自动共享页码和批注；
- 不混合引用指标；
- 不共享全文授权；
- 可以提示“已有正式版”；
- 引用导出可以优先正式版。

**最终硬门槛**

```mermaid
flowchart LR
  A["contentHash"] -->|只能| CACHE["文件去重 / 缓存"]
  B["题名 + 作者 + 年份"] -->|只能| CANDIDATE["候选检索"]
  C["旧 8 位 FNV"] -->|只能| LEGACY["旧记录只读兼容"]
  D["confirmed literatureId"] --> CITATION["引用"]
  D --> ANNOTATION["公开批注"]
  D --> COMMUNITY["社区同步"]

  A -.禁止.- CITATION
  B -.禁止.- CITATION
  C -.禁止新写入.- CITATION

  classDef allowed fill:#e8f5e9,stroke:#2e7d32,color:#172019;
  classDef denied fill:#fdecec,stroke:#b42318,color:#3b1111;

  class D,CITATION,ANNOTATION,COMMUNITY allowed;
  class A,B,C denied;
```

最终只保留一条正式主链：

```text
PDF 线索
→ provider 检索
→ 分级裁决
→ 服务端重新抓取
→ confirmed literatureId
→ 引用/发布
```

旧人工正式确认、旧 FNV 写入、仅判断“不是 local ID 就允许同步”等并行路径都会在兼容验证后删除。
