# C03 第一片：原文件入口与可恢复的任务布局

基于 `8d31bf57`，分支 `feat/client-c03-workbench-start`。保留现有 CommandPalette、自由 Dock、笔记文件授权/读取/保存链路，没有创建第二套命令或文件管理系统。

## 可见行为

- 起始页优先提供“打开 Markdown 原文件”（Ctrl/⌘+O）、“连接笔记文件夹”（Ctrl/⌘+Shift+O）、页面历史。已有“打开文献库”说明复制导入 PDF/电子书，不把复制包装成原位置打开。PDF/电子书原位置直开仍待后续切片。
- Markdown 使用现有系统选择器、单文件授权和中央 reader。打开不写源文件、不移动、不改名、不调用模型；编辑/保存仍走已有冲突检查。连接文件夹使用原有目录授权，保留层级，不复制/上传内容。浏览器环境显示不可用原因，不假装有原生文件系统权限。
- 阅读布局收起周边面板；研究布局打开文献库和助手；处理布局打开已有运行记录，不发起任务。恢复自定义布局返回本轮第一次切换前的展开/隐藏状态；面板顺序、宽度、文件 ID、标签页、草稿与运行任务不删除。此恢复是当前窗口内的显示快照，不是跨重启布局版本管理。
- 同一快捷操作注册表供首页、菜单和键盘调用。不可用原因在按钮和搜索菜单显示；回车/快捷键不能绕过不可用状态。文件选择重入受限；取消无导航副作用；切换账号后忽略旧选择结果；错误有可关闭提示。

## 验证与边界

先用禁用动作仍被点击/快捷键调用的反例复现缺口。51 个相关测试通过，包含 AppShell、六窗格展开恢复、原文打开不调用写入/复制 API、取消、选择中切换账号、既有 Dock 与聊天任务生命周期。8 个 smoke 与生产 build 通过，另运行既有原生笔记存储的 12 个 Rust 文件测试（真实临时文件/SQLite，非窗口选择器）。无新 schema/版本/锁文件/网络服务改动。

WSLg 真壳显示新首页（`/tmp/liteasy-c03-welcome.png`），但系统文件选择器未能通过当前 X11 自动输入完成；实际原文件打开场景为 blocked，不能记为原生成功。合成 Markdown 的 SHA-256 始终为 `af03be751b335e9a0dcd6460cd2f16ad08b1e4568ae2db008ca444a9057a8b9a`。测试不读取私人资料。Windows/macOS 原生尚未执行。

Playwright 使用现有 Chromium 和 local-only Vite，阻止外部服务访问。首次冷模块转换超过既有首屏断言时间，未扩大超时；进一步复现了旧测试关闭最后一个设置页面却要求保留空面板的前提冲突。该起始页场景显式启用“保留空面板”，空面板自动关闭另由现有测试覆盖，未修改产品默认值。并更新已过期的手册标题断言；最终 3 个浏览器场景通过（12.2 秒），结果见机器报告，不能据此声称冷启动性能达标。
