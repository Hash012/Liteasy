# C06：受控本地复制切片

2026-10-02；从 `0fba97be` 隔离实施。此报告只证明本次有界切片，不代表整张 C06 或三平台交付完成。最终集成入口和测试提交见同目录 JSON 报告及集成报告。

## 可用流程

桌面工具 `LocalFileOperationsTool` 通过既有 `note_files_dispatch` 与账号隔离的 `FileStore` 工作。原生文件夹选择器分别授权来源、输出父目录；用户逐项勾选 `.md`、`.markdown`、`.canvas`，生成计划后另行确认。文件内容仅原样复制，不能增加动作、路径或权限。浏览器显示不可用；其他格式未接入。

新动作 `local_files.copy` 注册在现有 `resourceActionPolicy`，需要确认。未向自然语言 planner 或 Agent CLI 增加隐式写文件入口。审计发现现有 `skills/actionRegistry` 没有可直接复用的确定性外部文件复制动作；其语义计划回滚也不提供持久逐文件回执，因此本次只复用 action policy 和已有原生文件服务，不重写通用 Agent 执行器。

原生计划绑定当前账号、两个 grant、文件夹身份、逐文件身份与 SHA-256 修订、输出路径、固定动作、幂等键与计划摘要。相同幂等键不能绑定不同输入。输出在确认后新建 `Liteasy-copy-*` 目录，拒绝复用已有目录、覆盖已有文件和接受渲染层绝对路径。嵌套来源按文件名复制；大小写折叠后的同名输出需分批处理。

边界为 100 项、每项 8 MiB UTF-8、合计 32 MiB、并发 1。面板显示逐项路径、字节数、修订、状态、已提交字节数、回执和备份位置。模型和网络调用均为 0，没有虚构金额。

每次 `step` 最多提交一项：重新检查账号、目录与来源修订；在既有 SQLite WAL / `synchronous=FULL` 中提交意图；复用 `FileStore.write(expected=None)` 的暂存与原子新增路径；再提交逐项回执。取消停止下一项调度，正在临界提交的一项按回执保留。失败不显示整批成功。重试跳过已提交、版本冲突和需人工核对的项；已知版本冲突必须重新预览新计划。

重启读取日志不会自动恢复写入。若意图存在而输出尚不存在，该项可在再次确认后重试。若输出存在但缺少完成回执，则标为 `uncertain`，保留文件、不重复写入、不冒认所有权或自动撤销；用户可继续其余项目。创建输出目录后、记录目录身份前中断会拒绝复用该目录，需新建计划。

撤销另行确认，只处理有完成回执且当前身份、内容修订仍匹配的输出。输出移入同目录下回执列明的 `.liteasy-undo-*` 备份，不永久删除；人工改动或替换发生冲突并保留。撤销中断保留原位置及备份供核对；撤销可以在项目间取消。

## 集成

根集成者在可到达的设置/工具入口渲染：

```tsx
<LocalFileOperationsTool
  key={localScope}
  scope={localScope}
  currentScope={() => currentScopeRef.current}
/>
```

导入路径为 `src/app/controllers/LocalFileOperationsTool`。`scope` 与现有笔记/对象存储使用同一已验证账号范围，切换账号按 `key` 重建。无需新增 main 命令注册、共享 schema 或依赖。仅导出组件、尚未接入 AppShell 的分支不能声称用户入口已交付。

## 验证边界

环境是 WSL2 Ubuntu 24.04 x86_64，Node 22.13.1、Rust 1.98.0；与 `.nvmrc` 22.23.2 / Windows workflow Rust 1.98.1 不同。原生核心测试使用真实临时文件、真实 SQLite、真实权限/修订与 Unix 链接；没有启动 Tauri WebView 或调用真实 picker。React 测试使用 jsdom 和模拟 `invoke`，覆盖真实组件选择、预览、二次确认及请求内容。

回归包括：第 17 项失败保留前 16 项回执；临时失败重试不重写；已知版本冲突保留并继续其他项；账号边界；取消与撤销取消；持久意图重开后的不确定提交；输入变化；后续人工输出修改；路径逃逸、静态链接、授权根替换、非普通文件、非 UTF-8、格式、个数及字节限制；恶意文档文字按普通内容复制。

精确命令、通过数量和未运行项见 `C06-verification.json`。重开日志测试模拟中断边界，并非实际 kill/power-loss 测试。完整 Windows/macOS 原生编译、junction/权限、安装器、真实 Tauri IPC、进程杀死与低配性能均未在本分支验证。

`FileStore` 使用路径检查和操作前身份/修订复验。它拒绝观测到的符号链接、Windows reparse point 与替换，但普通跨平台文件 API 不能消除外部进程在最后检查与 OS 操作之间的对抗性 TOCTOU。撤销保留备份以避免永久丢失并发内容，但仍不宣称完整满足 C06 的对抗性路径替换验收。该项及 Windows 原生证据必须继续完成；当前不是 release-ready。

## 数据兼容与回退

仅在既有 `note-files/grants.v1.sqlite3` 增加 `file_operation_tasks` 表，账号隔离；日志存路径、修订、状态和回执，不复制正文。不会更改对象 schema、锁文件、版本或生产服务。旧版忽略附加表；回退不会删除原文、新输出或撤销备份。不要为回退清空整个 grants 数据库；需审查任务时使用新版本或只读导出该表。任务历史界面最多列出最近 50 项，持久日志不自动淘汰。
