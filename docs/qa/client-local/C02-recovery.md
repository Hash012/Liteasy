# C02 第一片：会话恢复只读保护与可靠保存

基于 C00 的 `4978126c`，分支 `feat/client-c02-recovery`。这是 C02 的独立最小切片，不代表完整备份、所有草稿、迁移与插件安全启动已验收。

## 行为和实现边界

- 未知快照版本、无法读取的 JSON 或加载异常：保留原文件/存储值，禁止后续创建持久会话和执行任务，不再写入空快照。
- v1 中坏一条记录：按会话、运行、确认、trace 分别检验；可读取正常记录，错误诊断仅给字段位置，不打印资料内容。只要有坏记录，整个快照保持只读，避免“修复保存”丢弃坏记录。原始文件/对象存储值仍完整保留，可通过原有资料目录备份；本片没有自动修复/诊断导出 UI。
- 保存失败：返回明确错误，阻止未开始的动作；已经执行但回执保存失败时，明确提示先检查操作结果再恢复，不能把内存完成当作持久保存成功。原有中断任务标记为失败、相同幂等键不重执行的行为继续保留。
- 账户作用域继续使用既有对象存储事务，按加载时版本提交，拒绝另一窗口更新后的旧写入。浏览器 localStorage 降级存储检查加载值是否改变，但不宣称它具有跨进程事务。
- 旧原生 JSON 存储复用 local_library 的原子发布器，Windows 不再 remove 后 rename；Unix 私有会话文件维持 0600。原生端也拒绝覆盖未来版本/损坏 JSON。不新建数据库、不改服务/API/云同步。
- 前端 Agent client 原样传播恢复错误，不再用笼统的“无法创建会话”掩盖原因。

## 反例与验证

新增测试先在修改前失败：5 个恢复/保存反例，另有 2 个并发覆盖反例。修复后 25 个 focused、73 个前端/上下文/会话生命周期、12 个 public API/中断恢复测试通过，另有 8 个 smoke；传输和模型使用替身，未调用真实模型。生产前端构建通过，保留现有大 chunk 警告。

Rust `--locked` check 和真实临时目录文件测试在 Ubuntu 24.04 x64 / WSL2 运行。原生测试验证未来版本与坏 JSON 的字节不变、合法重复保存、非法替换被拒绝、Unicode/空格路径、Unix 权限；复用原子发布的失败注入与长路径测试。不是进程断电、完整磁盘、Windows 安装升级或多文件事务验证。命令和剩余状态见 `C02-verification.json`。

## 恢复与兼容

数据版本不变。已支持快照无需迁移。只读提示出现时先保留完整资料目录或对象存储备份，不能删除旧快照“解决”；未来版本用支持该版本的应用恢复，坏记录应在副本上修复后重新打开。读写冲突应重新载入，禁止盲目重试同一写入。回退代码前仍先备份，因为旧版仍存在覆盖未知版本的行为。
