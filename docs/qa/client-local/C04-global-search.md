# C04：工作区全局搜索

2026-10-02；从第一轮 `0fba97be` 继续。入口固定在应用最上栏中间，快捷键 Ctrl/Command + Shift + F；窄窗口收为居中图标。使用现有 Fluent Dialog，支持关键词、引号短语、正文/元信息/笔记/批注/产物过滤、分页和保存查询。

## 数据与定位

复用账号隔离的 `semantic_index` SQLite，加一个 FTS5 trigram 文本表；不增加向量服务、模型请求或第二份资产数据库。两字中文与标点通过参数化精确子串条件保留。新缓存分区为 `global-search-v1`，旧推荐索引接口不变。

只收集当前可访问论文、对象最新修订、阅读库和已授权笔记目录。对象先读取紧凑标题，再逐项读正文，避免一次取回一批大文件。PDF 仅用已经提取的页文本与私有批注；扫描页没有文字不假称已索引。电子书导入节选、白板文字和未确认覆盖的 PDF 均明确标记部分正文。未支持格式保留元信息检索。

命中包含作用域、来源修订与页码/批注/行定位；查询显示前及打开前复查修订和访问权。删除、修改、撤销目录、账号切换后旧结果不能继续暴露正文。PDF 复用既有证据跳转；Markdown 只滚动/短暂标示命中段落，不修改内容；实时编辑器定位选区，阅读库映射导入文本的章节位置。通用资源定位处理异步挂载和 React 重新生成节点。

索引由对象、笔记、正文与批注变更失效；重新打开搜索或应用重新获得焦点会检查外部文件，也可手动刷新。窗口一直获得焦点时，外部新词不保证立即出现，但已有命中必须通过实时修订校验。没有声称实现 OS 全盘 watcher。

边界：最多 3,000 项来源、16,000,000 字符；桌面最多 48,000 个索引块，浏览器预览 450 块。达到限制有明确提示。块为 4,000 字符、1,200 字符重叠，32 块逐批提交。索引是可重建缓存；中止刷新先清空可展示集合，防止旧/部分结果冒充完成。白板节点、EPUB CFI 与任意二进制正文的精确定位尚未实现。

## 实测

环境：WSL2 Ubuntu 24.04 x64，Node 22.13.1 / Rust 1.98.0，分别与仓库要求的 22.23.2 / Windows 1.98.1 有差异。以下不是原生 Windows 验收。

- 69 项受影响组件/路由测试通过；新增和后续集成测试另列机器报告。覆盖真实 IndexedDB 对象/修订、外部目录撤销、PDF 页/批注位置、取消与账号边界。
- Chromium 151 的全局搜索端到端检查通过：输入、过滤、保存查询、点击定位、Esc 焦点返回，以及 1440/960/600/400/320px 最上栏居中。另 6 项既有工作台浏览器测试通过。浏览器用合成资料和模拟桌面 API，不算真实 Tauri picker 或 Windows 窗口测试。
- SQLite 3 项查询测试通过。真实 SQLite 合成语料基准如下；debug 构建，冷查询仅重开连接，未清 OS 页缓存；每档冷 20 次、暖 40 次，不是端到端 UI 耗时或进程内存数据。
