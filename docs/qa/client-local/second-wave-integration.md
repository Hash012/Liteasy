## 隔离恢复启动

`--recovery-profile <absolute-folder>` 在普通数据目录、单实例转交、OAuth、Agent host 和 WebView 初始化之前校验恢复回执。参数缺失、重复或不支持的等号形式都明确失败，不转入普通工作区。恢复目录使用进程锁，不能同时打开两个写入实例。

原生资料根固定为 `<profile>/data`，文献库固定为其中的 `local-library/library`，不能回退到普通库设置或 HOME 下的旧版库。WebView 使用独立数据目录；macOS 的 WKWebView 使用临时浏览器存储作为隔离后备，仍保留原生恢复资料，macOS 行为尚未真机验证。

原生启动信息只提供恢复分区与离线标记，不伪造登录。前端先初始化该信息再创建对象仓库；恢复 `user:*` 对象仍使用原分区。OAuth 与 WebDAV 恢复不启动，自动关联推荐关闭；CSP 和原生命令白名单限制网络与凭据操作，新增未知命令默认不可用。正常工作区保留既有行为。

恢复保留对象记录、历史版本、关联、白板、当前文献库、批注、拥有的附件、已关联外部笔记的副本和阅读位置。预览明确列出排除项：账号/应用配置、插件安装与授权、未关联外部文件、独立产物与旧检查点、旧式独立 Agent/会话 JSON，以及本地批量文件任务日志和撤销状态。**这不是全设备备份，也不会自动重放任务。**

## 集成期间发现的真实问题

- 原生窗口的 Fluent Dialog 默认尺寸覆盖了搜索 CSS，导致结果高度失控；提高局部选择器优先级，限制对话框为视口的 86%，结果单独滚动。Chromium 中验证尺寸与滚动，不以 jsdom 代替布局验证。
- 缓存曾只绑定来源 revision 和块数，标题、分类或定位信息改变后仍使用旧展示；现在绑定规范化索引记录的摘要。来源复验拒绝条目时同步失效 manifest，避免恢复访问后永久漏检；同分区仓库实例更换也重新加载来源。
- 打开 PDF 后，父组件重渲染使批注保存回调身份改变，重复保存又发出索引更新事件，导致搜索反复取消。针对真实触发链补充回归，保存应由内容与身份变化触发，不能由回调身份变化触发。
- 恢复副本曾可能被旧版库自动发现逻辑替代；显式隔离 profile 必须绕过旧库探测与普通 override，保留原库。

## 最终代码与真实窗口验证

最终功能代码提交为 `0fb015ec321a70e98f8696341be72252cfe7d9fd`。完整桌面测试通过 502 个文件、3359 项测试（2 个文件、4 项按既有条件跳过）；之后修改的阅读器/启动集成 21 项和搜索 18 项重新通过。smoke 9 项、生产构建（158 个资源）、Rust 恢复/启动测试与 `--locked --all-targets --no-default-features` 检查通过。全量测试与后续针对性回归分开记录，不声称后续又跑了一次全量。

最终代码构建的真实 Tauri 程序，在合成恢复副本中完成：打开含原批注的 PDF；随后搜索笔记与白板，正常返回且可刷新；打开已恢复的外部 Markdown 副本，追加文字、Ctrl+S 保存、退出并重启，再从全局搜索找到新增文字。原始外部 Markdown 的字节摘要与备份前一致。并发第二实例因 profile 锁明确退出。该窗口实测同时覆盖了先前出现的 PDF 自动保存反馈与搜索取消问题。

相同最终二进制在 GUI 关闭且移除 DISPLAY/WAYLAND_DISPLAY/XDG_RUNTIME_DIR 后，通过授权目录列举与 Markdown 提取；修订冲突、未知授权、越界路径和伪造分区参数分别失败，原文件不变。授权来自合成的现有 FileStore 数据库，不能称作系统选择器授权验收。六页 PDF 的原生选择器自动化未完成，页码恢复的对应证据仍为浏览器与组件回归。

详细命令、日志、二进制 SHA-256、截图位置和未执行项目见 [机器验证报告](second-wave-integration-verification.json)。日志与截图位于本机 `/tmp`，不是永久托管的发布附件。最终干净提交上的契约检查另行记录。
