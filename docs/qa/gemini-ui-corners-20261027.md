# Gemini UI 补充巡检（2026-10-27）

依据 [10 月 26 日设计提示词](../design/gemini-ui-review-20261026.md) 和 [10 月 27 日设计提示词](../design/gemini-ui-review-20261027.md)，继续检查上一轮主框架修正后容易遗漏的条件分支。两份提示词从 `tmp/` 原样移入 `docs/design/`，纳入版本控制。

## 巡检范围与修正

- 使用现有 UI inventory 和边界检查扫描桌面源码；检索原生控件、禁用状态、固定最小宽度、双列布局、视口断点、定位层和装饰伪元素。静态扫描覆盖不等于每个页面都完成了人工视觉验收。
- 登录、创建组织、加入组织、邀请成员、退出组织、查看学术档案、清空档案共七类弹窗接入共享 `ModalSurface`：Fluent 焦点管理、可滚动表单、可换行操作区、统一关闭入口及危险操作样式。关闭后恢复原入口焦点；组织请求进行中阻止重复提交和意外关闭；登录仍允许跳过。
- 统一 Fluent 及现有原生按钮的禁用状态；修正 Combobox/SpinButton 最小宽度造成的窄栏溢出；内联状态提示允许操作按钮换行。模型测试、数据迁移和资产分类表单的失败／忙碌提示接入共享通知样式。
- 图表解析、翻译对照、电子书目录、薄读正文、工作流列表与详情、认知图详情、引用图及资产筛选改为按所属容器宽度重排。翻译语言弹窗使用自己的容器；固定在视口上的选区工具仍使用视口断点。
- 认知图外框、详情栏和阴影改用主题 token；扩展工作台空状态、阅读空状态应用现有浅色层次。保留文档内容颜色、图形画布缩放和真实请求／导出／删除回调。
- 装饰层审查保留 `.pane-resizer::after` 的交互能力：它是拖动分栏的命中区域，不是装饰遮罩，不能机械地加 `pointer-events: none`。

## 回归证据

新增用例在 `products/liteasy/apps/desktop/src/tests/browser/uiRefinement.browser.spec.ts`，沿用现有 `ci:ui-browser` 入口，使用实际产品组件：

- 明暗主题、360px 窗口和放大文字下，弹窗输入、角色下拉、精确提交内容、等待状态、失败后草稿、Tab 焦点范围与 Escape 返回入口。
- 模型高级选项、真实传输层发出的请求内容、HTTP 503 后重试与 SSE 回复、只读结果。
- 1600px 宽窗口中的 320／520px 分栏，验证图注、翻译对照、电子书目录、薄读、工作流详情和认知图布局及操作。
- 分类年份校验与有效保存内容，以及小窗口中的引用图加载、画布和详情。

本地 UI 边界检查通过：读取 1554 个源文件，631 项历史声明／控件仍按精确清单管理；相关脚本测试 15 项通过。`ci:smoke`、`npm run build` 通过。26 项相关浏览器用例通过（资产库首次冷加载超过原有 5 秒等待，未改代码单独复核通过），覆盖原有产品控件、设置、档案、资产库及这次新增分支。截图与运行日志保存在本机 `tmp/ui-corners-20261027-evidence/` 和 `tmp/ui-corners-*.log`，不提交运行生成物。

## 交付边界

本轮没有修改 Rust 宿主、依赖、版本号、语言包或用户手册。未将所有历史原生控件一次性重写，也未将静态扫描表述为所有隐藏状态的人工验收。Windows 安装包由带 `[windows-installer]` 标记的最终推送触发；本地浏览器与前端构建通过不代表 Windows 安装包已构建成功。
