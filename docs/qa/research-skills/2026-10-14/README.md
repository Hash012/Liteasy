## 已实现

- 十个科研方法通过现有 workflow registry 的单个 `liteasy.research.generate-document` operator 执行。方法身份固定为 id/version/packageDigest；未知、缺失或被改写的版本不替换为最新版本。其余十四个目录项未开放执行。
- `$` 菜单选择独立的方法引用；不是上下文 token。精确命令、空提示的默认任务、中文输入法、代码/数学保护、方法移除、单独的保存目标、资料用途与已选范围说明、草稿持久化接入现有 composer/session。
- 从已选 ObjectRef 固定实际文本快照；角色与来源信任分开。说明、契约、模板、预设、用户任务、资料、schema 和输出计入预算。超预算、失效引用和图片输入在请求前阻塞。
- 一个 `research_document` 类型容纳十种 documentKind。严格 JSON 输出、必需章节、引用编号和引文定位校验；最多一次生成加一次同模型修复。语义状态始终 `unverified`。统一正文用于显示、Markdown/既有导出与资源投影。
- 明确 entry/paper owner；原子且不可覆盖的本地输出；同 run/slot 固定 ID；不同正文冲突；保存失败在现有 ArtifactTask 中保留完整 pendingResult；重试保存和回执丢失协调不再生成。已保存结果是投影修复的依据。
- 单个主资产、其他论文项目引用、来源预览、当前读取文本、可编辑笔记副本。旧版本不会随笔记修改而改写。账号切换移除旧研究任务与目录投影；中断模型请求不自动重放。
- 本地目录对单个不可读 JSON 隔离，保留文件并由现有目录状态报告问题。

## 验证边界

本次优先完成可用的本地后端。云端模型调用与 HTTP 产物存储是不同能力；未开放正式 API/PostgreSQL 科研文档保存。H17 的本地 IPC、IndexedDB、恢复、目录、导出和资源链路已接入，HTTP 后端验收未执行。

桌面采用 Rust 1.98.1 的 Linux 检查与受影响测试；这不等于此科研方法提交已通过 Windows Installer。前一批 UI 改动有独立 Installer CI。

默认预设固定为 default；当前未新增预设编辑器。文档标题上限收紧到既有产物接口的 160 字符。M1 图片输入明确阻塞，不自动切换模型。研究过程不会联网检索、执行实验或投稿。

十种方法各三例的自动化测试验证生成结构、修复上限和伪造引用拒绝，共 30 个契约案例；不是 starter SCIENCE 矩阵的人工科研质量评分。充分材料、缺失材料、冲突材料的逐项人工 rubric 与同模型普通提示对照尚未执行，不能据此宣称科研质量提升。

`live-model-smoke.json` 记录一次真实 DeepSeek 调用：使用已配置的开发模型，合成缓存实验材料，1 次请求，2,227 输入 tokens、3,556 输出 tokens（含 2,483 推理 tokens），约 18 秒。服务未返回货币费用，未估算价格。报告仅证明真实调用、结构和引文定位闭环；不是科学有效性背书。没有保存密钥或端点。

`research-skill-selection.png` 为实际桌面浏览器截图。浏览器用例验证选择方法、清除输入中的命令、明确生成动作、持久保存、刷新恢复和移除。

最终验证明细见 `validation.json`。全量回归的唯一失败发现了方法选择被输入更新清空的问题；修复后相关 78 项回归、75 项最终受影响测试以及实际浏览器恢复测试通过。原全量运行仍如实记录为 1 项失败，不将其重标为全量通过。
