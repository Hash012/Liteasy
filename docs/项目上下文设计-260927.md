**优先需要处理的缺口**

1. **P1：长文与混合上下文容易整轮失败。**\
   对象上下文最多接受 100 个引用，默认预算约 6,000 token，按 UTF-8 字节数估算；超限直接拒绝，没有分块补读或部分覆盖结果。论文与笔记混合提交时，会把论文全文转换为对象一起送入这个预算，因此普通长论文、整本 EPUB、大白板都容易触发。此限制针对对象上下文链路，不能等同于所有论文问答路径。\
   依据：[预算检查](/home/tjm/proj/Liteasy/products/liteasy/apps/desktop/src/app/features/context/objectContext.ts:209)、[混合论文提交](/home/tjm/proj/Liteasy/products/liteasy/apps/desktop/src/app/features/assistant/AssistantPane.tsx:1739)。

2. **P1：图片和手绘“可以加入”，但通用上下文里的模型看不到图片本身。**\
   批注捕获会保存图片附件，然而快照只有文本，模型调用传入的也是文本 prompt。图片通常退化为 `attachment:` 链接或替代文字。因此不能把“手绘批注已附加”理解成“AI 已读取手绘内容”。\
   依据：[快照结构与提取](/home/tjm/proj/Liteasy/products/liteasy/apps/desktop/src/app/features/context/objectContext.ts:24)、[实际模型调用](/home/tjm/proj/Liteasy/products/liteasy/apps/desktop/src/app/controllers/agent/createDesktopAgentService.ts:193)。

3. **P2：整板上下文保留成员，未保留完整白板语义。**\
   加入整板会固定白板和成员对象的版本，这是已有能力；但展开时只取成员引用，未加入连线、布局、分组等结构。模型能读卡片文字，却不能据此完整评审白板的关系结构。\
   依据：[白板展开逻辑](/home/tjm/proj/Liteasy/products/liteasy/apps/desktop/src/app/features/resource-filesystem/resourceContext.ts:17)。

4. **P2：资产发现入口不一致。**\
   EPUB/TXT 等阅读文件已保存为 `source.document`，可通过对象 Liteasy Path 解析；但 `@` 对象候选只收录笔记、白板、摘录，没有收录这些阅读文件。用户需要知道另一条入口，才能添加已经存在的资产。\
   依据：[候选过滤](/home/tjm/proj/Liteasy/products/liteasy/apps/desktop/src/app/controllers/useAssistantContextCatalog.ts:97)、[阅读文件对象化](/home/tjm/proj/Liteasy/products/liteasy/apps/desktop/src/app/features/reading-library/readingLibraryRepository.ts:93)。
