# Liteasy 独立产物库设计

**日期：** 2026-08-09  
**状态：** 已确认

## 目标

为桌面端增加独立、可发现的“产物库”，让用户能够：

- 查看并重新打开账号中已保存的 Agent 产物；
- 查看当前设备上的导出历史；
- 通过原生“另存为”明确选择导出位置；
- 打开已导出的文件或在系统文件管理器中定位文件；
- 识别已经移动或删除的导出文件，并安全地清除失效记录。

本设计不改变 Agent 产物的服务端保存协议，不复制已保存产物，也不把用户导出的文件收拢到 Liteasy 私有目录。

## 当前问题

Agent 产物已经保存到账号产物服务，并在启动后恢复到 `artifactCatalog`。应用也会把账号产物投影成来源论文的子项，但 `LibraryPane` 没有消费这些子项，因此关闭产物标签或重启后缺少可靠的重新打开入口。

文档导出目前通过浏览器 `download` 属性下载 Markdown、HTML 和 PDF。用户不能选择明确的桌面保存位置，应用也不记录导出路径，因此没有“已导出”视图、打开文件或定位文件夹能力。

## 方案选择

采用独立活动栏入口，而不是将产物继续附着在文献树或中央产物查看器中。

左侧活动栏增加 Fluent 图标按钮“产物库”，并扩展现有 `LeftRailView`。产物库在左侧紧凑面板中呈现“已保存”和“已导出”两个标签页；产物正文仍使用现有中央产物区域，不在左栏重复渲染。

该方案让账号产物和设备文件各自保持清晰边界，也为后续搜索、筛选和批量管理保留稳定入口。

## 信息架构与界面

### 活动栏入口

- 使用 `@fluentui/react-icons` 中语义匹配的文档集合图标。
- 图标按钮具有可访问名称“产物库”和 Fluent Tooltip。
- 激活后沿用现有左栏宽度、边框、布局 token 和折叠行为。

### 已保存

“已保存”默认激活，直接消费当前账号的 `artifactCatalog`：

- 顶部提供紧凑搜索框，按标题、产物类型和来源论文标题匹配；
- 列表行展示标题、类型、来源论文和保存时间；
- 点击列表行调用现有 `openArtifact(artifactId)`，并在中央产物区域激活对应产物；
- 行尾菜单提供“打开”“重命名”“删除”；
- 生成、重命名和删除操作完成后，列表随 `artifactCatalog` 即时更新；
- 切换账号时先清除旧账号目录，再加载新账号产物；
- 未登录时显示登录提示，不展示其他账号或设备缓存的账号产物；
- 加载失败时显示错误和“重试”，不得把失败状态表现为“暂无产物”。

产物库不复制账号产物内容。查看、重命名和删除继续复用 artifact controller 与 result client，保持 `layout -> controllers -> features` 依赖方向。

### 已导出

“已导出”展示当前设备的导出记录：

- 列表行展示文件名、格式、导出时间和绝对路径；
- 文件存在时提供“打开文件”“在文件夹中显示”“移除记录”；
- 文件已经移动、删除或不可访问时显示“文件不可用”，禁用打开操作，保留原路径和“移除记录”；
- 移除记录只删除 Liteasy 的历史记录，不删除用户文件；
- 进入该标签页时刷新文件状态，执行打开或定位操作前再次检查；
- 设备上没有记录时显示简洁空状态。

应用不会扫描用户磁盘。功能上线前已导出的文件不会被自动发现或导入历史。

## 数据边界

### 账号产物

账号产物仍由现有 `/v1/agent-artifacts` 服务管理。`useArtifactWorkflowController` 负责加载状态、错误状态、重试和目录更新；`ArtifactLibraryPane` 仅消费 controller model 和 actions。

需要为 controller model 增加明确的目录加载状态：

- `idle`：尚未开始或未登录；
- `loading`：正在加载当前账号目录；
- `ready`：目录已加载，包括合法的空目录；
- `error`：加载失败，包含用户可见错误。

controller 提供重新加载当前账号目录的 action。重新加载只替换账号产物，不影响设备导出记录。

### 设备导出记录

新增版本化导出记录仓库，存放在 Tauri 应用数据目录。记录至少包含：

```ts
type ArtifactExportRecord = {
  artifactId: string;
  exportedAt: string;
  fileName: string;
  format: "html" | "markdown" | "pdf";
  id: string;
  title: string;
} & (
  | {
      location: "desktop";
      path: string;
      status: "available" | "missing";
    }
  | {
      location: "browser";
      status: "browser_managed";
    }
);
```

持久化快照使用独立版本标识 `liteasy.artifact-export-history/v1`。仓库按 `exportedAt` 倒序返回记录，并以记录 `id` 作为删除键。快照使用临时文件加替换的原子写入方式，避免应用退出时留下半写文件。

导出记录属于设备，不按账号隔离。记录只包含用户选择的文件路径和产物展示元数据，不包含访问令牌、论文正文或产物完整内容。

## 桌面导出流程

现有 TypeScript 继续负责构造 Markdown、HTML 和 PDF 内容。桌面导出适配器接收建议文件名、格式和内容，并通过 Tauri 宿主完成以下步骤：

1. 打开原生“另存为”对话框，并设置正确扩展名和格式过滤器；
2. 用户取消时返回 `cancelled`，不写文件、不追加记录、不显示成功提示；
3. 用户确认后写入所选路径；
4. 写入成功后追加导出记录并返回完整记录；
5. 前端刷新“已导出”列表，并在产物工具栏显示包含保存路径的成功消息。

文件写入成功但记录写入失败时，界面必须明确说明“文件已保存，但未写入导出历史”并显示文件路径，避免用户重复导出。文件写入失败时不添加记录。

桌面宿主还提供以下能力：

- 列出并检查导出记录；
- 打开记录对应文件；
- 在系统文件管理器中定位记录对应文件；
- 移除记录但不删除文件。

所有命令只操作用户在原生对话框中选择并被记录的具体路径，不接受目录递归删除，也不提供删除外部文件的命令。

## 浏览器开发降级

非 Tauri 环境继续使用浏览器下载，保证组件测试和浏览器开发可用。浏览器无法获得真实下载路径，因此：

- 下载记录使用 `location: "browser"` 和 `status: "browser_managed"`，不包含 `path`，也不伪造绝对路径；
- 不提供“打开文件”或“在文件夹中显示”；
- 成功提示说明文件由浏览器下载设置管理；
- 浏览器记录不是桌面导出历史的权威来源。

桌面安装包必须使用原生另存为流程，不能回退到不可定位的 WebView 下载而仍提示导出成功。

## 状态与错误处理

- 账号产物加载失败：保留明确错误状态和重试按钮。
- 原生另存为取消：安静结束，不显示错误。
- 文件写入失败：显示具体错误，不添加历史。
- 历史写入失败：显示文件已保存及其路径，同时指出历史未记录。
- 打开或定位前文件已失效：更新记录状态为 `missing`，显示“文件不可用”。
- 导出历史快照损坏：隔离损坏快照，返回可恢复错误；不得阻止应用启动或账号产物使用。
- 账号切换：只切换“已保存”内容，不清除“已导出”。

## 组件与职责

- `ActivityBar`：提供“产物库”导航入口。
- `LeftPane`：根据 `LeftRailView` 组合 `ArtifactLibraryPane`，不承载产物业务逻辑。
- `ArtifactLibraryPane`：渲染双标签、搜索、列表、状态和用户命令。
- `useArtifactWorkflowController`：管理账号产物目录的加载状态、重试及现有产物操作。
- `artifactDocumentExport`：生成具体导出格式内容，不负责路径选择和历史持久化。
- 导出 controller/client：编排另存为、刷新历史、打开、定位和移除记录。
- Tauri 导出仓库：执行文件写入、记录持久化、文件探测以及系统打开/定位。

## 测试策略

### TypeScript 单元与组件测试

- 活动栏显示“产物库”图标、名称和激活状态；
- `LeftPane` 能切换到 `ArtifactLibraryPane`；
- 已保存列表覆盖加载、空、失败、未登录和搜索状态；
- 点击产物能够调用打开动作，重命名和删除沿用现有结果；
- 导出取消不添加记录；
- 导出成功刷新历史并显示保存路径；
- 文件失效时禁用打开并允许移除记录；
- 清除历史只调用记录移除，不调用文件删除；
- 浏览器降级继续下载三种格式并显示“由浏览器管理”。

- 原子替换不会暴露半写快照；

- 移除记录不删除对应文件；
- 非记录路径不能通过记录操作被打开或定位；
- 损坏快照返回可恢复错误。

## 非目标

- 不同步导出记录到账号或组织；
- 不扫描或导入功能上线前的导出文件；
- 不在应用内编辑已导出的 Markdown、HTML 或 PDF；
- 不删除用户导出的外部文件；
- 不改变 Agent 产物服务协议或宣称生产服务已经验收；
- 不重构无关的文献库、账号或 Dock 系统。

## 验收标准

1. 用户可从左侧活动栏进入独立“产物库”。
2. 登录用户可看到账号中已有和新生成的产物，并在中央产物区域重新打开。
3. 用户可通过原生“另存为”导出 Markdown、HTML 和 PDF。
4. 成功导出立即出现在“已导出”，包含准确文件路径。
5. 用户可打开文件或在系统文件管理器中定位文件。
6. 文件失效后列表明确标记，应用不崩溃，也不误报成功。
7. 移除导出记录不会删除实际文件。
8. 账号切换不会泄漏其他账号产物，也不会清除设备导出历史。
