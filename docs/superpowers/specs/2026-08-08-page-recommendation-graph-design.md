# 页级相关推荐图优化设计

## 背景

当前薄读页同时提供“概念标记”和“页级关联图”两个按钮。概念锚点由模型生成，页级关联图将每个锚点关联到检索得到的外部论文，并使用确定性扇形布局避免节点遮挡。现有实现已经可靠地区分了相关度和关系可信度：距离表示相关度，边和节点强调表示关系证据。

本次优化合并入口、提高锚点质量、增加全页推荐论文之间的可验证关系，并在保留现有布局作为基线和回退的前提下，引入受约束的力学布局。视觉方向采用“锚点固定的约束力导向布局”和“墨线与淡彩”的手绘关系边。

参考资料为 `docs/reference/graph-vis-0526.pdf`。设计采用其中的力导向、约束松弛、stress 优化和 crossing minimization 思路，但不使用无约束的纯力导向布局。

## 目标

1. 将两个入口合并为一个“相关推荐”三态按钮。
2. 让高价值锚点综合反映内容重要度、证据覆盖、生成期间的可审计证据操作和原文局部引用出处。
3. 在全页范围内展示推荐论文之间经过验证的直接引用、共同被引和共享参考文献关系。
4. 同一锚点的主推荐节点位于锚点同一侧，主关系边在常态图中零交叉。
5. 用边长表达关系远近，用颜色表达关系种类，用透明度表达关系衰减。
6. 使用稳定、克制的墨线与淡彩手绘视觉，同时保持节点文字、键盘操作和关系语义清晰。
7. 新布局只有被客观指标证明不劣于现有布局时才启用，否则自动回退。

## 非目标

- 不展示或持久化模型隐藏思维链。
- 不根据语义相似推断两篇推荐论文之间存在真实关系。
- 不将页级相关推荐图改造成可自由拖拽的独立画布。
- 不改变薄读页面层级“关系网络 / 思维导图”的职责。
- 不宣称开发 API 或生产连接器已经完成生产环境验收。

## 交互状态

“概念标记”和“页级关联图”合并为一个 `相关推荐` 按钮。状态循环为：

```text
0 正文
  -> 第一次点击
1 概念标记
  -> 第二次点击
2 页级关联图
  -> 第三次点击
0 正文
```

- 初始状态不显示概念标记。
- 在概念标记状态点击锚点，直接进入页级关联图并聚焦该锚点。
- 在页级关联图中点击推荐论文进入论文阅读卡。
- `Esc` 每次只返回一层：论文阅读卡 -> 页级关联图 -> 概念标记 -> 正文。
- 切换薄读节点时重置为正文状态，避免继承上一页的空间状态。
- 按钮具有明确的可访问名称、状态和悬浮提示；状态不能仅由颜色表达。

## 锚点评分

### 可审计指标

锚点质量分只使用已有或可持久化的可审计数据：

```text
anchorScore =
  0.35 * normalizedImportance
  + 0.25 * evidenceCoverage
  + 0.20 * evidenceAttention
  + 0.20 * citationProvenance
```

- `normalizedImportance`：模型输出的概念重要度。
- `evidenceCoverage`：独立句级证据数量、证据状态和证据覆盖质量的归一化结果。
- `evidenceAttention`：相关 evidence ID 在生成审计中被搜索、阅读、查看和复核的次数；按页内最大值归一化并设置上限，避免重复调用无限抬高分数。
- `citationProvenance`：锚点支撑证据对应的原文局部是否存在可解析参考文献，以及引用匹配质量。

引用出处是强加权项，不是硬门槛。没有局部引用但确属论文核心方法、原创结论或关键局限的概念仍可成为锚点。

### 选择规则

- 每页选择最多 8 个高价值锚点；有效候选不足时不补造锚点。
- 每个摘要句默认最多保留 2 个锚点，避免局部过密。
- 优先覆盖方法、核心结论、关键结果和局限，避免单一锚点类型占满整页。
- 同分时按正文位置和稳定 ID 排序，保证结果可复现。
- 锚点记录评分分项和简短理由，界面只显示读者可理解的说明，例如“核心方法 · 3 条证据 · 原文有引用”。界面不显示模型、工具调用或内部开发术语。

## 全页推荐论文关系

### 图的范围

论文关系不是按锚点分别计算。系统汇总当前页全部锚点的推荐论文，按 `canonicalPaperId`、DOI、来源 ID 的顺序去重，形成一张全页论文子图。任意两篇当前页论文之间只要存在可验证关系，无论它们属于同一锚点还是不同锚点，都进入该子图。

### 数据结构

```ts
type RecommendationPaperEdge = {
  sourcePaperId: string;
  targetPaperId: string;
  kind: "direct_citation" | "co_cited" | "bibliographic_coupling";
  strength: number;
  directed: boolean;
  provider: "openalex" | "semantic_scholar";
  evidenceRecordUrls: readonly string[];
};
```

- `direct_citation` 必须能验证方向，`directed` 为 `true`。
- `co_cited` 和 `bibliographic_coupling` 必须有实际重合依据及归一化强度，`directed` 为 `false`。
- 语义相似可以影响锚点到论文的相关度，但不得生成论文间事实边。
- 两端必须都在当前页去重论文集合中，关系边才进入 artifact。

### 查询和持久化

- 第二次点击“相关推荐”时先立即显示已有锚点关系。
- 客户端随后按当前页规范化论文 ID 批量查询邻接关系，不逐对发起 `O(n^2)` 网络请求。
- 查询结果按规范化论文 ID 对和关系类型缓存。
- 验证通过的边写入当前薄读节点的可选 evidence 字段，使 artifact 重开后仍可显示。
- 部分提供方失败时保留成功部分；全部失败时保留基础锚点图，不显示推测关系。
- 渐进结果到达后只进行一次稳定重排；不持续抖动或动画模拟。

## 图模型与主归属

同一论文命中多个锚点时仍合并为一个节点。为保证常态图中锚点主关系边零交叉，每篇论文选择一个主锚点：

1. 优先作者亲引或权威精确匹配。
2. 其次选择关系可信度更高的锚点。
3. 再按相关度、锚点评分和稳定 ID 破同分。

常态图只绘制论文到主锚点的主关系边。其他真实锚点关系保留在节点的多锚点标记中，并在聚焦该论文或对应锚点时显示为上层次级边。次级边不参与常态图的零交叉承诺。

## 约束力学布局

### 基线与候选

现有 `layoutAssociationPageGraph` 的确定性结果继续作为基线、候选初始位置和失败回退。新算法不得直接替换基线。

候选布局分为四步：

1. **主归属与侧面选择**：为每个锚点选择左侧或右侧出边区域。
2. **同侧初始排布**：使用现有扇形布局，在该锚点的单一侧面生成初始位置。
3. **受约束力学松弛**：节点斥力、关系弹簧、碰撞力和全页论文关系力共同优化位置。
4. **交叉与质量验证**：计算硬约束和质量指标，决定采用候选或回退基线。

### 同侧硬约束

- 每个锚点计算左右两侧可用面积、邻近锚点密度、预计碰撞数和预计边交叉数。
- 动态规划选择相邻锚点的左右侧组合，使全页交叉、拥挤和总边长最小。
- 同一锚点的全部主推荐节点必须位于所选侧面的同一半平面。
- 出边扇区以水平外法线为中心，限制在约 `+/-55deg`，避免主边上下穿过正文。
- 空间不足时整组换侧，不允许单篇推荐独自翻到另一侧。
- 锚点位置固定，不能被力学模拟移动。

### 力与约束优先级

硬约束优先级高于力学目标：

1. 锚点固定、节点不越界。
2. 节点不重叠、不遮挡锚点文字和芯片。
3. 同一锚点主推荐保持同侧。
4. 常态锚点主关系边零交叉。
5. 强关系保持较短的期望边长。
6. 全页论文间关系作为软弹簧，使强关系论文尽量靠近。

全页论文关系力可以调整同一侧面扇区内的论文顺序和距离，但不能将节点拉出主锚点扇区，也不能破坏主边零交叉。

### 边长

- 锚点到论文的期望边长继续由 `relevance` 决定，相关度越高越短。
- 论文到论文的期望边长由验证后的 `strength` 决定，强度越高越短。
- 所有长度映射设置最小值和最大值，避免强关系节点相撞或弱关系边跨越整个文档。

### 质量门

只有候选布局满足全部硬约束且不劣于基线时才启用：

- 节点越界数为 0。
- 节点重叠数为 0。
- 锚点或芯片遮挡数为 0。
- 同侧约束违反数为 0。
- 常态锚点主关系边交叉数为 0。
- 总体加权交叉数不高于基线。
- 加权 stress 不高于基线允许阈值。
- 布局结果对相同输入完全确定。

任何条件不满足时返回现有基线布局。质量报告只用于测试与诊断，不作为常驻界面文案。

## 边路由与层级

- 锚点主关系边位于最清晰的关系层。
- 次级多锚点边只在聚焦时显示于上层。
- 全页论文间关系边位于主关系边下层，避免抢夺锚点阅读路径。
- 跨锚点区域的论文边优先沿正文外侧曲线路由；局部相近路径可使用轻量束化。
- 边束必须保持端点可追踪，不将不同关系类型合并成无法区分的单线。
- 文献关系边允许存在少量不可避免的交叉，但布局目标会最小化加权交叉数和穿过正文的长度。

## 墨线与淡彩视觉

### 视觉原则

手绘感集中在关系边、节点局部描边和淡彩底层。节点仍使用紧凑 Fluent 2 卡片、清晰排版、4-8px 圆角与低层级阴影，不将工作界面整体插画化。

### 关系色

- 锚点类型：方法使用松石绿，结果使用靛蓝，局限使用低饱和朱红，概念与主张使用中性青灰及相邻可区分色。
- 作者亲引：深绿色实墨线。
- 引用图推导：靛蓝实墨线。
- 纯语义锚点推荐：石墨色短虚线，并明确不表示引用。
- 论文间直接引用：低饱和朱红墨线和小型方向端点。
- 共同被引：灰紫色墨线。
- 共享参考文献：苔绿色虚线。

颜色只表达可命名的类别。关系远近主要控制透明度，关系证据强度轻微控制线宽。状态不能只依赖颜色，线型、方向端点、标签和可访问名称共同表达语义。

### 手绘路径

- 精确几何路径决定端点、命中区域、碰撞与交叉计算。
- 可见墨线由 edge ID 驱动的确定性低频扰动生成，中段轻微偏移，端点保持精确。
- 主关系边可增加一条透明度较低的细复线，模拟重复描画。
- 墨线下叠一层窄而低透明度的淡彩晕染；晕染不扩大交互命中区。
- 同一输入不得产生随机变化，不运行持续动画。
- 聚焦时提高当前路径饱和度和线宽，其他路径降低对比度。

### 透明度与可读性

- 关系越远，边、节点边框和淡彩底层越透明。
- 论文标题和交互焦点保持最低可读对比度，不随距离消失。
- 弱关系的最低边透明度必须通过浅色与深色主题的可见性测试。
- 图例只呈现当前页实际出现的关系类型。

## 组件边界

- `ThinReadingTab`：只负责“相关推荐”状态、当前聚焦和跨模块编排。
- 锚点评分模块：从锚点、句级证据、generation audit 和局部引用映射计算稳定评分。
- 全页论文关系 client/hook：批量获取、验证、缓存和持久化渐进关系。
- 图投影模块：论文去重、主锚点归属和全页关系子图构建。
- 布局模块：基线布局、同侧选择、受约束力学候选和质量评估。
- `AssociationGraphLayer`：渲染节点、精确路径、手绘路径和交互状态，不承担网络请求。
- `AssociationReadingOverlay`：继续负责论文阅读卡和空状态。

依赖方向保持 `layout -> controllers -> features -> shared types / clients`，feature 不导入 layout 或 `AppShell`。

## 兼容与错误处理

- 新锚点评分明细和论文关系字段均为可选。
- 旧 artifact 缺少评分明细时继续使用原 `importance`。
- 旧 artifact 缺少论文关系时只显示锚点推荐图。
- 关系查询失败不清空已存在数据、不产生语义推测边、不阻止打开图。
- 提供方部分成功时保留可验证部分并记录来源。
- 渐进重排不满足质量门时保持当前布局，仅加入能安全路由的关系边。

## 测试策略

### 单元测试

- 三态状态转换和逐层返回规则。
- 锚点评分权重、证据关注度归一化、引用加权、类型覆盖和同分稳定性。
- 全页论文去重和主锚点选择。
- 论文关系方向、强度、来源 allowlist 和两端集合约束。
- 批量关系查询缓存、部分失败和旧数据兼容。
- 同侧选择、扇区约束、节点碰撞和稳定输出。
- 主边交叉检测、加权交叉和 stress 计算。
- 候选布局劣于基线时自动回退。
- 手绘扰动确定性、端点固定和命中路径不变。

### 组件与集成测试

- 单个“相关推荐”按钮替代原两个按钮。
- 第一次点击显示概念，第二次显示图，第三次回正文。
- 点击概念直接进入聚焦图。
- 全页跨锚点论文关系可显示，未验证关系不显示。
- 渐进加载前后状态稳定，失败时基础图可用。
- 主关系、次级关系和论文关系的层级与聚焦行为。
- 论文卡全文、保存条目、拖拽和可访问名称继续工作。

### 浏览器测试

- 桌面、窄窗口和移动视口截图。
- 锚点芯片与正文实际位置漂移小于现有阈值。
- 节点重叠、锚点遮挡和主边交叉均为 0。
- 每个锚点的主推荐节点全部位于同一侧。
- 跨锚点的全页论文关系可见但不遮蔽主路径。
- 手绘墨线、淡彩和关系端点实际渲染且非空白。
- 键盘聚焦、`Esc`、可访问名称和非颜色状态表达。

桌面改动完成后运行受影响测试、完整 `npm test` 和 `npm run build`。

## 实施顺序

1. 合并按钮并建立三态交互，迁移现有测试。
2. 增加可审计锚点评分和引用出处加权。
3. 增加全页论文关系契约、批量查询、验证、缓存与持久化。
4. 抽出图投影和主锚点归属。
5. 在现有布局之上增加同侧选择、受约束力学候选和质量门。
6. 增加全页论文关系力和低层级边路由。
7. 启用 H2 墨线与淡彩渲染。
8. 完成响应式、可访问性、浏览器截图与回归验证。

每一步保持可单独测试和回退。新算法不会在缺少质量证据时覆盖现有有效算法。
