# Liteasy 文献推荐、关键词标签与全文获取

日期：2026-10-01。状态：功能已实现，人工评测与 Windows 实机发布验收待完成（[实现记录](../../agent-dev/2026-10-02-personalized-recommendations-implementation.md)）；代码基线 `cb47fbe7`（桌面端 0.1.27）。

## 1. 目标与现状

推荐应回答：**围绕这份文献，以及我在其中提出的问题，接下来值得读什么？** 输入包括论文、电子书、Markdown、网页资料及其批注、关联笔记，用户画像作为补充。推荐结果必须能查看详情、打开来源；存在可获取的 PDF 时能保存并打开阅读。

现有桌面推荐已经使用题名、摘要和主题，并非只有文件名；但 `useLocalRecommendations.ts` 主要接受 `Paper[]`，`recommendationPersonalization.ts` 主要按画像关键词少量调序，尚未统一利用资产及批注。`development/dev-cloud/payloads/recommendationPayloads.mjs` 已有 BM25、向量分数与 RRF 融合的开发实现，可提取算法及测试用例，不把开发服务作为桌面或正式 API 的依赖。

网站入口仍依赖普通 `target="_blank"` 链接。全文获取已有原生 Rust 请求、开放地址发现和导入流程，但可用性主要来自元数据，部分失败最终表现为“没有 PDF”。因此 Windows 打开失败的实际原因仍需复现，不能只归因于浏览器 CORS，也不能把存在下载代码视为下载已验收。

## 2. 首先修复打开与下载

- **单击**在底部信息栏显示完整题名、作者、摘要、推荐依据；**双击或 Enter**在中间栏打开文献详情。详情先使用已有元数据，补充请求失败不阻止页面出现。网站按钮通过统一 `ExternalNavigation.open()` 调用 Windows 系统浏览器，失败提供具体错误与复制链接；不依赖出版社允许 iframe 嵌入。
- 将现有全文链路拆成 `发现地址 → 探测 → 下载 → 导入`。各阶段返回结构化结果，保留来源、最终地址、HTTP 状态和耗时，诊断记录移除密钥。按 DOI、arXiv ID 等身份标识合并版本，不能下载一个题名相似的文件就算成功。
- 地址来源覆盖现有 arXiv、仓储、出版社 `citation_pdf_url`，补充 OpenAlex 的 `has_content.pdf` / `content_urls`。OpenAlex 内容接口需要 API key，并按用量计费；配置适配器后才启用这一来源。公共全文不要求登录 Liteasy；凭据只发送给对应服务，不能随跳转传给出版社。[OpenAlex 全文接口](https://help.openalex.org/access/fulltext/)
- 统一状态：`unknown / checking / available / unavailable / blocked / error`，附 `checkedAt`、原因和来源。元数据声称开放获取只代表候选；成功取得符合 PDF 特征的响应片段才能标记 `available`，仍需下载后完整校验。探测优先当前可见条目，并发最多 3；采用有字节上限的 GET，服务忽略 Range 时及时中止，不能为筛选自动下载整篇。
- “可下载”筛选展示已验证条目，同时显示“仍有 N 项待检查／M 项检查失败”和检查、重试入口；不得把超时、403、429、登录页、HTML 冒充 PDF 都缓存成永久无全文。成功地址设有效期，下载失败重新解析一次。
- PDF 在 Rust 侧流式写入临时文件，支持取消、大小上限和进度；校验文件、计算哈希后，复用现有文献库去重与导入语义。保留用户选择目录及默认 `Download`，成功后可直接阅读。原生 IPC 返回文件句柄或导入回执，避免整篇 PDF 以 Base64 在 WebView 内重复占用内存。

验收区分“来源无开放 PDF”和“应用获取失败”；不能承诺所有推荐都有开放 PDF，但已知开放样例必须真实下载成功。

## 3. 从资产、批注和画像构建推荐输入

新增 `RecommendationContext`，通过统一资源适配器读取，不在推荐组件内各写一套 PDF、电子书或笔记解析器：

| 输入视图 | 使用内容 | 处理规则 |
| --- | --- | --- |
| 文献 | 正式题名、摘要、作者、标识、学科、目录；必要时相关段落 | 缺少题录时先提取或获取；电子书、笔记无需 DOI 也能参与，文件名不能作为唯一主题依据 |
| 阅读关注 | 用户批注、被引用原文及所在小节、显式关联笔记 | 按锚点去重 PDF／阅读模式中的同一批注；用户问题权重高于单纯划线；引文不等于用户赞同 |
| 个人背景 | 已确认的研究方向、项目、方法和熟悉程度 | 复用结构化画像；待确认记忆不参与；回答口吻偏好不直接当作研究主题 |

每条输入保留 `liteasyPath / revision / anchorRef / provenance`。只读取当前选择及明确关联的资产，先摘要后局部内容，不因刷新推荐扫描整座 Obsidian 仓库。白板从卡片内容和显式关系投影，坐标接近不能推断研究关联。没有文本的资产显示可补充描述，不伪造语义。

文献、批注、画像分别建立检索视图，不能拼成长提示词后只生成一个向量。关联笔记更新、批注删除、画像修改或账户切换时，使对应缓存失效；用户可以关闭“结合批注”或“结合画像”。

## 4. 技术选型与排序流程

**本地 SQLite FTS5 + sqlite-vec，接入独立的 Embedding Provider。** 现有 Rust 已使用 `rusqlite` 的 bundled SQLite；FTS5 提供 BM25，sqlite-vec 可通过 Rust crate 静态编译接入，无需用户另外部署数据库服务。首版使用余弦距离 KNN，不把它描述为已具有 HNSW 索引。依赖锁定版本，并先验证 Windows 编译和 FTS5 能力。[SQLite FTS5](https://www.sqlite.org/fts5.html#the_bm25_function)、[sqlite-vec Rust 接入](https://alexgarcia.xyz/sqlite-vec/rust.html)、[KNN 查询](https://alexgarcia.xyz/sqlite-vec/features/knn.html)

向量数据库负责检索已入库的内容，**互联网新论文仍要由文献供应商召回**。完整流程如下：

1. **召回**：从确认后的题录生成主题／方法查询，结合引用关系；另建针对批注问题的查询。合并供应商结果、本地缓存及本地相关资产，按标识去重，首版每轮至多 200 个候选。多文献选择分别分配预算，不能只截取前两篇。
2. **混合匹配**：每种输入视图分别用 BM25 与向量相似度排序，再做加权 RRF（按名次融合，避免直接相加不同量纲的分数）。文献／批注／画像初始权重为 `0.55 / 0.30 / 0.15`，缺项归一化；这些是待评测的默认值，记录在版本化策略中。
3. **主题约束**：画像不能把与当前文献、批注问题均无关的论文提升到前排。普通风格保留主题相关性门槛；跨域模式可依据相同方法放宽，但须展示实际关联。Cicada 的数据库论文不能因为同名词被昆虫论文占满。
4. **重排与多样性**：优先上线可解释的混合排序；支持可选批量 reranker 对前 30 项进一步判断。最后用 MMR 抑制近重复结果，并对前沿／经典风格施加有限的时间、引用关系加权。收藏、下载是弱正反馈；忽略一篇只影响该条目，不自动判定用户讨厌整个领域。
5. **可追溯解释**：返回具体匹配主题、批注锚点和画像条目，形成“回应你关于事务排序的批注”等依据。沿用 `rankingFusion`、`scoreComponents`，增加可选的视图贡献与证据引用，不把向量相似度显示成虚假的“相关概率”。

Embedding Provider 支持用户配置的兼容接口或本机多语言模型服务，先探测能力、维度和输入限制；聊天接口可用不代表支持 embeddings。未配置时仍提供 BM25、题录与批注词项匹配，已存在且模型一致的向量可继续使用。模型更换后按新空间重建，不能混算维度相同但模型不同的向量。

索引是可重建缓存，按账户／工作区隔离，以 `资源路径 + 修订 + 片段 + 模型指纹 + 分段器版本` 标识记录；保存候选摘要和按需片段，不复制全部资产正文。后台增量、批处理、限制队列与内存，退出可恢复。索引迁移失败回退词法检索，不影响原文件，默认不加入 WebDAV 同步。中文采用显式分词与术语归一化，不能假设默认 FTS 分词器自动解决中文检索。

原始批注与画像默认本地处理；使用远程 embedding／reranker，或将个性化内容加入外部检索时，在设置中明确发送范围。密钥沿用凭据存储，索引、解释和日志不保存密钥。

## 5. 推荐列表与关键词

- 条目使用最多两行题名，日期靠右；下一行显示 **3 个彩色圆角关键词 + `+N`**。从 `LibraryTagChips` 提取不依赖文献库数据结构的 `ResourceTagChips`，两处共用 Fluent 主题、字号、间距和悬浮提示。
- 关键词优先使用来源提供的主题与关键词；不足时从题名／摘要抽取短语，按 TF-IDF 与摘要语义相关度重排，归并缩写、同义词与中英文别名。无 embedding 时使用词法结果。每个标签保留来源，不能凭文件名或让模型无依据扩展学科。
- 稳定颜色区分主题、方法、对象，标签本身有文字，深浅模式均可辨认。悬浮显示完整名称及来源；点击筛选，`+N` 展开。标签和操作按钮阻止事件冒泡，避免误触打开或下载。
- 作者、摘要、完整推荐依据放在底栏／详情页；默认列表不重复长段理由。详情中的批注、关联笔记使用可点击的 `liteasy://` 链接，支持继续加入 AI 上下文。
- 搜索同时覆盖题名、作者与关键词；保留年份、风格、已收藏和全文状态筛选，提供“一键清除筛选”。下载状态与推荐相关度分开表达，不能为了看起来可下载而丢弃重要文献。

## 6. 模块接入与交付顺序

下表路径除另有注明外，均相对 `products/liteasy/apps/desktop/`；功能文件的简写相对 `src/app/features/`；“新增”为计划模块。

| 模块 | 复用入口与增量职责 |
| --- | --- |
| 资源上下文 | `src/app/features/resource-filesystem/agentAsset.types.ts`、`paper-anchors/`、`profile/profileMemory.ts`；新增 `recommendations/recommendationContext.ts`，只做推荐投影与修订追踪 |
| 检索基础设施 | 新增 `src/app/features/semantic-index/` 与 `src-tauri/src/semantic_index/`，封装索引生命周期、向量提供商和检索；UI 不接触 SQL |
| 排序核心 | 新增仓库级 `products/liteasy/packages/recommendation-core/`，提取开发实现中的纯排序逻辑与回归样例；桌面及开发服务使用同一版本，正式 API 按需接入 |
| 推荐编排 | 现有 `src/app/features/recommendations/`、`src/app/controllers/useRecommendationLibraryController.ts`；串联召回、排序、详情、反馈和导入；`AppShell` 只组合入口 |
| 打开与全文 | 现有 `src/app/features/paper-services/paperPdfResolver.ts`、`paperServiceTransport.ts`、`src-tauri/src/paper_services.rs`；新增统一外链入口，分离探测与原生下载任务 |
| 视觉组件 | 现有 `src/app/features/library/LibraryTagChips.tsx`、`recommendations/RecommendationList.tsx`；提取共享标签组件，沿用现有 Markdown 和资源导航能力 |

按五步交付，每步可独立验证：**打开与下载闭环 → 通用资产／批注输入和标签 UI → 本地索引与 embedding → 混合排序及画像联动 → 质量评测与 Windows 实机验收**。旧推荐缓存新增字段均可缺省；旧开放获取布尔值迁移为待探测，不直接认定可下载。资产数据仍以现有仓库为准。

最低验收：

- Windows 上双击进入中栏详情、网站按钮实际唤起浏览器；至少覆盖 arXiv、PMLR、出版社跳转的开放样例，下载到所选目录且能阅读。另用固定响应测试 403、429、超时、假 PDF 和取消，不能都变成“暂无全文”。
- 固定候选集验证 Cicada 数据库论文不被昆虫结果污染；Markdown／电子书可作为输入；同一文献加入不同研究问题的批注，前列推荐出现有依据的变化。删除批注、禁用画像、切换账户后结果正确失效。
- 建立至少 30 个人工标注查询，包括论文、非论文、批注与画像组合；比较当前基线、词法、混合、混合加画像的 nDCG@10 与明显离题率。目标 nDCG@10 相对提升至少 10%，离题率不增加；未达标不默认启用新排序，不能仅凭几个漂亮示例宣布改善。
- 性能验收目标：指定 Windows 基准机、1 万资产／5 万片段、固定 768 维向量，热索引检索与融合 P95 小于 500ms（不含网络及向量生成），检索新增峰值内存小于 200MiB；索引、供应商请求和下载均可取消，不阻塞阅读与点击。记录硬件、耗时与峰值，超预算先限制索引工作集，再评估其他向量后端。
- 实施期间按仓库 `AGENTS.md` 做受影响测试、构建和契约检查；Windows 原生外链及下载用真实桌面环境验收，安装包交付另确认完整 Installer CI，不能用浏览器预览或模拟 HTTP 成功代替。
