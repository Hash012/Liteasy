# 结构化产物、统一文本显示与论文锚点

本轮解决生成演示文稿命令进入普通问答、结果缺少可展示正文、流式过程重复保留大对象，以及来源在跨视图收藏后丢失的问题。实现范围是统一资源设计中的产物读写入口、正文显示基础组件和论文来源实体；完整资源目录与全部 provider 仍按设计文档分期推进。

## 生成路径

聊天中的生成命令通过 `AgentPublicApi` 进入主 Agent 和实际 SDK specialist 子任务。包含笔记、批注等 `ContextRef` 的产物请求也走该路径，普通对象问答仍保留原有处理方式。`生成PPT` 等中文连写可以识别；“如何制作 PPT”、否定生成等普通讨论不会误启动任务。

演示文稿和大纲由模型返回 `liteasy.authored-artifact/v1`，分别包含幻灯片正文/备注/来源或层级节点。运行时校验字段、非空正文、父子关系、深度和允许引用的来源，格式错误最多修复一次。新演示文稿缺少合格 slides 时失败，不再用旧模板伪装成功。旧产物的展示兼容仍保留。

生成结果经 `createArtifactResourceService.saveArtifact` 保存到原有 `liteasy.agent-artifact/v1` 记录。来源对象引用和论文锚点随正文持久化；原生文件采用 `liteasy.authored-resource/v1`，`content` 保留创作结构，`sources` 保留完整论文实体和 ContextRef，Markdown 逐页、逐节点展示可读出处并附引文索引。相同正文没有新增第二套存储。

模型不取得任意系统文件权限，也不会通过生成正文直接执行写文件工具；主 Agent 委派创作，领域服务校验后完成保存。保存期间无法取消已经进入存储的工作；成功回执后发生取消仍承认写入完成。切换账户后的旧结果不发布到新账户界面，明确提示已保存在切换前的位置。

## 显示与来源

`MarkdownContent` 是应用内唯一的 `ReactMarkdown` 基础管线，提供 GFM、KaTeX、Mermaid、图片、链接和基础样式。聊天、薄读、批注、OCR Markdown、Notes、对象、帮助、工作面板、脑图标签及幻灯片复用它。领域适配器只处理来源定位、附件解析、已净化 OCR 表格等差异；编辑器保留各自输入行为。

Mermaid 按需加载，流式正文完成后再布局，过大的图表保留代码显示。幻灯片只挂载当前页，备注按需展开。图片使用受限来源解析和懒加载；默认不执行原始 HTML 或脚本链接。基础层出现渲染错误时保留可读正文，不让整页卸载。

`PaperAnchorEntity` 将证据身份、论文定位、摘录快照和固定下置出处呈现放在一个版本化实体中。显示标题与页码，点击回到原论文；已知证据标识转换为可读出处，未知标识显示“来源待关联”，不会伪造定位。代码示例保留原样。

来源实体在聊天、产物、对象、Notes、上下文快照及文件投影间传递，保存聊天或薄读片段时保留原始偏移、提取器和文档标识。普通对象问答也返回原始实体；缺页码的引用继续呈现原文摘录，禁用跳转。用于生成的来源 ID 仍是机器引用，显示组件不直接展示这些 ID。

## 已定位的内存放大

- 相同产物目录和 tabs 不随每个 token 重发、重写；200 条 PPT 进度的回归中，全量目录写入从 200 次降为 0 次。
- 恢复存储每个 scope 只保留正在写入和最新待写状态；阻塞存储期间的 200 次更新合并为初始与最终两次写入。
- 任务恢复只保留本次选中论文的文本；完成后释放恢复上下文和流式预览副本。
- 重复累积的公开推理事件按同一 activity 合并，保持实时推送和递增事件序号，避免持久状态的平方级增长。
- 子任务预览使用有界缓存；PPT 进度只保留正文尾部。模型接收端对 UTF-8 正文、推理、单帧、累计数据和帧数设限，超限失败并释放浏览器 reader 或取消原生请求。

正文上限为 2 MiB、推理 256 KiB、SSE 单帧/残余 1 MiB、NDJSON 单帧/残余 4 MiB、累计数据 16 MiB、50,000 帧。结构化创作还有最多 40 页或 1200 个大纲节点、输入来源 180,000 字符及结果 600,000 字符的限制。超限会明确报错，不截断后伪装完整。

这些是代码和确定性回归验证的内存增长来源。本轮没有复现用户 Windows 上的原始进程内存耗尽，不能认定它们是该故障的全部原因。

## 验证与边界

使用 Node.js 22.23.2 运行桌面单元/集成测试和生产构建。受影响测试覆盖真实 SDK 委派路径（注入模型传输）、格式修复与失败、对象来源生成/保存/重开、引用跨对象/Notes 保存、资源 scope/版本/字节边界、取消与迟到结果，以及存储和流式内存增长回归。

最终桌面测试为 364 个文件通过、2 个文件跳过，共 2495 项通过、4 项跳过；生产构建和 152 项资源文件检查通过。原有主包体积提示仍存在。文献编辑测试补充真实焦点进入步骤，避免 jsdom 中菜单恢复焦点时把编辑弹窗暂时标成隐藏。

共享契约的另一消费者 `development/dev-cloud` 全量 340 项通过。验证中固定了旧身份迁移测试的时间，并关闭重排测试未提供桩的额外在线来源，避免日期过期和真实网络耗时影响断言；未修改开发 API 的业务逻辑。

Chromium 独立 fixture 验证实际幻灯片中的表格、公式、Mermaid SVG、图片加载、论文出处点击、切页和备注，未出现 pageerror。测试数据用于验证渲染和流程，不能替代真实模型生成质量或 Windows/Tauri 实机验收。

本次提供 Liteasy 原生 `.slides.json`、`.outline.json` 和 Markdown 文件表示，尚未新增二进制 `.pptx` 导出。资源适配器仍依赖旧服务的全量 `list`，其应用层分页不等于后端流式或分页读取。旧存储没有不可变历史字节，版本不匹配返回不可用，不拿新正文冒充旧版本。更多 provider、资源目录事务和跨设备同步不属于本次完成范围。
