# Liteasy 用户工作台 UI 与交互设计方案

## 1. 文档目的

本文档用于把 Liteasy 当前用户端工作台的视觉方向、账号交互、三栏布局、未登录退化逻辑和组织入口行为正式定稿，作为后续界面实现与交互实现的直接依据。

本文档基于以下已确认文档继续细化：

- `docs/Liteasy_功能与UI设计文档1.0.md`
- `docs/Saas/Liteasy_SaaS纠偏设计与调整方案.md`

本文档不负责描述完整云端架构，也不替代实施计划；它只负责用户工作台层的 UI 与交互规则。

## 2. 总体定位

Liteasy 用户端仍然是一个桌面优先的研究工作台，但它的体验目标不是“后台系统”或“工程调试工具”，而是：

- 现代
- 简洁
- 学术
- 柔和
- 有秩序感

工作台应让用户感到自己在一个稳定、长期可使用的研究环境中，而不是在一组漂浮的演示卡片中穿梭。

## 3. 视觉方向

### 3.1 已确认方向

视觉方向采用 `B1` 方案。

该方向的核心特征是：

- 保留 VSCode 式工作台秩序
- 降低工程工具的冷硬感
- 提升学术阅读产品的柔和感与稳定感
- 不依赖渐变建立设计感
- 依赖结构、比例、留白、边界和层次建立设计感

### 3.2 明确排除项

以下方向不再采用：

- 强烈的科技渐变
- 大量悬浮卡片式布局
- 过重的“后台管理系统”视觉感
- 用颜色装饰代替结构秩序

### 3.3 视觉原则

1. 左中右三栏应属于同一个连续工作台，而不是三个浮在页面上的独立模块。
2. 主要层次通过边界、分隔线、留白和比例建立，而不是通过阴影堆叠建立。
3. 色彩基调应偏暖灰、纸面色、柔和中性色，避免过冷和过艳。
4. 设计感必须来自秩序，而不是装饰。

## 4. 工作台结构

### 4.1 基本布局

用户主界面保留四段式结构：

1. 顶部栏
2. 最左侧窄 `Activity Bar`
3. 主三栏工作台
   - 左栏
   - 中栏
   - 右栏

其中最左侧窄栏不计入主三栏比例。

### 4.2 主三栏默认比例

主三栏默认比例已确认如下：

- 左栏：`24`
- 中栏：`52`
- 右栏：`24`

即默认比例为：

`24 / 52 / 24`

该比例用于强调：

- 中栏是阅读与产物展示主区
- 左栏和右栏是辅助区
- 但左右辅助区仍然保留足够操作空间

### 4.3 中栏优先原则

中栏必须是主视觉中心，并且在布局策略上具备最高优先级。

这意味着：

- 中栏默认最大
- 拖拽调整时，中栏不允许被压缩到不适合阅读和展示产物的程度
- 所有布局策略都必须优先保障中栏可读性和产物展示空间

### 4.4 拖拽调整

主三栏采用百分比布局，并支持拖拽分隔条调整。

调整规则如下：

- 左中之间可拖拽
- 中右之间可拖拽
- 调整结果以百分比方式存储
- 不使用固定像素宽度作为长期布局记忆方案

### 4.5 布局记忆

工作台应记住用户上次使用的三栏比例。

推荐行为如下：

- 默认第一次进入使用 `24 / 52 / 24`
- 用户拖拽后保存布局
- 下次打开恢复上次布局
- 双击分隔条可恢复默认比例

### 4.6 左右栏折叠

左栏和右栏都支持折叠。

折叠规则如下：

- 折叠后不完全隐藏
- 折叠为细边栏
- 细边栏中保留明确的展开入口
- 不采用悬停才出现的隐藏式方案

## 5. 顶部栏与账号区

### 5.1 顶部栏作用

顶部栏负责三件事：

1. 品牌识别
2. 账号状态
3. 云端能力状态反馈

### 5.2 顶部状态图标

顶部只需要一个小图标来向用户反馈状态。

该图标表达的不是“浏览器在线/离线”，而是：

- `云端能力状态：可用`
- `云端能力状态：不可用`

判断逻辑可由实现层综合以下条件得到：

- 是否联网
- 是否已登录
- 云端控制平面是否可达

但这些实现细节不应暴露给用户。

### 5.3 账号文案原则

用户不应看到“开发云”“切端点”“控制平面地址”这类开发态语义。

顶部账号区只应表达：

- 当前是否已登录
- 当前是否处于本地阅读器退化状态
- 登录后哪些能力会自动恢复

## 6. 登录与首次启动

### 6.1 默认启动状态

用户默认进入软件时，应处于 `未登录` 状态。

未登录并不阻止使用软件。

### 6.2 首次启动登录面板

每次在 `未登录` 状态启动软件时，默认自动弹出同一个轻量登录面板。

该面板支持：

- `一键 Demo 登录`
- `跳过，进入本地阅读器`
- `不再提醒`

### 6.3 登录面板统一原则

所有登录入口都统一打开同一个轻量登录面板。

不再允许出现：

- 一个顶部登录面板
- 一个组织页单独登录页
- 一个推荐区单独登录流程

统一入口有利于后续把 Demo 登录平滑演进为正式账号体系。

### 6.4 路演版登录策略

路演版不采用自动登录。

理由如下：

- 要和未来真实登录环节保持一致
- 便于后续基于同一入口继续深化账号功能
- 不把路演专用逻辑硬编码成产品主路径

### 6.5 未登录后的后续行为

用户如果跳过登录，则进入退化后的本地阅读器。

之后：

- 顶部持续保留登录入口
- 未登录时不强制再次弹登录
- 组织、推荐、收藏等云端能力入口提示登录后可用
- 这些入口不自动强弹新的独立登录流程，而是复用同一个轻量登录面板

## 7. 本地阅读器退化模式

### 7.1 产品定义

当用户满足以下任一条件时，产品退化为本地阅读器：

- 未登录
- 离线
- 云端当前不可用

在这种状态下，产品不应表现为“坏了”，而应表现为：

- 云端能力暂不可用
- 本地阅读与本地文献库仍可正常使用

### 7.2 统一表达原则

所有退化态入口应统一收口为：

- 当前已退化为本地阅读器
- 相关云端能力暂不可用
- 联网并登录后将自动恢复云端能力

不应各自使用互相冲突的话术。

## 8. 左栏结构与未登录行为

### 8.1 左栏结构

左栏保持三段结构：

1. `我的文献库`
2. `收藏`
3. `关联推荐`

### 8.2 未登录时的左栏策略

未登录时，不隐藏 `收藏` 和 `关联推荐`。

它们应保留位置，但进入灰态 / 锁定空态。

理由如下：

- 保持界面结构稳定
- 让用户知道该能力存在
- 明确登录后可用，而不是让用户误以为功能不存在

### 8.3 本地文献库

未登录时：

- `我的文献库` 正常可用
- 本地阅读能力正常可用
- 本地工作区、选中文献集、导入前的基础工作流正常可用

这部分是退化为本地阅读器后仍保留的核心能力。

## 9. 组织入口与未登录状态

### 9.1 组织入口处理

未登录点击 `组织` 时，不直接强弹登录。

应先显示组织能力说明页，并在页内提供登录入口。

### 9.2 组织说明页作用

组织说明页应向用户清楚表达：

- 登录后可用哪些组织能力
- 组织共享文献库是什么
- 为什么当前不可用
- 提供统一登录入口

这样既不打断用户当前节奏，也不会把组织入口做成“点了就报错”。

## 10. 推荐、同步与云端能力入口

### 10.1 推荐

未登录或云端不可用时：

- 不展示云端推荐结果
- 以锁定空态提示登录后可用
- 明确当前处于本地阅读器模式

### 10.2 收藏

收藏属于用户云端私有长期数据。

因此未登录时：

- 收藏区保留位置
- 但不展示真实云端收藏
- 提示登录后可用

### 10.3 文献元数据同步

未登录或云端不可用时：

- 设置页同步区不应表现为异常崩坏
- 应稳定显示当前已退化为本地阅读器
- 并明确文献元数据同步当前不可用

## 11. 右栏助手

右栏保持统一会话入口。

在退化状态下，右栏仍可作为本地阅读器中的解释与命令入口使用，但涉及云端能力的命令必须：

- 明确提示当前不可用
- 不暴露调试式概念
- 保持统一登录面板入口

右栏不应再承担开发态端点切换或内部调试入口。

## 12. 视觉与交互的实现约束

后续实现本方案时，应遵守以下约束：

1. 不新增用户可见的开发态端点切换 UI。
2. 不让左中右三栏继续表现为漂浮卡片式结构。
3. 不用大面积渐变营造“设计感”。
4. 中栏始终维持主视觉中心。
5. 所有登录入口统一到同一个轻量登录面板。
6. 退化模式统一表达为“本地阅读器”，不再各说各话。

## 13. 结论

本方案已经明确了 Liteasy 用户工作台最核心的产品层规则：

- 工作台结构是什么
- 中栏为什么必须最大
- 左右栏如何拖拽与折叠
- 登录如何进入
- 未登录如何退化
- 组织、推荐、收藏、同步在未登录时如何处理
- 顶部图标究竟表达什么

这些内容已经足够进入下一步实施计划与界面实现。
