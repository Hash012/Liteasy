# WebDAV 分类同步

本次把原先仅包含 PDF 与论文伴生 JSON 的同步协议扩展到 Liteasy 工作数据。连接方式仍然是用户自己的 WebDAV，兼容坚果云缺少强 ETag 的现有传输策略。

## 设置与默认值

| 选项 | 默认 | 内容 |
| --- | --- | --- |
| 文献与本地文件 | 开启 | 文献库内的非隐藏普通文件，包括 PDF、电子书、Markdown、图片等，以及独立题录 |
| 论文批注与阅读产物 | 开启 | 论文伴生数据目录中的批注、阅读产物等 |
| Liteasy 笔记、白板与产物 | 开启 | 对象记录、不可变版本、关联附件、笔记目录、Canvas 文件及产物目录 |
| AI 对话历史 | 开启 | 对话快照，不恢复运行中的 Agent 任务 |
| 偏好设置与用户画像 | 开启 | 主题/字体、模型连接配置、推荐设置、画像记忆、研究行为画像和库图标 |
| 外部链接目录 | 关闭 | 已授权连接的目录/文件及其对象投影，例如 Obsidian Vault；保留相对层次 |
| API key | 关闭 | 已配置模型和论文服务的系统凭据，独立加密 |

关闭类别只是暂停传输，不删除远端或抹除该类别的历史比较基线。重新开启后继续三方比较。本次是类别级选择，尚非逐个外部目录开关。外部目录不上传 `.obsidian`、`.git` 等隐藏内容，也不遍历符号链接或 Windows 目录联接。

API key 必须额外设置至少 12 字符的同步口令。各设备使用同一口令，口令仅保存在系统凭据库；PBKDF2-HMAC-SHA256（210,000 轮）派生 AES-256-GCM 密钥，随机盐与 nonce。加密包不会因为普通重复扫描而随机变化。明文密钥不经过渲染器或写入同步目录；登录 token、WebDAV 密码、MCP token 不纳入同步。缺失的密钥条目不删除另一设备现有凭据。

## 数据与恢复

- Manifest 升至 v2，读取兼容 v1。旧应用应拒绝 v2 而非覆盖它；参与同步的设备需要升级。
- 应用数据在文献库 `.liteasy/sync-data/<类别>/<账号哈希>/` 生成逻辑快照。SQLite 使用正常查询与事务导出/恢复，绝不复制活动 WAL 数据库。
- Liteasy 自有对象与外部绑定对象分别导出。附件按记录引用收集，不把外部对象内容夹带到默认的自有笔记同步里。
- 本地文件继续按原有文件协议同步；对象记录组、每个连接目录、对话历史、偏好分别是一个比较单位。两端均编辑时由用户选择版本；界面以类别名称标识整组冲突。
- 下载的工作数据先持久化到恢复队列，下次启动、该账号的编辑器加载前应用。登录账号在原生 OAuth 身份恢复后载入自己的分区；原生离线 `local` 与浏览器画像 `guest` 映射一致。
- 重启前继续编辑时，恢复比较会保留最新本地数据，并退回该条目的比较基线，下次同步出现冲突，而不是自动覆盖任何一端。偏好按键比较，保留下载后修改过的本机设置。
- 外部授权路径不随快照传输。新设备把目录恢复到 Liteasy 数据目录的 `synced-external`，白板恢复到 `synced-boards`，注册可用的本地授权；已有授权继续使用本机路径。
- 原版本、下载副本分别保存在 `.liteasy/webdav/recovery`、`incoming-data`。恢复出错提供设置页提示，保留内容；不会因此 panic。停止同步不删除这些恢复材料。

## 边界与验证

同步不是整个 AppData 的镜像，不传缓存、OAuth 会话、正在执行的任务、其他账号对象或未经选择的外部文件。目录/对象快照有 128 MiB 级大小限制，普通文件维持 256 MiB 上限；超限会报告错误，尚未实现大型 Vault 分块快照。未移除目录授权或删除整个目录的本地文件来追随远端解绑。

本地验证覆盖：设置分类与口令交互、凭据/其他账号排除、首次账户恢复、对象事务回滚及不可变版本、目录层次/图片/Canvas 跨目录恢复、外部编辑冲突、开关关闭不删除及重新开启的三方冲突、加密往返/错口令/篡改、下载后本地编辑的基线回退。另运行桌面 smoke、生产构建、Rust 测试与 locked 检查，提交后运行现有 contracts 门禁。

验证环境是 Linux；未使用用户坚果云凭据做在线验收，也未在本次提交中请求 Windows 安装包构建。
