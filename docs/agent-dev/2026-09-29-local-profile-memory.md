# 本机研究画像与对话偏好

个人中心在未登录时也可使用，分为研究档案、已记偏好、数据管理。界面沿用 Fluent 组件与主题 token。旧版全局 Memory 仅迁移到 guest，不归属首次登录的云账号；随应用预置且未被用户改写的示例条目不作为用户事实。

## 数据边界

- 学术档案与结构化偏好按稳定账号身份隔离；guest 独立。
- `liteasy.profile-memory.v1:<scope>` 保存 schemaVersion、revision、条目、待确认候选、删除指纹与检查计数。原话仅保存被采纳/待确认偏好的那一句，不另存完整对话历史。
- 条目包含 field、value、source、updatedAt，以及对话来源的 evidence/sessionId。字段覆盖研究主题、方法、数据集、阅读语言、回答语言、回答方式、研究阶段、项目和手动补充偏好。
- 写入采用 revision 检查。遇到不兼容、损坏或更高版本的数据停止写入并保留原文；不会用空默认值覆盖它。
- 删除或拒绝的条目保留有限指纹，避免后台原样恢复。用户可手动重新添加。
- 清空画像清除条目和待确认项并暂停自动整理。手动修改期间到达的旧模型结果丢弃。

## 自动整理规则

1. 仅个性化和自动整理均开启、用户对话回合成功完成后启动。失败/取消/重复请求不触发；失败的后台检查仍计入预算。
2. 本地规则先筛选用户自己的明确长期偏好声明。寒暄、一般问题、临时要求、代码/引用以及含明显凭据或敏感信息的文本不触发。
3. 首次符合条件可检查；后续至少间隔 10 分钟与 5 个完成回合。同一会话每天最多 3 次，全部会话每天合计最多 6 次。
4. 每次只送最多 4 条、每条最多 400 字的候选声明与有限已有画像给当前配置的模型。不会发送论文正文、附件、工具结果或完整聊天记录。20 秒超时，后台失败不影响主回答，不循环重试。
5. 模型只返回严格结构，最多 4 项。应用复核字段、长度、置信度 >= 0.9、原话必须精确来自本次候选、字段必须有对应声明依据。
6. 自动保存仅接受可在原话直接找到的值。翻译/概括和含糊的冲突进入待确认区；明确“改为/改成”等纠正且能精确定位先前自动条目时可更新。手工维护条目始终受保护。
7. 账号变化、关闭采集、暂停整理、清空或 concurrent revision 变化时取消/丢弃旧结果。最多 48 项有效偏好、12 项待确认候选。

这些规则刻意偏保守，不承诺捕捉所有自然语言表达。对于含糊、否定或复杂描述，用户可在个人中心明确维护。

## 实际消费

- 工作区 Agent 的真实模型请求加入有限画像摘要；用户本轮明确要求优先，画像不能授予工具/写入权限。
- 寒暄仅加载回答语言和回答方式，不加载论文或完整研究画像。
- 没有选中文献时，研究主题/方法可用于直连文献 API 查询。有选中文献时仍先确认其元数据，画像只对已通过主题筛选的候选作有限排序调整，最多提升两个位置。回答风格不作为论文关键词。
- 推荐按获取时间排序时不再按偏好重排。关闭个性化停止注入画像、采集与排序影响，保留本机数据。
- 学术档案导出同时包含结构化偏好与待确认候选。

“本机/离线模式”指不依赖 Liteasy 云账号；完全断网时可手动编辑画像、使用已有记录，自动 AI 整理与新文献获取仍需可访问的模型/文献 API（包括本机模型）。

## 验证入口

- `profileMemory.test.ts`：证据检查、冲突、删除、频率、迁移、版本与账号隔离、推荐消费。
- `useProfileMemory.test.ts`：实际异步生成、并发修改、切账号/关闭/清空、失败预算。
- `agentApplicationService.test.ts`、`workspaceAgent.test.ts`：完成回调去重及真实请求画像注入。
- `personalCenter.browser.spec.ts`：360px 窄栏、明暗主题、未登录编辑、持久化与删除。
