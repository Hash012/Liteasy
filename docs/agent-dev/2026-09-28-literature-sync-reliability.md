# 文献服务、WebDAV 与数据兼容修复

## 现象与修复

### 坚果云同步

旧传输层要求 GET 返回强 ETag，并要求服务器支持条件 PUT。服务器未返回该响应头时，在同步文件前就被拒绝。这是客户端兼容性门槛，不足以判断用户网络有问题。

2026-09-29 更新：按用户要求，清单发布不再要求独占创建 `manifest-write-lock/` 目录，旧版本遗留锁目录也不再阻止上传。直接重新读取清单、比较上次读取的版本，然后写入并读回校验。GET 缺少强 ETag 或只返回弱 ETag 时，使用内容 SHA-256 作为本地比较令牌，不把它伪装成 HTTP ETag。有强 ETag 时仍附带条件更新。内容寻址文件继续校验哈希，原有双向三方比较、冲突选择、删除恢复副本和打开文献延迟应用机制保留。

服务器验证只检查实际读写及验证文件清理，不再探测独占目录创建能力。模拟服务覆盖重复 MKCOL 返回成功、无 ETag、忽略条件 PUT、旧锁目录存在、两个设备增量更新、旧版本发布拒绝和冲突保留。

边界：这是 Liteasy 设备间同步，不导入 Zotero WebDAV 数据。同步范围仍为现有协议允许的 PDF、元信息、批注与论文产物，未扩展为整个数据目录的镜像。不支持条件请求的服务器只做尽力的版本比较和写后校验，不保证多设备同时发布的原子性，不以此阻止使用；后续账户同步另行处理。没有用户凭据，尚未连接用户实际坚果云空间进行验收。

### 关联推荐

之前元信息默认直连 Crossref，而推荐仍请求 Liteasy 云端。两个接口与 AI 模型服务各自独立；AI 聊天成功不能证明云端推荐接口可用。

现在选择 Crossref、OpenAlex 或 Semantic Scholar 时，元信息与推荐共用配置的文献服务和凭据，无需额外开启本地模式或登录 Liteasy。明确选择 Liteasy 云端时保留云端链路，失败提示明确指出云端推荐服务，不再混淆 AI 接入。Crossref 公共查询无需密钥，依据其 [REST API 文档](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)。本地画像依然需要用户单独开启。

### 论文元信息

- 无有效嵌入题名时，从首页文字中去掉常见期刊、卷号、版权和标识横幅，使用有界题名线索检索。Crossref 请求增加题名/作者字段；自动确认仍要求首页证据一致，不把无关候选强行绑定。
- 用户提供的 `das24a` 是 [Larimar 的 PMLR 正式会议论文](https://proceedings.mlr.press/v235/das24a.html)。首页有 `PMLR 235, 2024`，原自动识别路径丢失此来源线索，直连客户端也没有 PMLR 查询。现在保留卷号和年份，按题名查询官方卷级 BibTeX 并核对作者。PMLR 正式版不以题名相似的 Crossref 条目或 arXiv 预印本替代；无法核实则保持未确认。
- PMLR 候选保留来源内 ID、官方 URL、卷号和实际下载字节的 SHA-256，满足现有候选快照契约；支持跨会话重新查询确认。下载限制 20 MiB，原生与浏览器传输均按流限制；只缓存一个卷的精简题录 5 分钟，不保留整卷摘要，也不向 PMLR 发送用户配置的 API 密钥。
- 保留自动识别的完整 query、hints 和候选结果，避免进入确认对话框后丢失检索线索。
- 支持仅输入标题，或 DOI / arXiv 编号；作者和年份可选。
- Crossref / arXiv 候选跨会话确认时重新按稳定标识取回题录，不依赖已清空的内存候选表。
- 确认成功同步更新 Paper 的题名、作者、年份和标识。文献库以当前 Paper 题名显示并检索，不再被旧磁盘文件名遮住。手动确认不强制重命名物理文件；自动获取流程仍按既有机制尝试重命名，失败时保留可访问路径。
- 畸形 API 条目隔离处理，避免空记录、非数组作者等引发类型错误。

## 数据格式复核与保护

| 边界 | 兼容行为 |
| --- | --- |
| 文献库标记 | 当前支持 schemaVersion 1；更高版本返回可恢复错误，不移除旧标记或重写文件 |
| 原生索引 | 保留无版本字段的旧索引读取；拒绝显式未知版本；保留顶层扩展字段，继续使用原子写入 |
| WebDAV 清单与本地 baseline | 先识别 schemaVersion，再反序列化与校验；未知版本、畸形 JSON、路径冲突均返回错误 |
| PDF 批注 | 继续恢复旧版及 v1/v2；未知版本拒绝降级。只有成功解析后才启用自动保存，防止错误恢复后用空数据覆盖磁盘 |
| 文献身份/对象/论文项目 | 维持现有 schema 校验和不可识别数据拒写机制；文献身份的旧版恢复、未知对象类型测试保持通过 |
| 阅读文件与分类元数据 | 编辑时保留同版本附加字段，不随重新序列化丢弃 |
| 论文解析缓存与外部元信息 | 验证数组、条目和字段类型；损坏缓存不进入界面资源模型 |

后续不兼容的格式修改必须提升对应数据版本，不能只提升 APP 版本；旧版本读取器遇到新版本应报可恢复错误并保持原字节。兼容字段扩展必须考虑写回保留，迁移必须覆盖旧样例、重复执行和失败恢复。这里的回归证据不等于对未来任意格式变化作出“永不崩溃”的保证。

## 验证记录

- 相关前端测试四组分别 134、141、38、27 项通过（含跨组重叠）；覆盖真实 PDF 题名提取样例、确认与恢复、默认公共推荐、批注拒绝未来版本写回、文献库题名显示与对象/项目兼容。
- 追加 PMLR 识别、题录审计、畸形/重复记录、大小限制及真实 PDF 回归：24 项通过。真实 `das24a.pdf` 首页 → PMLR 查询 → 确认流程恢复正式题名、12 位作者和 2024 年；实时下载官方完整卷级文件后也确认同一题录可恢复。
- Rust 无默认 feature 全部 120 项通过；追加原生分块响应大小限制后，受影响 `paper_services` 两项测试通过（包含原有一项）。`cargo check --locked --all-targets --no-default-features` 通过。
- `ci:smoke` 8 项通过；`npm run build` 通过，156 个生产资源验证通过。
- 原有锁文件/schema cleanliness 门禁和 `git diff --check` 通过；没有依赖或生成契约漂移。
- 浏览器两条回归通过：默认公共推荐无需登录即可刷新；真实 `das24a.pdf` 右键获取元数据后文献库显示正式题名。后者在浏览器测试中以内存仓库模拟 Tauri 原生元数据持久化边界，PMLR 网络响应使用官方题录样例。

本机检查使用 Linux、Node 22.13.1、Rust 1.98.0；Windows CI 工具链和真实坚果云空间尚未验证。本次提交使用 `[windows-installer]` 请求完整安装包 CI；以上为推送前的本地验证记录，Windows 构建与上传结果以对应 GitHub Actions run 为准。
