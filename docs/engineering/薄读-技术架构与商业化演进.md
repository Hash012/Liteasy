# 薄读技术架构、质量边界与商业化演进

更新：2026-07-30  
状态：桌面端第一版已实现；本文描述当前代码事实与明确的后续接口，不把未上线的社区服务、订阅服务或云端协作写成既有能力。

## 1. 定位与约束

薄读不是“把 PDF 摘成一段文字”的功能。它是以一篇目标论文为中心、可连续下钻的阅读产物：首层保留读者读完论文应留下的核心判断；后续层只围绕用户选中的正文或未覆盖板块展开；每个内容性句子都能回到论文证据或显式的外部来源。

实现优先服从 [新模态-薄读.md](../design/新模态-薄读.md) 与 [薄读-完成标准.md](../design/薄读-完成标准.md)。工程上的核心取舍如下：

- **可信优先于流畅幻觉**：没有可用本地证据、闭包外没有可信外部来源、或结构质量门连续失败时，任务停止并说明原因，不输出本地拼接的“成功结果”。
- **阅读优先于审计面板**：主界面是一段可读的总述或下钻文本；证据通过句级绑定、PDF 跳转和状态提示显现，而不是占据主内容区。
- **用有界工作流控制延迟与成本**：检索规划、工具观察、生成、复核和修复职责分开，但轮数、候选数、全文数和修复次数均有上限。
- **论文内与论文外严格分层**：外部文献可补足语境、挑战、后续工作或知识图谱位置，不能伪装为目标论文的结论。
- **产物边界与文献身份分离**：`artifactId` 代表一次薄读会话及其侧重点；`PaperIdentity` 代表“同一篇文献”，用于跨会话、社区和检索关联。

## 2. 当前能力一览

| 范围 | 当前能力 | 关键边界 |
| --- | --- | --- |
| 入口与呈现 | 模态入口生成 `thin_reading` artifact；同一标签内展示根节点、选择正文下钻、遗漏板块下钻、前后导航和闭包状态。 | 当前首层以当前阅读器中已选且打开的论文优先；否则使用选中文献中的第一篇。 |
| 真实模型 | 复用系统 OpenAI / DeepSeek 配置，使用 `requireLive: true` 的结构化输出请求。 | mock endpoint、无论文、无文本索引会明确停止。 |
| 证据 | 本地 evidence allowlist、页码/片段/quote/置信度、claim、句级映射、PDF 定位。 | 不能以相邻 evidence 或上层证据替代本轮 evidence。 |
| 解释 | 论文类型引导的“读后留存”总述；根据“是什么/为什么/怎么样”组织下钻论述。 | 不按章节平均复述；关键术语在中文中保留原文并括注释义。 |
| 论文外扩展 | OpenAlex / Crossref / arXiv 的受限检索，关系字段、来源白名单、可选开放全文页级证据。 | 不能猜测引用关系；外部检索失败且无已验证来源时停止闭包外生成。 |

| 社区对接 | Intuecho 推荐查询和批注同步的 HTTPS 协议客户端、身份校验、幂等键。 | 社区后端、社交图和真实推荐服务不在本仓库内；未配置时保持本地 `pending_public` 状态。 |

## 3. 端到端链路

```text
用户选择论文 / 总述选区 / 遗漏板块
        |
        v
artifactId + PaperIdentity + ThinReadingGenerationContext
        |
        +--------------------------+
        |                          |
        v                          v
本地 evidence 准备、意图规划          条件触发的外部检索 Promise
        |                          |  (多意图并发，结果可复用)
        v                          |
目录级证据计划 -> 确定性工具执行 -> 观察 -> 可选第 2 轮
        |                          |
        +------------ 汇合 --------+
                     |
                     v
严格 JSON 生成 -> 确定性结构/来源/数字门 -> 命题级证据复核
                     |
             最多一次定向修复
                     |
                     v
ThinReadingNodeSeed + GenerationAudit -> ThinReadingDocument -> artifact 持久化 / UI
```

### 3.1 上下文与论文内闭包

`ThinReadingGenerationContext` 是一次生成的完整边界，至少包含 `artifactId`、目标论文、当前深度、来源类型、目标语言、父节点摘要、父级 claims/evidence spans 和祖先摘要。下钻来源只有三类：

1. `root_overview`：根级总述。
2. `omitted_section`：由当前正文与祖先正文的语义差集导出的未覆盖板块。
3. `selected_text`：用户从当前生成文本选择的片段，可附加问题与已知 evidence/source ID。

解释规划器将选区和本地证据归为 `what`、`why`、`how` 或 `mixed`，生成相应的论述顺序，并判定论文内部证据是否足够。默认的内部深度阈值是 3；超过阈值、用户明确要求外部关系、父节点已在闭包外，或缺少回答该意图的证据时，会请求外部知识。节点同时保留 `withinPaperClosure` 和 `inside_paper` / `near_boundary` / `outside_paper` 状态，前端据此给出明显视觉区分。

这个设计避免了两种常见问题：局部下钻失去上文而成为新摘要，以及模型因为“想讲完整”而把未检索的常识填进论文结论。

### 3.2 有界证据工作流

薄读采用“目录规划 -> 证据观察 -> 条件补充”的动态工作流，而不是将整份 PDF 或全部 evidence 直接交给最终生成模型：

- planner 先读取轻量 evidence 目录，返回当前问题所需的 `selectedEvidenceIds`、页请求、检索词和 focus；ID 必须逐字来自本轮 allowlist。
- `read`、`search`、`view` 是确定性本地工具，只能返回当前 `PreparedMultiPaperAnalysis` 中的 evidence。每轮最多直接选 12 条，关键词检索最多 3 条请求、每次至多取 6 条，页检索最多 3 页。
- observation Agent 只在发现具体证据缺口时允许第二轮；两轮最终最多合并 18 条 evidence。没有新证据或已足够时显式停止。
- 每轮选中的 ID、工具调用、观察到的 ID、停止原因都写入 `ThinReadingGenerationAudit.evidenceLoop`，供复现和成本归因。

这是目前最关键的性能/质量平衡点：小模型或强模型都只面对和当前阅读问题有关的受控证据集合；同时，系统仍保留“为什么没有继续检索”的审计答案。

### 3.3 并发与延迟控制

当解释规划判断需要外部知识时，外部检索 Promise 会在本地 evidence 规划开始前启动；本地 planner、工具执行和 observation 先行，只有构造最终 prompt 前才等待外部结果。多条外部查询使用 `Promise.allSettled` 并发执行，单条失败不阻塞其他已验证来源。开放全文补证也对最多 4 个来源并发执行。

同时，系统避免“为了更安全再重复一遍所有检查”：薄读已经通过句级 allowlist 与命题复核后，通用远端答案审计不再重复调用，只保留其本地确定性元数据。失败修复限制为一次；第二次结构失败直接停止。这样减少的是重复等待，而不是减少证据、白名单或来源校验。

进度事件覆盖本地证据、外部检索、生成、结构化、保存等阶段，UI 不会在长请求中处于无状态空白。

## 4. 可信生成与质量门

### 4.1 模型输出契约

模型仅能返回严格 JSON，核心字段为：

- `summary`：单段、长度受语言约束的正文。
- `summarySentences`：顺序逐字覆盖 `summary` 的句子，每句带 `evidenceIds`、`externalKnowledge` 和 `grounded` / `weak` / `unsupported` 状态。
- `paperEvidence`：本轮真正用于正文的论文 evidence ID。
- `claims`：关键判断及其论文内证据 ID。
- `omittedSections`：由未覆盖差集导出的稳定 `sectionKey` 与按钮标签。
- `withinPaperClosure`、`paperType`、`externalKnowledge`：边界和呈现策略所需状态。

解析阶段通过 Zod schema 和确定性校验，拒绝自由文本 ID、越界 ID、没有来源的正文句、`grounded` 却无论文证据的句子、外部关系用词越界、正文句映射未完整覆盖等输出。模型无法通过“格式正确但指向另一条证据”绕过 allowlist。

### 4.2 学术严谨性

质量链是分层的，不依赖单一“模型自评”：

1. **提示约束**：证据、父层文本、选区和外部摘要均按不可执行参考数据处理；要求保留限定词、适用范围和作者主张强度，不把局部结果泛化为普遍因果。
2. **来源和关系门**：论文内事实只能使用论文 evidence；外部来源必须使用本轮 canonical source ID。`cited_by_target`、`cites_target`、`related` 与 `topic_search` 是结构化关系，只有上游图字段支持的关系才能被表述为引用关系。
3. **句级可追溯性**：`summarySentences` 必须完整覆盖展示正文；每个句子都可定位其 evidence/source，PDF 证据 span 保存页码、chunk、quote、抽取方式与置信度。
4. **数值保真**：根级总述可以压缩次要数字；下钻中，若正文句解释、比较或概括含量化数据的原文断言，必须保留至少一个对应原文数字及单位、百分比、区间、误差或统计限定。质量门按 evidence 内的最小子句和量化语义判断，避免因同一长证据的无关 `4096`、页码或结构编号误拦截。
5. **命题复核**：在证据规划或使用外部知识后，独立 review Agent 对句子提出的命题给出 `supported`、`partial`、`contradicted` 或 `insufficient` 判断。纯外部且无直接支持的句子可被确定性删除后重新复核；其余失败进入一次定向修复。
6. **失败显式化**：两次结构质量门都未通过时抛出可诊断错误，不生成伪造产物。

`GenerationAudit` 将模型/provider、planner、工具、复核结论、修复原因和版本写入节点。它不只是调试日志，而是日后回答“这句话为什么能展示、花了哪些资源、何时用了外部知识”的数据基础。

## 5. 数据模型与持久化边界

### 5.1 四个稳定标识

| 标识 | 用途 | 不应替代的对象 |
| --- | --- | --- |
| `artifactId` | 一次薄读会话、节点树、批注、审计与持久化边界。 | 不能当作论文身份。 |
| `PaperIdentity` | `doi -> arxivId -> semanticScholarId -> title+authors+year hash -> local paper id` 的文献身份链。 | 不能覆盖 artifact 的不同阅读侧重点。 |
| `nodeId` | 根节点/下钻节点、导航、批注目标和 recommendation scope。 | 不能跨 artifact 复用。 |
| evidence/source ID | 当前一轮论文证据或外部来源的引用边界。 | 不能靠短 ID、标题或模型猜测替代。 |

`ThinReadingDocument` 是版本化的不可变投影（当前 `liteasy.thin-reading/v1`）：以根节点、节点记录、active node、目标语言、文献身份映射、批注和待公开队列组成。根据相同 parent/source 的稳定哈希生成 child ID，因此重复点击相同下钻入口会恢复既有子节点，而不是产生无意义的重复分支。

artifact 本地仓库会校验薄读文档和 agent audit 版本。分支任务中断时只保存包含 artifact、文档版本、主论文、父节点和有限选区的 recovery snapshot；重新提交前重新验证父节点、证据/source ID、选区文本和文档版本。验证通过后创建新模型请求，失败则保留失败态。

### 5.2 批注与 Intuecho 协议

任何节点总述、claim、论文 evidence、外部知识和推荐项都可作为批注目标。批注默认私有；公开操作或自动公开设置会进入本地 `pending_public` 队列，绝不伪装为已经同步。

桌面端已定义两个 HTTPS 协议边界：

- `POST /v1/thin-reading/annotations:sync`：发送带 paper identity、scope、节点和批注内容的待同步项。请求使用由队列键和更新时间生成的 `idempotency-key`；响应必须逐项回显可验证的 queue key / annotation ID。
- `POST /v1/thin-reading/recommendations:query`：按 whole paper、section 或 selected passage scope 查询社区理解线索。返回的推荐必须携带与当前 stable paper identity 完全一致的身份。

只有 DOI、arXiv、Semantic Scholar 或题名作者年份等非本地 fallback 身份可以同步或查询社区；仅 `local_paper_id` 的条目被明确拒绝。这使未来社区服务能安全地按文献、段落和用户画像索引，而不污染本地匿名数据。

## 6. 外部知识与全文证据

外部检索是闭包外生成的前置条件，而不是“模型可以自由联网”的许可。客户端接受 OpenAlex、Crossref、arXiv 三类来源，校验 provider、canonical ID、HTTPS URL、关系类型、作者、摘要、撤稿标记和检索查询；撤稿来源或过短摘要不进入可信集合。

外部来源保存 `provider`、`relation`、`retrievalQuery`、`authors`、`year`、`doi/arxivId`、record URL 与 relevance。来源优先级为可核验关系优先、正式出版优先、相关度次之；同一 ID 合并而不重复投喂模型。外部查询结果按 `artifactId + query + target identity` 持久化，可标记复用，避免把缓存结果伪装成新检索。

对高价值且有开放 PDF 的来源，桌面端可请求全文：服务端返回 base64、最终 URL 与 SHA-256；客户端复算内容哈希后才解析内嵌 PDF 文本，不使用 OCR。随后按标题和检索词做 BM25，单来源最多保留 5 个页级 chunk。这一补证的意义是让“外部文献说了什么”尽可能从摘要级来源升级为页级可核验来源，但不会把开放全文抓取扩展成无限爬取。

## 7. 可测试性、可观测性与运维

测试不只验证 JSON 是否能解析，还覆盖：论文类型和提示、证据 allowlist、句级覆盖、外部关系、闭包状态、结构编号排除、数值保真、全文哈希、Intuecho 队列/幂等、分支恢复、真实 PDF gold span 和浏览器截图。`thinReadingEvaluation.ts` 还提供可重复的 gold-case 评估，指标包括：

- 总述核心概念、下钻相关性与论文类型准确性；
- citation precision/recall、evidence grounding、句级边界覆盖；
- 闭包边界、外部来源可追溯性与关系保真；
- 遗漏板块召回、语言一致性、术语保留和 unsupported 比例。

生产观测应以 `GenerationAudit`、artifact task 阶段和 provider 调用记录为主，至少聚合：完成率、停止原因、各阶段耗时、修复率、planner 第二轮比例、外部检索复用率、来源数量、每节点 token/模型成本和上述评估分数。日志不得保存 API key、完整提示或未经处理的网页正文。

## 8. 面向收费分级的技术演进

当前仓库没有订阅、支付、配额或权限判定；以下是基于现有可审计接口的推荐演进，不应在客户端通过隐藏按钮实现。

### 8.1 计费单元应是“验收后的能力”，不是按钮点击

建议在服务端将一次薄读 run 拆为可计量的 entitlement units：

| 单元 | 已有计量依据 | 推荐计费时点 |
| --- | --- | --- |
| 根级薄读 | artifactId、完成状态、quality gate、模型/provider。 | `ThinReadingDocument` 成功持久化且质量门通过。 |
| 下钻节点 | nodeId、source、depth、generation audit。 | 子节点成功写入，而非用户点击时。 |
| 外部扩展 | retrieval state、canonical source、复用标记、全文 evidence basis。 | 可信来源实际返回；缓存复用可设更低或零增量成本。 |
| 全文核验 | 内容哈希、来源数、页级 external evidence。 | 哈希和 PDF 解析验证成功后。 |
| 社区同步/推荐 | stable paper identity、queue key、同步结果。 | 服务端成功接受或返回推荐后。 |
| 团队资产 | artifactId、审计版本、共享范围、导出记录。 | 后续云端持久化和权限审计完成后。 |

取消、无本地索引、来源不可信、质量门失败、恢复校验失败的 run 不应消耗“成功生成”额度；可单独记录基础设施成本，不能向用户暗中计为成功产品用量。

### 8.2 推荐的能力层级

产品层级应由服务端 entitlement 下发并在网关强制执行，UI 仅展示可用性。具体价格和额度由产品配置决定，以下是能力边界而非既定套餐：

| 层级 | 合理能力范围 | 必须保持的可信底线 |
| --- | --- | --- |
| 基础阅读 | 根级薄读、有限下钻、本地证据跳转、私有批注、用户自带模型密钥。 | 仍走真实模型、句级证据和失败停止；不能降为模板摘要。 |
| 深度研究 | 更高的节点/深度额度、外部来源检索、开放全文核验、更多模型选择和优先队列。 | 外部关系、来源白名单、撤稿过滤和质量门全部保留。 |
| 团队/机构 | 云端 artifact、团队共享、审计导出、集中 provider 路由、Intuecho/机构知识库连接器。 | 身份、组织权限、保留期、数据隔离和完整审计必须在服务端实施。 |

不建议把“减少证据门、允许无来源生成、隐藏闭包外状态”作为低价层策略。它会直接伤害产品最可收费的特征：可信、可复核的深度阅读。

### 8.3 建议的服务端契约

将以下逻辑从桌面端抽为可版本化的服务端接口：

```ts
type ThinReadingEntitlement = {
  accountId: string;
  plan: "basic" | "research" | "team";
  limits: {
    branchNodesPerPeriod: number;
    externalFullTextSourcesPerRun: number;
    externalRetrievalsPerPeriod: number;
    rootRunsPerPeriod: number;
  };
  capabilities: {
    auditExport: boolean;
    communitySync: boolean;
    externalKnowledge: boolean;
    organizationStorage: boolean;
  };
  modelPolicy: {
    allowedProviders: string[];
    maximumGenerationBudget: number;
    priority: "standard" | "high";
  };
};

type ThinReadingUsageEvent = {
  artifactId: string;
  eventId: string;
  kind: "root_completed" | "branch_completed" | "external_source_verified" | "full_text_verified";
  nodeId?: string;
  sourceId?: string;
  auditVersion: string;
  idempotencyKey: string;
  occurredAt: string;
};
```

网关应在开始前检查 capability/预算，在成功持久化后以幂等 `UsageEvent` 结算，并向客户端返回剩余额度。若用户自带 API key，应将模型调用成本与产品能力额度分开记账；若由平台提供模型，才将 provider token/请求成本纳入该账户的预算策略。

## 9. 后续开发优先级

1. **先建立服务器端 entitlement 与 usage ledger**：复用 `artifactId`、`nodeId`、audit version 和现有同步幂等思想；不要让前端成为权限事实来源。
2. **把运行策略配置化**：内部深度、证据轮数、外部候选数、全文来源数、模型预算应由版本化 policy 控制，并在 audit 记录 policy version。当前常量是可靠默认值，不应永久写死为产品套餐。
3. **强化真实评估集与延迟基准**：按论文类型、语言、PDF 质量、provider、是否闭包外记录通过率、P50/P95、修复率、数值保真与人工偏好；据此再调 prompt、并发和分级额度。
4. **接入社区和组织后端**：实现用户身份、授权 scope、内容审核、数据删除、组织隔离和推荐反馈闭环；继续要求 stable paper identity，禁止只按标题匹配。
5. **扩展外部来源前先扩展验证器**：Semantic Scholar、OpenReview、机构仓储或内部知识库均应先定义 canonical ID、关系语义、撤稿/版本策略和证据契约，再进入模型 prompt。
