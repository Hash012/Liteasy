LiteasyClaw 三人分工可视化

目标是让三个人分别拥有清晰的主责闭环，同时把可能互相影响的文件明确标出来。主责文件可以直接推进；可能涉及文件要看影响范围；共享高风险文件改动前先同步。

主责文件 该负责人优先设计、实现、测试和评审。
可能涉及 改动常见但要注意跨模块影响。
测试文件 对应模块的 focused tests，优先补这里。
共享高风险 改前先沟通，避免多人同时抢一个入口。

左侧是负责人和共享区，右侧是被多人涉及或属于共享高风险的文件。线条表示这个人会碰到这个文件；虚线表示共享高风险。搜索框会同步过滤连线。

协作规则

  • 任何人需要改 `AppShell.tsx`，先确认是否能通过 controller 接入。
  • 新增跨模块逻辑先建或扩展 controller，不直接从一个 feature 调另一个 feature 的内部 hook。
  • 每个人的 PR 尽量围绕自己的主责模块，测试文件跟着模块走。
  • 如果一个需求同时碰到两个人的主责文件，先定义接口契约，再分别实现。
  • `docs/engineering/module-boundaries.md` 是最终边界规则；本分工图是执行层建议。
