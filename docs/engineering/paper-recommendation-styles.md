# 论文推荐风格

桌面入口为「设置 → 论文推荐」和「文献库 → 关联推荐」。风格保存在本机，刷新推荐时保留已有卡片。推荐以选中文献为起点；用户开启个性化且填写研究主题或方法后，也可直接从研究兴趣获取推荐。关闭个性化时不向推荐请求传递研究画像。

| 风格 | 目的 | 排序依据 |
| --- | --- | --- |
| `balanced` 均衡 | 兼顾进展和基础 | 主题相关性、近期发表、引用依据和结果多样性 |
| `frontier` 追踪前沿 | 发现近期相关工作 | 实际发表时间，优先检索近两年的相关候选 |
| `classic` 经典基础 | 补充领域基础 | 相关性、发表年限、压缩后的引用计数；额外检索至少五年前的候选 |
| `exploratory` 跨域探索 | 扩展相邻主题与方法 | 保留主题相关性，增加相似标题的重复惩罚 |

## 数据和服务边界

正式 API 的推荐提供器使用 Crossref 实际返回的 DOI、标题、作者、发表日期和引用计数。`published-print`、`published-online`、`issued` 用于确定发表日期；只有年份时只提供年份，不补造月日。检索时间不代表发表时间。缺失元数据保留未知，未来日期不获得近期发表加成，引用计数不等于论文质量，也不是完整或学科归一化的引用统计。

正式检索合并相关、近期和经典候选。单次请求最多五组不同查询、同时两组查询；每组最多三个来源请求，每个最多十二条，最终最多八条推荐。某一检索分支失败时可以使用成功分支；全部失败则返回错误。超时覆盖 HTTP 请求及响应体读取。

候选先通过主题相关性过滤，再应用受相关性约束的风格权重与多样性排序；排除已选论文、重复 DOI、重复规范化标题和用户已屏蔽候选。标题相近但有新增内容的论文不会仅因相似度过高被判为同一篇。

`development/dev-cloud` 保留其 OpenAlex/Crossref/arXiv 检索、身份解析、质量门禁、排序融合与可选外部重排流程，在其上接入同名风格。它是独立开发实现，不代表正式 API 具有同样的数据源或生产能力。

## 请求、响应及兼容性

`POST /v1/recommendations` 增加可选 `style` 字段，缺省为 `balanced`；非法值返回 400。桌面发送至多三篇种子文献以符合正式接口限制，完整选中集仍用于本地排除与缓存作用域。

响应保留原有字段，并可提供 `citationCount`、`publishedAt`、`rankingStyle`、`styleScore`。`styleScore` 只是风格证据，`scoreComponents.finalScore` 才是实际综合排序分数；不能用风格分替代综合分或再叠加一次风格权重。桌面在返回风格匹配时遵循综合分，连接旧服务时按已有元数据本地排序。用户明确选择按检索时间排序时，该排序方式优先。

缓存键包括算法版本、风格、完整选中集和结构化画像，并保留原有账号、工作区、个性化版本和排序作用域；未修改缓存数据库结构。切换风格取消旧生成请求并拒绝迟到结果。清除操作等待本作用域已发出的写回完成，再清理缓存。成功反馈按账号和论文身份隐藏候选，避免切换风格或刷新后立即恢复；反馈失败显示错误并保留卡片。

## 验证与发布

前端回归覆盖风格排序、弱相关高引用、发表时间、重复排除、服务分数契约、请求取消、缓存隔离、反馈竞态和设置持久化；浏览器测试验证设置操作与刷新后的保留。服务测试使用受控的真实结构来源响应验证请求参数、日期解析、超时、部分失败、排序和隐私门禁，不依赖实时网络波动。

发布时需同时更新正式 API 和桌面应用，新增候选检索能力才会完整生效。旧服务兼容排序只能调整它已有的候选。自动化测试验证行为与契约，不等同于已通过真实研究者相关性评价，也不代表服务器已部署。
